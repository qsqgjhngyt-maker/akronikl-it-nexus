# Nexus Sync Worker · v0.1.7-alpha.2.1 foundation

This folder is the Cloudflare backend foundation for Nexus Sync & Team.

It is intentionally **safe-by-default**: `AUTH_MODE` is `disabled`, so protected project routes return `AUTH_NOT_CONFIGURED` until a verified production identity adapter is connected. A development-only `AUTH_MODE=dev` exists for local Worker smoke tests and is rejected when `ENVIRONMENT=production`.

## Storage split

- D1: workspaces, memberships, project metadata, roles/scoped ACL, revision index, invites and audit events.
- R2: immutable project revision snapshots. R2 object keys are generated by the Worker, never accepted from the browser.
- Durable Objects / Queues: not required for this first foundation; reserved for real-time project coordination and background build/sync jobs.

## Security invariants

1. Project reads/writes require an authenticated subject.
2. Authorization is evaluated server-side from project membership + role + path scope.
3. Explicit `deny` policies override `allow`.
4. D1 queries use prepared statements with bound values.
5. R2 keys are server-derived from `workspaceId/projectId/revision`.
6. Revision mismatches return HTTP 409 instead of silently overwriting a newer cloud version.
7. Audit events are appended server-side after accepted state-changing operations.

## First deployment sequence (later step)

1. Create a D1 database and an R2 bucket in Cloudflare.
2. Copy `wrangler.jsonc.example` to `wrangler.jsonc` and fill the resource IDs / GitHub Pages origin.
3. Apply `migrations/0001_sync_team_foundation.sql`.
4. Keep `AUTH_MODE=disabled` until Nexus Account authentication is connected.
5. Deploy the Worker and verify only `/api/v1/health` first.

Do not enable the development auth mode on a public production Worker.
