# Nexus: авторизованный чат в feature-ветке

Интеграция подключена к существующей цепочке Nexus:
HttpOnly session → Gateway cookie ingress → BFF Account read → подписанный запрос
Worker → действующая сессия/устройство/метод входа/аккаунт в базе.
`server-access/bff/akronikl-cloud.mjs` использует существующий `createAccountReadHandler`.
ID из браузера является только ожиданием для обнаружения смены пользователя.
Он не создаёт аккаунт и не даёт доступ к данным указанного человека.
После проверки сохраняется именно владелец из серверной сессии.

`ui/bridge.js` лениво подключает account-bound broker после подтверждённого входа
на серверном origin Nexus. Публичный/offline host не получает эту capability.
После logout исходный passkey handler отзывает сессию, а cloud middleware прерывает
связанные HTTP-запросы и освобождает соединения. Смена identity закрывает старый UI.
Версия соединения защищает новое подключение от запоздалого отключения старой вкладки.

## Личные данные

Ключи, настройки Akronikl и дерево разговора хранятся зашифрованными на сервере
отдельно для каждого проверенного аккаунта. Личный локальный preview с DPAPI
не мигрируется автоматически в Nexus: это могло бы приписать ключ чужому аккаунту.
Серверный вариант использует AES-256-GCM, случайный nonce, проверку тега и
административный 32-байтовый master key. Открытого fallback нет.
В API-ответах и browser storage нет API-ключа. Серверные cookies Secure/HttpOnly/SameSite.
Сохранение настроек/чата проверяет revision; конфликт другой вкладки не затирается.

Общие настройки Nexus из `core/storage.js` после подтверждённого входа теперь
пишутся через account-storage. При отсутствии личных настроек нового аккаунта
не берутся значения предыдущего пользователя. Публичные настройки экрана входа
остаются отдельными. После блокировки account-storage поздний prefs autosave запрещён.
Старые данные не удаляются и не присваиваются произвольному новому аккаунту.

## Ветки, сообщения и вложения

Можно начать новый разговор, ответить в новой ветке от выбранного сообщения
и переключаться между ветками. Модель получает только путь выбранной ветки.
«Удалить с продолжением» удаляет сообщение и зависящие от него ответы/вложения
во всех ветках, где они использовались; они не остаются скрытым контекстом модели.
Смена ветки отменяет прежний запрос и очищает ещё не отправленные вложения.
История и ветки восстанавливаются после перезагрузки в том же аккаунте.

Общий чат доступен подключённой облачной модели. Команды платформы сохраняют
прежнее явное подтверждение и не становятся полномочиями модели.
Изображения можно выбрать, перетащить или вставить из буфера обмена.
PNG/JPEG/WebP обрабатываются в браузере в JPEG с длинной стороной до1536px,
без публикации на внешнем файловом хостинге. Вопрос и выбранные вложения уходят
выбранному провайдеру только после отправки. Текст/код читается как UTF-8.
HTML/код показывается и передаётся как данные, не исполняется.
PDF, DOCX, XLSX и PPTX теперь читаются на устройстве до отправки. DOCX/PPTX дают
извлечённый текст; XLSX — адреса ячеек, текст и кешированные значения, без пересчёта
формул и применения числового/датового форматирования. Внешние ссылки и вложенные
объекты не открываются. Удалённые правками фрагменты DOCX не включаются.
PDF до3страниц у визуальной модели включает текст и изображения всех страниц,
поэтому поддерживаются и сканы. Более длинный PDF до30страниц передаёт только
извлечённый текст: рисунки и страницы без текстового слоя явно отмечены как
непроанализированные. Полностью сканированный PDF длиннее3страниц отклоняется.
Зашифрованные PDF, макросы, старые DOC/XLS/PPT, архивы, исполняемые файлы и аудио/видео отклоняются.
Office ZIP распаковывается в отдельном завершаемом worker: проверяются размеры,
число частей, пути, CRC, макросы и XML entities. Распаковка ограничена16МБ,
одна XML-часть2МБ, до512частей; строки документа до64тыс. символов,
XLSX до5000ячеек/30листов, PPTX до60слайдов. Чтение отменяется при смене ветки
или закрытии окна; до готовности вложений отправка сообщения заблокирована.
PDF.js6.4.299 и fflate0.8.3 закреплены локально с лицензиями и SHA-манифестом;
для чтения не используется внешний сервис или CDN. В стартовый граф они не входят.
Проверка формата повторяется на сервере. Неизвестная модель не получает изображения
по предположению: подключены проверенные форматы Qwen/OpenAI/Claude/Gemini.
Для Kimi/DeepSeek/GigaChat/OpenRouter в этом варианте поддержан текст.

Ограничения: до4 подготовленных вложений (короткий PDF включает текст и страницы),
исходное изображение/документ до6МБ, текстовый файл до128КБ
и64тыс. символов, подготовленные вложения суммарно до2,5МБ; дерево до128сообщений,
12веток и3МБ. Модель видит последние24сообщения выбранной ветки, текст до128тыс.
символов. При превышении нет молчаливого обрезания вложений или имитации анализа.
Очистка записи не является гарантией физического стирания диска или удаления
уже отправленных данных из инфраструктуры провайдера. HTTP отменяется; остановка
удалённых вычислений и биллинга не доказана.

## Конфигурация feature BFF

`AKRONIKL_CLOUD_ENABLED=true`, `AKRONIKL_VAULT_MASTER_KEY` (Base64 32 случайных байт),
`AKRONIKL_VAULT_FILE` (закрытый постоянный серверный том). Это серверная конфигурация,
а не API-ключ модели и не поле пользователя. Master key выдаётся серверу через
секреты окружения/менеджер секретов, не включается в Git, логи или образы.
Нужны существующие Account flags/service secret/private Gateway settings.
Один процесс BFF владеет файлом; многорепличное хранилище этим кандидатом не реализовано.
При выключенном flag облачные маршруты не активируются.
Для будущего развёртывания Gateway должен передавать `/api/akronikl/cloud/*` в тот же
private BFF с существующим accountReadContract и защищённым Cookie ingress.
Gateway, IAM, production secrets, реальные аккаунты и базы в этой работе не менялись.
Сборка в официальный image/Release и деплой не выполняются.

## Воспроизводимая проверка

`check-nexus-chat.mjs`: реальная регистрация и вход A → logout → B → logout → A
через существующие WebAuthn/BFF/Worker с настоящей проверкой подписей.
Тестовые данные, виртуальные CTAP2 ключи, SQLite вместо D1 и локальный TLS/Gateway
изолированы от production. Личность не подменяется callback-таблицей или готовым DTO.
В синтетическом AI-прогоне у A/B разные тестовые provider keys; это контракт
upstream, не ответы живой модели. В live-прогоне Qwen используется один ранее
разрешённый ключ владельца только в A. B его не получает; второго живого ключа нет.
Qwen читает контрольное значение из файла и код, нарисованный на изображении;
ожидаемые значения не подставляются в ответ. Все FAIL сохраняются по source.
Мастер-ключ, виртуальные private keys, сессии и provider key не входят в evidence.

Официальные форматы изображений:
[Qwen](https://help.aliyun.com/en/model-studio/vision-model/),
[OpenAI](https://developers.openai.com/api/docs/guides/images-vision),
[Claude](https://platform.claude.com/docs/en/build-with-claude/vision),
[Gemini](https://ai.google.dev/gemini-api/docs/image-understanding).

## Продолжение проверки P4-Q

`check-nexus-quality.mjs` выполняет прежние32случая через настоящий settings broker
и проверенный Nexus Account. Ключ вводит только QA-автоматизация через поле UI.
Сырые ответы и предыдущие FAIL не перезаписываются. Tutor получает исходное объяснение и относящиеся к нему условия из того же урока: до3выдержек в облаке и до2 на CPU. Облако делает один явный дополнительный проход редакции черновика, оба raw результата сохраняются. CPU:35–65слов, до256output tokens, прежние n_ctx4096/n_threads1/без thinking. Это не гарантия правильности:
даже после уточнения инструкций встречаются фактические ошибки и раскрытие решения.
Их нужно учитывать в CONTENT_REVIEW; полная приёмка требует проверки всех критериев,
а получение JSON или увеличенная длина ответа не считаются качеством.

Документация парсеров: [PDF.js](https://mozilla.github.io/pdf.js/examples/),
[релиз6.4.299](https://github.com/mozilla/pdf.js/releases/tag/v6.4.299),
[fflate](https://github.com/101arrowz/fflate),
[OpenXML](https://learn.microsoft.com/en-us/office/open-xml/about-the-open-xml-sdk).

## Озвучка

В этой feature доступны кнопка озвучивания у ответа и автоозвучка новых ответов. В настройках Голос: выбор установленного локального голоса, скорость, пример, пауза/продолжение и остановка. Автоозвучка по умолчанию выключена, сохранение персональное в Nexus. После восстановления истории речь сама не запускается; нужно действие пользователя. Смена ветки/языка, удаление, выход, закрытие и скрытие окна останавливают чтение. Используются только голоса с localService=true, без API-ключа и микрофона. Если нужного голоса нет, показана причина, успешная озвучка не имитируется.

NEXUS_SPEECH_QA — явно синтетический speech engine для UI/account-contract; это не доказательство слышимого звука. Отдельный native probe фиксирует реальные getVoices/onstart/onend без подмены. Проверка слухом человеком указывается отдельно. Остальные облачные провайдеры и голосовой ввод отложены пользователем; production/Release не изменяются.

Для Qwen3.7/3.8 в feature включено документированное обдумывание с бюджетом1024 и общим max_tokens3072. Внутренние reasoning_content не сохраняются и не выводятся, usage/флаг редактирования сохраняются. API-reported model фиксируется отдельно от выбранного. Это настройка модели, а не обещание правильности. Официальный контракт: https://help.aliyun.com/en/model-studio/qwen-structured-output и https://help.aliyun.com/en/model-studio/deep-thinking .

## Выбранный пользователем режим текущей версии

Обучение — через выбранного облачного провайдера (Qwen по умолчанию); локально — навигация, поиск и точные выдержки без генерации. Экспериментальные0.6B CPU/WebGPU убраны из пользовательского меню; библиотека/runtime и прежние raw/FAIL сохранены для QA, новые модели не скачиваются. Голосовой ввод и live-проверки остальных провайдеров отложены.

Выбор облачного провайдера/модели сохраняется отдельно для аккаунта; ключи не входят в preferences. Смена сервиса явная, автоматического fallback к другому провайдеру нет. OpenAI/Claude/DeepSeek/Kimi/GigaChat/Gemini/OpenRouter доступны как варианты настройки, LIVE NOT_RUN.

При открытии справки с интернетом публичный индекс проверяется по SHA и сохраняется в отдельном CacheStorage; при отсутствии сети cached bytes проходят те же pins. В CacheStorage нет вопросов, файлов, истории или ключей. Отмена не возвращает просроченный результат. Наличие места/разрешения кеширования зависит от браузера; холодный вход и offline shell подчиняются существующим правилам Nexus, авторизация не обходится. Файлы для облачного анализа офлайн не отправляются.
