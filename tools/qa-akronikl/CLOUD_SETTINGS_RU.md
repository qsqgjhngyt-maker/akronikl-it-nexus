# Облачные подключения в изолированной feature-ветке

Локальный Windows host: `node tools/qa-akronikl/serve-cloud-settings.mjs`.
Откройте напечатанный localhost URL → Akronikl → настройки → Модель → Облачные ИИ.
Выберите провайдера и модель, вставьте ключ и нажмите «Подключить».
ID модели редактируется: доступ определяется реальным проверочным запросом,
а не наличием названия в списке. Проверка может расходовать небольшое число токенов.
Для Qwen предустановлены Singapore и согласованная рабочая область P4-Q.
Регион/рабочая область меняются в «Параметрах провайдера».

«Запомнить подключение на этом компьютере» включено по умолчанию.
Ключ очищается из поля после отправки, но сохраняется зашифрованным через
Windows DPAPI CurrentUser в `%LOCALAPPDATA%\Akronikl\cloud-connections.dpapi`.
Приложение не требует текстового файла секрета и не читает переменные с ключами.
При следующем открытии на этом компьютере в том же профиле браузера выберите
сохранённого провайдера и нажмите «Подключить»: вводить ключ заново не нужно.
Соединение проверяется заново; автоматических запросов к ИИ при открытии нет.
Для замены сохранённого ключа вставьте новый и оставьте запоминание включённым.
Кнопка «Удалить сохранённый ключ» удаляет запись и отзывает связанные активные
соединения. Обычное отключение сохраняет запись. При отключённом запоминании
новый ключ используется только текущим соединением; старую запись удаляют отдельно.

Привязка к браузеру — долгоживущий случайный HttpOnly/SameSite cookie;
в зашифрованном хранилище сохраняется только его хеш. Другой профиль браузера
не получает список или ключи первого. После очистки cookies потребуется повторный ввод.
Это локальная интеграция Windows, а не промышленная авторизация Nexus Account.
DPAPI защищает файл на диске, но не от программ, уже работающих под тем же Windows
пользователем. Удаление записи не является доказательством физического стирания с диска.
Нет открытого запасного хранилища при ошибке DPAPI. Без запоминания подключение
работает и при недоступном хранилище. Серверные сессии истекают после 30 минут
простоя; сохранённый ключ остаётся доступен для повторного подключения.

Поддержаны Qwen, OpenAI API, Claude, Kimi, DeepSeek, GigaChat, Gemini, OpenRouter.
У каждого свой ключ и доступ к модели. GigaChat принимает Authorization Key
из кабинета и получает/обновляет краткоживущий OAuth access_token на сервере;
TLS не отключается. Ключи и OAuth токены не возвращаются браузеру, не попадают
в снимки состояния, URL, localStorage, протоколы ответов или Git.
Модель, провайдер и несекретные параметры сохраняются вместе с ключом.
Произвольные URL и заголовки от браузера запрещены. Промежуточные рассуждения
провайдера отбрасываются; ответ JSON и допустимые уникальные цитаты проверяются
после генерации, без исправления или подмены текста ожидаемым ответом.

Остановка прерывает HTTP на клиенте/локальном сервере. Остановка вычислений
у внешнего провайдера не доказана. Версия соединения не позволяет запоздалому
отключению или запросу старой вкладки затронуть новое подключение.

Host предоставляется только через явную capability `cloudBroker`. Основной
продукт не включает облачную отправку автоматически. Main, production, merge
и официальный Release этим изменением не затрагиваются.

## Проверки

`tests/akronikl-cloud-settings.test.mjs` проверяет реальные адаптеры протокола
с явно синтетическим upstream: это не успешные обращения к восьми живым ИИ.
`check-cloud-settings.mjs` разделяет `synthetic-ui-only` и live Qwen. Только
QA-автоматизация читает ранее предоставленный пользователем секрет и вводит
его в поле, чтобы не просить повторно; приложение/сервер такого механизма не имеют.
QA хранит отдельный DPAPI файл вне evidence. В evidence нет ключей и cookies.
Живые проверки остальных провайдеров требуют соответствующих ключей и отмечаются
NOT_RUN до получения настоящего результата. Синтетический PASS не засчитывается
как качество ответа ИИ. Исходные FAIL сохраняются отдельными неизменёнными файлами.
