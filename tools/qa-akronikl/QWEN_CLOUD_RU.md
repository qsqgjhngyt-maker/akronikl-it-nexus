# Изолированная интеграция Qwen для P4-Q

28.10.2026 владелец дополнительно разрешил API Qwen, используемый в Kitsune Math.
Это расширяет исходное ограничение пакета на облачный AI только для этой
изолированной интеграции и проверки. Main, production, Kitsune Worker/D1,
merge и официальный Release не изменяются.

В локальной конфигурации Kitsune Math подтверждены `qwen3.7-plus`, Singapore
и workspace endpoint, закреплённые в `qwen-upstream.mjs`. Чужой системный prompt
Kitsune, детские аккаунты, авторизация и секреты не копировались.

Браузерный адаптер обращается только к `/api/akronikl/qwen` своего origin.
Ключ читает сервер Node из `DASHSCOPE_API_KEY` либо файла, путь к которому задан
в `NEXUS_QWEN_KEY_FILE`. Файл должен находиться вне репозитория/evidence.
В браузер, prompt, storage и отчёт ключ не передаётся. Произвольный upstream,
модель, ключ или заголовки клиент выбрать не может. Сервер слушает только
`127.0.0.1`, проверяет Host/Origin, размер/структуру JSON, одну активную операцию,
таймаут, размер ответа и цитаты. Redirect запрещён. Сырые ошибки провайдера не
выводятся. Внутренние рассуждения отбрасываются; итоговые/частичные JSON сохраняются
только доверенным QA-наблюдателем. JSON/цитаты не доказывают истинность ответа.

Облачный режим доступен только host, явно передавшему capability `cloudBroker`.
Обычный production host её не получает: прежний default deny сохраняется.
В QA пользователь выбирает «Qwen3.7-Plus — облако» и подключает её. Автоматического
перехода с локальной модели нет. Передаются подготовленный вопрос, ограниченный
контекст продолжения, выдержка курса и только разрешённый текущий выделенный
фрагмент/диагностика. Полный проект, Account, голос и веса не отправляются.

## Запуск локального окна

В PowerShell из QA-копии исходного commit:

```powershell
$env:NEXUS_QWEN_KEY_FILE='C:\Users\User\Desktop\qwen-api-key.txt'
node tools/qa-akronikl/serve-cloud.mjs
```

Открыть напечатанный localhost URL, настройки → Модель → облачная Qwen →
«Подключить выбранную модель». До отправки вопроса платная генерация не начинается.
Ctrl+C завершает сервер. Ключ заранее создаётся в том же Singapore workspace;
действующий ключ Kitsune не сбрасывается.

## Настоящая проверка

`run-cloud.mjs` требует `NEXUS_QWEN_KEY_FILE`/`DASHSCOPE_API_KEY`,
`NEXUS_PLAYWRIGHT_MODULE`, `NEXUS_CHROME_PATH`, `NEXUS_QA_OUT`, `NEXUS_SOURCE_COMMIT`.
Запускается только после фиксации commit, `git archive` и проверки QA-копии.
Две реальные UI-реплики, 32 исхода корпуса, HTTP-отмена и восстановление сохраняются
в новый `RESULT.json`; существующий результат не перезаписывается. Максимум ответа
192 токена, `temperature=0.2`, `enable_thinking=false`, серверный таймаут45с.
Вызовы API расходуют квоту/баланс существующего аккаунта. Никакие эталонные ответы
в модель или результат не подставляются. Синтетические проверки используют отдельный
явный режим `NEXUS_CLOUD_TEST_TRANSPORT=synthetic-ui-only`, помечены
`realModel=false` и не являются доказательством настоящей генерации.

`firstOutputChunkMs` — первый upstream JSON-фрагмент, не видимый TTFT.
Время UI измеряется отдельно. Usage — счётчики провайдера; полная удалённая память
и чистое decode-время не измеряются. Отмена подтверждает закрытие HTTP на клиенте
и gateway, отсутствие позднего ответа и повторный запрос. Остановка вычисления
на стороне Alibaba не доказана (`remoteComputeStoppedProven=false`).

Полный локальный прогон остаётся на собственном SHA; последующие точечные повторы
и облачный прогон имеют отдельные SHA/результаты. Побайтовое совпадение prompt
не выдаётся за новое inference или независимую приёмку. `qualityAcceptance=false`.
