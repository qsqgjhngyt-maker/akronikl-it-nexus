# Пробное обучение «Уют-7» для Piper

Пользователь явно разрешил пробное обучение после пояснения, что Piper Irina не клонирует прежнего рассказчика. Это отдельный эксперимент feature-ветки. Main, production и официальный Release не изменяются. До проверки тембра и дикции обученный голос не считается принятым.

Запуск проводится из `cloud-dialogue-round-20261029`, в отдельном `private/piper-training-env`. Уже установленный CUDA PyTorch 2.9.1 из Kitsune-Qwen-Voice подключён для чтения; новые учебные зависимости установлены только в новую среду. Piper trainer закреплён на v1.8.0. Здесь сохранены воспроизводимые скрипты; среда, датасет, checkpoint и модель в Git не добавляются.

Данные: 178 размеченных записей рассказчика из существующей озвучки книги. После фильтра длительности/RMS/клиппинга — 169 записей, 23,02 минуты, mono PCM 22050 Hz. 148 записей находятся в train.csv, 21 — во внешнем holdout. Фрагменты одного исходного абзаца не разделены между этими выборками, проверены пересечения групп и хешей. Стандартный DataModule дополнительно делит 148 на 141 обучающую и 7 внутренних validation. Эта внутренняя выборка не называется независимой. Смысловое соответствие текста WAV автоматически не подтверждено ASR.

Основа: John от автора Bryce Beattie, который публикует checkpoint и его lineage как public domain: https://brycebeattie.com/files/tts/ . Исходный файл `john-2599.ckpt`, 845898697 байт, SHA256 `729c2da11c833fb6f890e614e4fca8584b6dc503081984d2c9ac82db55da9a4b`. Независимого опубликованного автором хеша нет; этот хеш фиксирует скачанный файл. Русская основа Ruslan была отвергнута из-за указанного в MODEL_CARD ограничения CC BY-NC-SA; её незавершённая загрузка не используется.

Linux metadata исходного checkpoint вызвали PosixPath FAIL в Windows до обучения. Исходник и FAIL сохранены. Отдельный CPU-конвертер временно сопоставляет PosixPath с PurePosixPath и сохраняет только tensor state_dict без optimizer/metadata. SHA256 полученной копии: `2a54866bd26d58ff138231f63a5eb097217abbdb92a0d53b0640ba8dede09ece`. Перед warmstart проверено совпадение 673/673 generator keys и 100% элементов; сам trainer перенёс 784 параметра, 0 skipped.

Третий пилот: batch 4, float32/TF32, seed 20261029, max_global_steps 2000 (около 1000 minibatches, так как два optimizer update на batch). Лимит training-loop — 45 минут, внешний предел дочернего процесса — 65 минут; экспорт ограничен 15 минутами. Второй пилот остановился с нативным 0xC0000005 после 422 шагов; причина не доказана. В третьем отключён периодический диагностический дамп во время CUDA-loop. Checkpoint сохраняется каждые 200 global steps. Сохраняются промежуточные checkpoint, CSV metrics, PROGRESS.json и отдельные stdout/stderr. Метрики конечности контролируются; уменьшение loss само по себе не является PASS качества речи. Автоматические MOS-модели и облачная телеметрия отключены, сеть обучения запрещена. Qwen API для обучения не используется.

После пилота: ONNX opset 15 через совместимый legacy exporter, хеши весов/конфига, настоящий inference в браузере на новых русских фразах, измерение нового синтеза отдельно от кеша. Проверить текст, разборчивость, тембр против принятого эталона, отмену и смену аккаунта. Не менять имя готовой Irina на «Уют-7» и не выдавать её скорость за скорость нового голоса.

Скрипт экспорта адаптирован из OHF-Voice/piper1-gpl v1.8.0; лицензия GPL-3.0-or-later сохранена в COPYING_PIPER.txt. Лицензии обучающих инструментов, runtime, акустической основы и целевых записей учитываются отдельно; этот эксперимент не является официальной публикацией модели.

Пользователь отклонил третий пилот: недостаточное сходство тембра, акцент и менее живая подача по сравнению с исходным голосом. Его ONNX, WAV, checkpoint, метрики и отрицательный отзыв сохранены. Этот голос не принят и не подключается обычным запуском стенда.

Четвёртый пилот — отдельное обучение от русскоязычной основы Dmitri medium. Официальный checkpoint в `rhasspy/piper-checkpoints`, revision `37d1bea250e21ca0d617818d2bef1db724edb80c`, путь `ru/ru_RU/dmitri/medium/epoch=5589-step=1478840.ckpt`, 845898328 байт, опубликованный LFS SHA256 `744a4824dcb149cda87248ec38bd9f92dad93f842ab1da51deeb27a074e47ba6`. MODEL_CARD указывает CC0 для целевого датасета и fine-tune от English Lessac medium; происхождение сохраняется, официальный выпуск модели этим не разрешается. Не подменять разрешение локального эксперимента заключением о распространении.

Файлы `convert-dmitri-base.py`, `train-piper-russian-pilot4.py`, `supervise-piper-training-4.py` используют отдельные каталоги, доказательства, оптимизаторы и `voice-pilot4.onnx.json`. Максимум 6000 global steps (около 3000 minibatches), checkpoint на 200 и далее каждые 1000 шагов. Состав train/holdout не меняется. Прежний английский пилот не продолжается и не объявляется удачным. Новый modelId `ru_RU-uyut7-pilot4-medium` исключает выдачу старых весов из OPFS под прежним именем. До настоящего синтеза и пользовательской проверки качества это только кандидат.

Независимая проверка выявила несовпадение native eSpeak и браузерного `piper_phonemize.wasm`: 44 из 148 train-последовательностей отличаются; 104 совпадают. Это не сдвиг ID общей карты: все 152 общих символа имеют одинаковые ID; дополнительные 14 символов новой карты в исходном train не встречаются. Для пилота 4 `prepare-piper4-wasm-cache.mjs` и `piper-wasm-cache.py` создают отдельный `cache-pilot4` из точных WASM/data браузера, проверяя их SHA против публичных ассетов. Существующие audio/spec копируются без изменений, IDs берутся напрямую из WASM без повторной сборки или изменения границ предложений. Оригинальный cache не редактируется, внешний holdout не читается. Перед началом fit повторно сверяются все 148 тензоров с сохранённым private результатом WASM. Полные тексты и IDs остаются в private; evidence содержит агрегаты и хеши. Это исправление конкретной несовместимости, а не доказательство принятого произношения или интонации.

Дополнительная необязательная подготовка к браузеру: `simplify-piper-experiment.py` сохраняет отдельный ONNX после onnxsim0.4.36 без квантизации и не заменяет raw export. Численное сравнение проводится на трёх длинах входа и двух режимах noise, с одинаковыми явными seed только во временных validation-копиях. Сохранённый файл сохраняет исходные стохастические узлы без этих seed. Совпадение шести CPU-выходов не является доказательством качества голоса, универсальной эквивалентности всех входов или ускорения браузера. Для каждого нового trial нужен собственный proof. Доставку конкретной версии модели в браузер QA сверяет с SHA/bytes манифеста по фактически отправленному HTTP Buffer. При смене весов после использования версии нужен новый basename/modelId, чтобы OPFS не вернул прежние веса.
