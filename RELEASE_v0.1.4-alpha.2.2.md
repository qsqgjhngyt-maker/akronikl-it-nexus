# AKRONIKL IT NEXUS v0.1.4-alpha.2.2

## Standard Library Provider-Limit Classification Hotfix

Live-проверка `v0.1.4-alpha.2.1` показала ещё один вариант ограничения JSCPP/Browser Runtime: корректная C++ программа с `#include <string>` завершалась сообщением `cannot find library: string`, а UI ошибочно окрашивал это как ошибку программы ученика.

В `v0.1.4-alpha.2.2` этот сценарий закрыт:

- отсутствие **известного стандартного C++ заголовка/библиотеки** в лёгком Browser Runtime классифицируется как **ограничение provider**;
- для такого ограничения Nexus не подсвечивает строку исходника как ошибочную;
- диагностика прямо называет отсутствующий стандартный заголовок, например `<string>`;
- опечатки и неизвестные заголовки (например `<strng>`) не маскируются и остаются обычной ошибкой;
- добавлен разбор формата `line:column` из сообщений provider;
- содержимое трёх benchmark-уроков не менялось.

После публикации требуется повторный live-smoke того же примера из скриншота. Только после чистого PASS Nexus Lesson Standard 1.0 переводится в `Normative Production`.
