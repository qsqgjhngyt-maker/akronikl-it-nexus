# Learning and Knowledge Assimilation Standard

## Goal

Content is not considered well taught merely because it has been published. A learner should receive multiple paths to understanding and a way to demonstrate transfer of the knowledge.

## Required topic flow

1. **Prerequisites:** what must already be known and where to review it.
2. **Why it matters:** engineering context and real use cases.
3. **First understanding:** a compact mental model with limited terminology load.
4. **Precise theory:** definitions, constraints, rules and vocabulary.
5. **Deep layer:** internal mechanism, memory, state, protocol, algorithm or mathematical model as appropriate.
6. **Examples:** minimal to realistic; line-by-line code explanation where useful.
7. **Counterexamples and common errors:** symptom → cause → fix → how to recognize it later.
8. **Experiment:** change code, data or parameters and observe the result.
9. **Independent practice:** a task without a full solution visible.
10. **Comprehension check:** test transfer, not only term recall.
11. **Skill Graph connection:** which competencies were strengthened and what opens next.
12. **Akronikl fallback:** if the default explanation fails, the mentor changes the explanation strategy rather than merely giving the answer.

## What “understood” means

Viewing is not mastery. For complex topics, use a combination of explaining in one's own words, solving, debugging, modifying an example and applying the principle in a new context.

## Depth

Theory length is not a target by itself. Simple topics may be concise; complex topics should be as detailed as required for durable understanding. Template-generated repetition is not acceptable.

## Language parity

All required learning entities use language-neutral IDs and may have multiple localizations. Switching language does not create separate progress for the same topic.
