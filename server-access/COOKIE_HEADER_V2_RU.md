# Передача cookies через Gateway: V2

При реальных входах обнаружен `INGRESS_REJECTED`: cookie-параметры в контексте Gateway расходились с Cookie, дошедшим до BFF. Синтетические запросы воспроизвели `session_mismatch` и `flow_mismatch`, включая запрос без соответствующего cookie. Причина расхождения внутри платформы не установлена. Отключение сверки не используется как исправление.

В V2 Gateway передаёт одну строку заголовка `Cookie` через параметр `in: header`. Контекст содержит только прежнее имя маркера со значением `v2` и `cookieHeader`; отсутствие заголовка представлено `-`. Разбор отдельных cookies выполняет один общий parser в BFF.

Перед выдачей credential выполняются строгая проверка Base64/UTF-8/формы контекста, ограничение размера, синтаксическая проверка обеих строк Cookie и сравнение их канонических пар. Наличие должно совпадать в обе стороны: контекст с credential при отсутствующем сыром Cookie отклоняется. Повторение защищённых cookie-имён и неоднозначные заголовки также отклоняются. Формат session/flow, private container/IAM, Host/Origin, HMAC, актуальность сессии, привязка accountId, state и PKCE сохраняются.

V1 оставлен для последовательного переключения и отката Gateway. Новый frontend credential или способ выдачи сессии не вводится; проекты, роли, аккаунты и секреты не меняются. Сначала публикуется BFF с поддержкой обеих версий, затем меняются только контексты и cookie-параметры разрешённых auth-маршрутов. Прежний manifest, Service Worker и публичное кеширование не затрагиваются.

Адресные проверки включают одинаковые и переставленные пары Cookie, отсутствие одной из сторон, неподходящий/устаревший контекст, дубликаты, несовпадение аккаунта, неверный/просроченный credential и реальные обработчики с синтетическим upstream. После переключения требуется отдельная live-проверка Gateway. Локальный PASS не заменяет подтверждение настоящего входа пользователем и не закрывает формальный Release Gate 05.
