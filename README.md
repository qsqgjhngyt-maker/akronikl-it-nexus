# Политика прав на внешние вклады

## Зачем нужна отдельная политика

После появления внешних pull request у проекта может быть несколько правообладателей. Это влияет на возможность менять условия лицензирования, выдавать исключения и защищать проект.

## Foundation-режим

До утверждения окончательной contributor model внешние вклады принимаются только после ручной проверки происхождения и прав. В PR автор должен подтверждать, что имеет право предоставить вклад проекту и что вклад не содержит неразрешённого стороннего кода/контента.

## Не выбирать DCO/CLA автоматически

- DCO удобно подтверждает право автора отправить вклад, но сам по себе не всегда решает вопрос будущего relicensing.
- CLA может дать проекту необходимые права, но должен быть прозрачным и не использоваться как скрытый механизм присвоения чужого труда.

Перед массовым приёмом вкладов нужно выбрать модель с учётом принципа Nexus: бесплатное образование, защита от коммерческой перепаковки и уважение прав контрибьюторов.

## Минимальный будущий стандарт

- attribution автора вклада;
- подтверждение происхождения;
- указание лицензии входящего вклада;
- запрет загрузки закрытого корпоративного кода и материалов без разрешения;
- отдельное согласие, если проекту потребуется право выдавать иные лицензии на конкретный вклад.
