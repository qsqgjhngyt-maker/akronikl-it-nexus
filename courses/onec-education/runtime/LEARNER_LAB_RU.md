# Проверка своей работы на официальной учебной 1С

Исходники сохраняются в работе Studio. «Подготовить запуск1С» создаёт отдельный снимок и запись запроса. Сам браузер не исполняет1С. Личный Windows-комплект выполняет снимок в новой временной Windows и возвращает небольшой JSON-протокол. Загрузите его обратно кнопкой «Загрузить протокол запуска». Работа, учебный прогресс и прежние попытки не заменяются; результат прежней ревизии остаётся в журнале с соответствующей отметкой.

Проверена Windows x64. Нужны Windows11Pro/Enterprise/Education с доступным Windows Sandbox,Node24 и установленный compiler.NETFramework. Официальную учебную поставку8.3.27.1508 владелец получает самостоятельно для своего учебного экземпляра. Никаких ключей host,платных сервисов,реального учёта или чужих конфигураций. [Условия поставки](https://online.1c.ru/admin/documents/agreement.php?ID=16463663),[официальная загрузка](https://online.1c.ru/catalog/free/28765768/). Право общего сервера для класса не предоставляется. В комплекте Nexus платформы/installer нет.

Оператор использует исходники того же кандидата. Сначала собрать собственные приложения в новый каталог, затем выполнить запрос в ещё одном новом каталоге:

```powershell
powershell.exe -NoProfile -File tools/check-onec-lab-bootstrap-build.ps1 -OutputDirectory <новая-сборка>
node tools/check-onec-learner-run.mjs <запрос.json> <новый-каталог-попытки> <распакованная-официальная-поставка> <новая-сборка> --personal-training
```

Команда проверяет установленный Microsoft Sandbox CLI,снимок,собственную сборку и media. Она создаёт только свою VM;если уже открыта другая — отказывает. В гостевой Windows сначала устанавливается подписанная учебная платформа,затем проверяется конфигурация ученика. Режим «Только проверить конфигурацию» компилирует модули;«Проверить и выполнить» дополнительно запускает учебный сценарий конфигурации. Шаблон «Учебная сервисная служба» понимает параметр `seed|<внутренний-файл>` и завершает сеанс сам. Другая конфигурация должна поддерживать собственное завершение;интерактивное приложение,которое остаётся открытым,достигнет лимита времени. Работа выполняется в новой базе и не перезаписывает предыдущую.

На установку отведено до600с на VC++ и600с на MSI;учебный запуск имеет общий гостевой бюджет90с и внешний watchdog110с. Win32 Job Object назначается до запуска первой инструкции процесса,ограничивает память/CPU/число обычных дочерних процессов и завершает их при закрытии. Host всегда останавливает именно созданную им VM,включая отказ/отмену. Job Object сам по себе не является полной границей против гостевого администратора и альтернативного запуска через системные брокеры;окончательная граница — отдельная VM и её остановка снаружи. Это личный учебный runtime,не общий сервер исполнения.

Сеть,vGPU,clipboard,audio/video/printer выключены. Подключена ровно одна отдельная папка только для чтения;папки host для записи не подключаются. Ученический код,база,необработанные логи и созданные в гостевой Windows файлы остаются внутри временной среды и после её остановки исчезают. Исходный снимок и исходники Studio сохраняются. Не использовать гостевую Windows как постоянное рабочее хранилище. Нужные изменения исходников вносить в Studio перед следующим снимком.

Результат находится в `<каталог-попытки>/NATIVE_RESULT.json`. Передаётся только привязка запроса/ревизии/контрольной суммы,ограниченный статус,номер файла/строки/колонки и факт остановки. Передачи произвольных гостевых файлов нет:используется только числовой ответ официального CLI. Любой импортированный локальный протокол недоверенный и не является серверной аттестацией. Нельзя считать code exit0 подтверждением правильности решения,авторства или освоения темы. `outputTrusted=false`,`codeVerifiedServer=false`,`credentialEligible=false`,`progressWritten=false`.

Если протокол относится к чужой работе/запросу,меняет флаги доверия или имеет неверный формат,Studio отклоняет его. Повторный импорт не заменяет первый. Повреждённый журнал не обнуляется;при заполнении/ошибке quota новый запрос отклоняется без потери прежних записей. Журнал находится в существующем account namespace и удаляется штатной очисткой данных своего аккаунта;IAM/OAuth/BFF/Worker/D1 контракты не изменяются.

WindowsHome,Android/iPhone и браузер без доступного внешнего стенда позволяют читать курс,редактировать/сохранять/экспортировать работы,но не запускают официальный1С внутри браузера. Облачный многопользовательский runtime и серверная проверка требуют отдельной законной поставки и приёмки.
