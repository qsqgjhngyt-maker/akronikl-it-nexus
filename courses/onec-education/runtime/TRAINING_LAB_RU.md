# Учебная 1С в отдельной Windows — операторский стенд

Это проверка собственного закреплённого эталона «Учебная сервисная служба», а не публичный сервис исполнения произвольных работ. Источник:12 файлов, SHA256 снимка `af19d9dab9679256247d30ec587fdb392e6ee62010489c5ec488deee155ae17b`. При другом SHA runner отказывает до установки. Экспорт Studio сохраняет исходную работу, ревизию и provenance; runner не пишет учебный прогресс и не выставляет зачёт.

## Поставка и условия

Владелец отдельно скачал официальную Windows-поставку учебной1С8.3.27.1508. [Страница продукта](https://online.1c.ru/catalog/free/28765768/), [соглашение](https://online.1c.ru/admin/documents/agreement.php?ID=16463663), [ограничения учебной платформы](https://v8.1c.ru/podderzhka-i-obuchenie/uchebnye-versii/distributiv-1s-predpriyatie-8-3-versiya-dlya-obucheniya-programmirovaniyu/). Источники проверены31.10.2026.

Условия предусматривают один компьютер на экземпляр, учебные задачи и разработку; исключают реальный учёт и распространение платформы/компонентов без разрешения. Учебная поставка не использует клиентские/серверные лицензии и ключи защиты. Здесь проверяется один личный отдельный экземпляр в файловом режиме, на синтетической собственной конфигурации. Из этих условий не выводится допуск к общему серверу для класса. Автоматического юридического допуска `sharedRuntimeLicenseAdmission` нет.

В Git находятся только собственные исходники, открытые контрольные суммы и протоколы. Установщик, CAB, платформа, учебные базы, дампы, необработанные установочные логи и бинарники наших служебных приложений остаются вне Git. Ключи/пароли/host-лицензия не переносятся. SHA и подпись подтверждают выбранные байты и издателя, а не право произвольного оператора пользоваться ПО.

## Подготовка без установки на основной компьютер

В checkout одного и того же candidate собрать собственные приложения имеющимся .NET Framework compiler:

```powershell
pwsh -File tools/check-onec-lab-bootstrap-build.ps1 -OutputDirectory <новая-сборка>
node tools/check-onec-official-lab.mjs <снимок-эталона.json> <новый-пакет> <новая-сборка>/NexusLabBootstrap.exe
node tools/check-onec-training-lab.mjs <новый-пакет> <распакованный-официальный-дистрибутив> <новая-сборка>
```

Каждый каталог должен быть новым. Export JSON не задаёт путь executable. Подготовка сверяет исходники/бинарник по build record и четыре media-файла по version lock; отказывает при подмене и не исполняет установщик на host. Build record локален и не является удалённой аттестацией. `NexusTrainingStatus` — отдельно собираемый операторский помощник: возвращает только фиксированный код стадии/результата собственного job, без канала чтения произвольных файлов.

Сгенерированная `.wsb` имеет единственный readonly input,4GiB RAM; отключены сеть, vGPU, clipboard, audio/video/printer. Запись результата на основной компьютер через mapped folder не разрешена. Оригинальные исходники доступны только для чтения; каждая копия, база, восстановление и мутация создаются в новом guest UUID-каталоге. Штатный PowerShell guest не используется; ExecutionPolicy/GPO/security/privacy не меняются.

## Запуск и проверка

Использовать штатный [Windows Sandbox CLI](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-cli). Команда может находиться в зарегистрированном MicrosoftWindows.WindowsSandbox MSIX, а не в PATH/System32. Проверка наличия команды не равна успешной установке/исполнению1С. CLI возвращает отдельный ExitCode гостевого процесса: host exit0 сам по себе не PASS.

В активной пользовательской сессии guest выполнить `C:\NexusInput\NexusTrainingRunner.exe --batch <новый-UUID>`. На обычном host служебное приложение отказывает. Оно повторно сверяет manifest и readonly, version lock, SHA всех media, Windows Authenticode и закреплённый сертификат издателя. Проверенные media копируются внутрь отдельной guest-попытки и снова проверяются; Windows Installer получает локальные CAB/MST. Подпись установленного `1cv8t.exe`, SHA и ProductVersion проверяются до исполнения.

Для x86 VC++ используется установленная совместимая v14-среда только при наличии Installed registry flag, подходящих версий двух DLL и действительных подписей Microsoft. Нижняя граница14.16.27033.0 взята из фактической версии пакета поставщика. При отсутствии зависимости запускается именно подписанный пакет поставки и результат проверяется снова. [Правило совместимости Microsoft](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170). Нельзя считать один registry flag успешной проверкой зависимости.

Бюджеты установки и запуска разделены: не более600с для VC++,600с для MSI и90с для каждого запуска1С. Реальные offline проверки установщика занимали около120с на отдельный подписанный пакет. Это не причина отключать проверки подписей/ограничений Windows. Точный результат определяется завершением установщика, кодом возврата и последующей проверкой установленной платформы. На таймауте уничтожается только непосредственно запущенный процесс; Windows Installer может ещё завершать свою дочернюю транзакцию. Поэтому не начинать конкурирующие установки и не объявлять завершение по отсутствию клиентского процесса.

Runner воспроизводит существующую спецификацию:70 core+3 loopback HTTP case IDs,8 положительных сеансов,12 документов,440 минут оригинала/455 минут изменённой копии; повторное наполнение, reopening, backup/restore, проверка неизменности оригинала. Отдельные синтаксическая и семантическая мутации должны быть отвергнуты. HTTP обращается только к синтетическому127.0.0.1 сервису внутри guest; наружная сеть остаётся отключённой. Это настоящий `1cv8t.exe`, не подсветка/JS/OneScript.

Только ExitCode0 означает прохождение всех этих проверок закреплённого эталона. Ограниченный `TRAINING_RESULT.json` и private-логи остаются в guest. `--show-result <UUID>` открывает протокол для чтения. Перед завершением среды сохранить нужные разрешённые доказательства. Для завершения именно своей временной среды использовать `wsb stop --id <UUID>`; закрытие окна не гарантирует остановку VM. Не завершать процессы клиента/сервера и системные службы вместо штатного lifecycle.

## Границы приёмки

Реальный результат и связанные SHA находятся в отчёте S5. Исторические S3/S4 не переписываются. Этот стенд не принимает произвольный ученический BSL и не является web runtime. Автоматический возврат проверенного результата в Studio, многопользовательская изоляция/лицензирование, серверные сценарии, роли/RLS, конкуренция и фоновые задания требуют своей платформенной матрицы и согласованного контракта. `codeVerifiedServer=false`, `credentialEligible=false`, `progressWritten=false`; онлайн-проверка отзыва сертификатов не заявлена при отключённой сети. Человеческую security/педагогическую приёмку и выпуск не заменяет успешный эталон.
