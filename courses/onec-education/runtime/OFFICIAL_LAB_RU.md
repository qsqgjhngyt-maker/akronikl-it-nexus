# Официальный изолированный стенд1С — подготовленный кандидат

Приоритет владельца: законно лицензированная установленная1С; при отсутствии — отдельный официальный учебный экземпляр. Платформа8.3.27.2214 с действительной подписью установлена на host; собственный эталон снова выполнен в новой базе. Это операционная проверка, а не перенос лицензии или подтверждение прав отдельного guest.

Точное [соглашение учебной версии](https://online.1c.ru/admin/documents/agreement.php?ID=16463663) прочитано31.10.2026 в официальном браузерном источнике. Оно ограничивает использование одним компьютером и требует отдельного экземпляра для другого; разрешает учебные задачи и разработку, исключает реальный учёт, запрещает распространение продукта/компонентов без разрешения. Клиентские и серверные лицензии с этой учебной поставкой не применяются. Из соглашения не выводится право на общий сервер исполнения для класса. Виртуализация и право конкретного guest требуют отдельной проверки выбранной поставки; простое копирование host-ключей не используется.

Подготовка: экспортировать в Studio «Снимок для официального стенда1С» и выполнить в checkout того же SHA:

```powershell
node tools/check-onec-official-lab.mjs nexus-onec-official-snapshot.json <новый-каталог>
pwsh -File tools/check-onec-official-host.ps1
```

Создаются новая `.wsb`, оригинальные исходники, manifest по SHA/ревизии и guest script. Платформы/installer/лицензий/ключей/чужих конфигураций нет. Исходная работа и прогресс не меняются. Готовый пример содержит собственную «Учебную сервисную службу»,12 файлов.

Конфигурация [Windows Sandbox](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file): сеть, vGPU, clipboard, audio/video/printer отключены;4GiB RAM; единственный mapped folder — отдельный input с ReadOnly=true. Host-output mapping отсутствует. Результаты остаются внутри guest; автоматическое извлечение/зачёт не реализованы. Перед закрытием оператор должен сохранить нужный протокол разрешённым способом. Guest script отказывается работать на обычном host, проверяет manifest, отдельное право guest, подпись/версию установленной внутри guest платформы и запускает новую базу. Каждый запуск создаёт новый каталог; результаты ученика остаются недоверенными. Изменение guestUseConfirmed в JSON само по себе не является правом на ПО.

На текущем компьютере Windows Sandbox command/package не найдены, текущий процесс не Windows admin; состояние optional feature без admin не объявляется Disabled. ОС не менялась, перезагрузка не выполнялась. Пакет IMPLEMENTED и автоматически проверен, физический guest launch — BLOCKED_HOST_SANDBOX_UNAVAILABLE. Наличие Docker Linux этого не устраняет. Ученический код на обычном host не запускается. Дальнейшая настройка ОС/guest должна выполняться уполномоченным оператором с подтверждёнными правами, до LIVE PASS публикация runtime не готова.
