# Нативная лабораторная A1/P1

Это оригинальный минимальный стенд Nexus. В нём нет типовых конфигураций или рабочих данных. Заявки P1 существуют в памяти; реальные справочники и документы относятся к следующим модулям.

Проверенная авторская среда: Windows, официальная платформа 8.3.27.2214, файловая база, толстый клиент управляемого приложения. Публичная учебная Windows-сборка 8.3.27.1508 — отдельная цель совместимости: результат на ней пока NOT RUN. Не переносите PASS между сборками автоматически.

Автоматический путь из корня GitHub checkout:

    ./tools/check-onec-native.ps1 -PlatformPath "ПОЛНЫЙ_ПУТЬ_К_1cv8.exe" -OutputDirectory "НОВЫЙ_КАТАЛОГ_ЭКСПЕРИМЕНТА"

Параметр PlatformPath указывает на вашу официальную установку. Используется только версия 8.3.27.x. Каталог OutputDirectory должен отсутствовать. Скрипт не читает список ваших баз, не добавляет туда новую запись, не запрашивает пароли и не меняет исходные работы. Он создаёт три изолированные базы, проверяет исполнение, выгрузку/восстановление и намеренную синтаксическую ошибку в отдельном стенде. Запуск на существующий каталог отклоняется.

Ручной путь, по одной операции с проверкой результата:

1. В окне запуска создайте новую файловую базу без конфигурации в новом каталоге. Проверьте полную версию платформы и имя базы.
2. Откройте только эту базу в Конфигураторе. Загрузите конфигурацию из файлов папки service-desk, затем проверьте конфигурацию.
3. Обновите конфигурацию базы данных. Не применяйте изменения к неизвестной базе.
4. Запустите режим 1С:Предприятие. В сообщениях ожидается NEXUS_1C_P1|requests=3|minutes=105|negative=2|PASS. Без автоматического параметра приложение остаётся открытым для наблюдения.
5. Закройте пользовательский сеанс. Выгрузите информационную базу штатной командой Конфигуратора.
6. Создайте ещё одну новую пустую базу. Восстановите туда выгрузку, повторите запуск и сравните результат. Исходник сохраняется.

Автоматический протокол NATIVE_RESULT.json содержит версию, коды операций, hashes исходников и проверенные границы. BSL_RESULT.txt и RESTORED_BSL_RESULT.txt содержат только синтетический вывод. Базы, .dt и *.private.log остаются локально; их не нужно добавлять в GitHub. Файлы лицензий и сведения активации не собираются.

Для обучения без установки используйте теорию, схемы и самопроверку. Они не исполняют 1С. Отсутствующая нативная часть остаётся NOT RUN в личном протоколе.

Лицензии: установщик берётся с официального сайта, условия принимает сам пользователь. Бесплатное получение не даёт права переупаковать платформу. Сервер и платные услуги для P1 не требуются.

## Консолидация PR #62 в #63

В модуль добавлена исходная функция СтоимостьУслуги из #62 с сохранением числовых предусловий. Три исходных случая (30/600→300, 60/900→900, 0/600→0) дополнены границами (1440/0→0, 1440/100000→2400000). Нативный gate вызывает функцию и сохраняет отдельную строку `NEXUS_1C_SERVICE_COST|normal=3|boundary=2|PASS` в `BSL_RESULT.txt.service-cost.txt`; после восстановления — в `RESTORED_BSL_RESULT.txt.service-cost.txt`. Прежний BSL_RESULT.txt не меняет формат.

Функция не проверяет произвольный ввод и не задаёт финансовую политику округления. Это отдельные задачи P2/P3. Паспорт среды фиксирует неизвестный профиль лицензии и архитектуру платформы как NOT_INSPECTED, не придумывая их по месту установки. Исторические нативные отчёты #63 до консолидации сохраняются отдельно.
