# Учебная сервисная служба — A2/P2

Оригинальная конфигурация Nexus `0.2.0-a2p2`. Это отдельный стенд; `service-desk/` A1/P1 не меняется. Платформа и сторонние конфигурации в комплект не входят. Используются только синтетические данные.

Реально проверенная среда: Windows, официальная 1С 8.3.27.2214, файловая база, толстый клиент управляемого приложения. Учебная 8.3.27.1508 отдельно NOT RUN; профиль лицензии/архитектура платформы NOT_INSPECTED. Эти сведения не выводятся из каталога установки. Сервер, Cloud/IAM и платные услуги не нужны.

## Один новый эксперимент

Из корня checkout или отдельной копии автономного комплекта:

    ./tools/check-onec-native-next.ps1 -PlatformPath "ПОЛНЫЙ_ПУТЬ_К_1cv8.exe" -OutputDirectory "НОВЫЙ_КАТАЛОГ"

Сначала проверьте, что OutputDirectory отсутствует. Скрипт отказывает для существующего каталога; ничего не очищает. PlatformPath относится к вашей официальной установке; установщик и условия получения проверяются владельцем отдельно. Список чужих баз не читается, пароли/лицензионные сведения не собираются.

Gate создаёт только собственные source-base, copy-base, negative-base и semantic-base внутри нового каталога. Он загружает оригинальные XML/BSL `service-desk-a2p2`, проверяет конфигурацию и выполняет семь положительных сеансов. Исходные A1/P1 базы не используются.

## Что должно получиться

- Клиенты: C001 Альфа, C002 Бета, C003 другая Альфа с иной ссылкой. Услуги: S001 Диагностика/600, S002 Настройка/900.
- Исходные документы A200001 (C001/S001/30/Новая) и A200002 (C002/S002/45/ВРаботе). Всего 75 минут. Они сохранены, проведение запрещено.
- Повторный seed не создаёт дублей и не переписывает существующие элементы. Новый сеанс читает прежние значения.
- Restore в copy-base сохраняет identity записей. У отдельной работы собственный workspace ID/alias, а не новые GUID каждого документа.
- В copy-base второй документ меняется до 60: итог 90 после повторного открытия. ORIGINAL_PRESERVED снова читает исходные 75.
- Каждый положительный сеанс проверяет 46 case IDs: 35 P2 и 11 A2. Они перечислены в `a2p2-spec.v1.json` и `SEED.txt.cases.txt`.
- Пустой клиент и отрицательные минуты отклоняются без добавления документов. Испорченный синтаксис отклоняется CheckConfig. Семантическая копия с вычитанием проходит синтаксис, но выдаёт `FAIL|NEXUS_CHECK_FAILED: P2.1.russian-keywords`.

Изменённая copy-base уже содержит 90. Для собственной пользовательской практики с исходными 75 восстановите source dump в **ещё одну новую** базу, дайте работе новый ID и сохраните происхождение. Не редактируйте принятый source-base, пытаясь одновременно сохранить его как контроль.

## Ручная практика, по одному действию с проверкой

1. Создайте новую файловую базу в отдельном месте и восстановите собственную учебную выгрузку. Проверьте её alias и ревизию.
2. Откройте её в режиме Предприятие **без параметра запуска**. Тестовый модуль не выполняет автоматическое заполнение/запись при таком открытии.
3. Через подсистему Учебная сервисная служба откройте справочники и заявки. Если команда недоступна, проверьте режим/состав конфигурации; не используйте чужую базу. Названия и расположение команд могут различаться.
4. После каждого действия сверяйте номер, код, ссылку и значения. Для опыта сохранения/отмены закрывайте и вновь открывайте нужный объект. История переходов не является аудитом данных.
5. Перед собственным изменением подготовьте ещё одну копию. Добавленная третья заявка меняет критерий количества; fixed gate на такую работу ожидаемо не подходит. Сохраните отдельный протокол вместо переписывания эталона.

Автоматический gate не доказывает выполнение этих ручных UI шагов. Их отмечают отдельно по факту наблюдения. Стандартные формы создаются платформой по метаданным; браузерные модели Nexus не подключены к этой базе.

## Что сохранить

`NATIVE_A2P2_RESULT.json`, SEED/REOPEN/RESTORED/EDIT_COPY/REOPEN_COPY/ORIGINAL_PRESERVED summaries, cases и snapshots, SEMANTIC_REJECTION, паспорт и заметки своей работы. UUID в этих снимках относятся только к синтетическим объектам. Базы, `.dt`, `*.private.log`, личные каталоги, лицензии и установщики остаются локально и не добавляются в GitHub.

Исходники `examples-a2p2/*.bsl` — точные фрагменты полного реально исполняемого модуля. Это не самостоятельные программы: функции вызываются из общего стенда. Для своего эксперимента сначала скопируйте **весь комплект** в отдельное место, затем изменяйте только эту копию и выбирайте новый output. Дополнительный тест/новый контракт нельзя объявить принятым старым fixed gate без отдельной проверки.

Completion Nexus — локальный самоотчёт с ревизией, не защищённая оценка. Новый урок требует своей попытки; старые работы, attempts и provenance не очищаются. Перенос заметок между курсами не переносит зачёт. Проведение, регистры, конкурентные транзакции, server execution и авторство ученика этим стендом не доказаны.
