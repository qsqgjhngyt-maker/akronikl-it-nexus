How to do a lab: from Studio to a training 1C infobase

Nexus and 1C are separate windows. Write and save source files in Studio. Open a training infobase and check the result in the installed 1C application. These instructions are for Windows.

Two workflows: installed 1C and temporary Windows

The eight steps below describe manual work in an installed training 1C application: opening windows, entering data and viewing results. The separate isolated kit checks a code snapshot inside temporary Windows Sandbox. The tested kit requires Windows 11 Pro/Enterprise/Education x64, enabled virtualization and a separately prepared personal kit. This workflow has not been tested on Windows Home.

To enable the component, search Start for Turn Windows features on or off, select Windows Sandbox and confirm with OK. Restart if Windows requests it. Skip this step if it is already enabled. Close other Sandbox windows before starting the kit.

For an isolated check, edit code in Studio, select Save and wait for Saved on this device. In Official 1C checks choose the check type and select Prepare official 1C run. It downloads nexus-onec-official-snapshot.json.

A separately prepared personal Windows kit executes the request. Starting it is currently a separate action described by Local execution instructions in Studio. Downloading JSON does not open temporary Windows; the browser has no automatic launch button yet.

The kit creates temporary Windows, installs the official training 1C application, checks a copy of the sources and stops that environment. Do not keep your only work or edit code inside it: make changes in Studio before the next check.

When the check finishes, its attempt directory contains NATIVE_RESULT.json. In Studio select Import execution report and choose that file. The history shows the result for that exact snapshot. Importing it does not complete a lab automatically.

Saved work and progress remain in Nexus. The temporary infobase and guest files are removed. Only a bounded check report returns, not arbitrary files or an infobase.

1. Prepare the 1C application

If an official 1C platform is already installed and you may use it for learning, continue to the next step. Otherwise open Download training 1C 8.3.27.1508 below. Complete the official request form and read the terms. A distribution download link arrives at the email address you provide. Nexus source files do not include the platform.

Follow the instructions for your distribution. If the installer is in a ZIP, right-click the archive → Extract All → Extract. Run setup.exe from the extracted folder if supplied, and follow the installation wizard. Read and accept the applicable terms yourself.

The Windows Start menu contains the 1C:Enterprise launcher or its training edition. Signing in to Nexus does not install 1C.

2. Open your own working copy in Studio

Open the lesson in Academy. Select Laboratory, then Open laboratory in Studio. Sign in to Nexus if necessary.

Check the selected course and lesson. Select Create new working copy. If you already have work, open it from the list. For a new experiment use New separate copy; the original work stays in place.

The editor shows a file list and the work has its own title. The starter template has 9 files; the full training template has 12.

3. Change the code and wait for confirmation

Select the file specified by the exercise. A .bsl file contains a 1C module; .os files are for separate language exercises. XML describes configuration structure and is protected in the original copy.

Make the requested change. Select Save and wait for Saved on this device. Reopen this work through My projects and check the text. If saving reports an error, keep the editor open and export the sources.

Your code is present after reopening. Saving code does not run it or mark the lesson complete.

4. Download and extract the ZIP

Select Download files ZIP. The browser saves nexus-onec-sources.zip, usually in Downloads. The archive contains the currently open source text.

Right-click the ZIP → Extract All. Choose a new folder, for example C:\NexusLabs\Lesson_01, and select Extract. Open the extracted folder: it should contain instructions and a src directory.

Inside src, find Configuration.xml and the Ext, Catalogs and other template directories. The source directory and the infobase directory are separate. If Configuration.xml is absent, this is an individual-file exercise rather than a full configuration: follow that exercise’s instructions.

You can see src\Configuration.xml in an extracted folder, outside the ZIP viewer. A JSON export is not an archive.

5. Create a new training infobase

Launch 1C from the Start menu. In the infobase list select Add → Create a new infobase → Next.

Choose to create an infobase without a configuration. Name it Training service desk — experiment 01. Select storage on this computer and a new empty directory, for example C:\NexusLabs\Base_01. Complete the wizard with Finish.

Select this new training infobase and open Designer (Конфигуратор in the Russian interface). Use a separate infobase and directory for each independent experiment or restoration.

Designer opens the new training infobase. Base_01 stores the infobase; Lesson_01\src stores its source files.

6. Load the configuration from src

In Designer select Configuration → Load configuration from files. Choose the extracted src directory containing Configuration.xml. In Russian: «Конфигурация» → «Загрузить конфигурацию из файлов…».

Load configuration from file expects a .cf file and is a different command. Do not select ZIP or JSON there. If the menu is unavailable, first select Configuration → Open configuration.

After loading, select Configuration → Update database configuration, or press F7 in Designer. In your new empty training infobase, accept the listed objects being added. If an error appears, preserve its text and return to the indicated file; do not mark the lab complete yet.

The configuration tree contains the training objects and the database update completes without an error. Studio source files have not been replaced.

7. Run 1C and follow the lesson

In Designer select Debug → Start debugging, or press F5 in the Designer window. Alternatively close Designer, select the infobase in the launcher and choose 1C:Enterprise.

A separate 1C window opens. The template displays a training-service-desk message. Ordinary first startup does not seed records automatically, so empty lists are expected. This proves the application opened; it does not yet prove the lab passed.

Open the Training service desk section and the list named in the exercise, such as Customers or Services. Use synthetic records. Compare each action with the lesson’s Expected result. Some exercises require additional objects or a separate server environment; follow the requirements in that lesson.

You can see 1C and the result of your actions, and explain whether it matches the exercise.

8. Preserve the result and record completion

Preserve the sources and the evidence required by the lab, such as a screenshot, output text or a verification table. If you changed code in Designer, copy that text back to the corresponding Studio file and select Save.

Return to the Nexus lesson. Answer the questions and select Check understanding. After actually completing the lab, tick the lab attestation and select Mark complete by self-report.

This course’s progress counter changes. The other course receives no transferred credit. The mark is your learning self-report, not an automatic certificate.

How to complete a knowledge check and final assessment

For one lesson, open Knowledge check, answer the questions and select Check understanding. Read the explanations. After actually completing the lab, attest it and select Mark complete by self-report.

For the final assessment return to this course’s page and select Final assessment or Open final assessment. Choose a variant. Each of the three variants has 24 questions. Answer them all and select Check and preserve attempt. Check the result and attempt count in the history.

Read the four practical tasks and expand Acceptance criteria for each. Use separate copies and follow the main lab workflow. Preserve the source ZIP and the evidence named by the task, such as screenshots and the execution report.

In Independent project select one of the three projects. Read its scope, deliverables and rubric. In Evidence portfolio describe your copy, checks, observed results and remaining limits. Include references and identifiers required by the project. This is a text field, not a file upload: preserve the archives and screenshots separately.

After doing the work, tick the attestation and select Preserve portfolio version. Wait for confirmation and check the version count in the history. A new version preserves the previous one. Use Export this course assessment history to keep a backup.

Theory answers are checked locally. The portfolio records your self-report; importing a 1C report does not grade the project automatically. The two courses have independent results. This page awards no certificate, instructor grade or server attestation.

Where to put your first test line

In your own copy select Ext/ManagedApplicationModule.bsl. Find «Процедура ПриНачалеРаботыСистемы()». Add the following line immediately inside the procedure, before conditions or Возврат. Do not put it outside the procedure.

Сообщить("My startup check");

Save, download a new ZIP, load its src into your training infobase, update the database configuration and run 1C. The message «My startup check» should appear. This step is optional for exercises without programming.

How to back up the infobase

Close the 1C:Enterprise window and open this training infobase in Designer. Select Administration → Dump infobase and save a separate .dt file. In Russian: «Администрирование» → «Выгрузить информационную базу…».

To verify restoration, create another new empty infobase in a different directory. In its Designer select Administration → Restore infobase and choose the .dt file. Open the restored copy and compare the data. Do not load the backup over the original infobase.

Which file is for what

Source ZIP: Extract it and load src using Load configuration from files in Designer.

nexus-onec-sources.json: Transfer a work back to Nexus with Import 1C sources. It is neither an archive nor a 1C infobase.

nexus-onec-official-snapshot.json: A request for a separately prepared personal verification kit. Downloading it does not start 1C.

.dt: An infobase backup restored by 1C into a new separate infobase. Do not import it into Studio as source code.

If something goes wrong

Prepare official 1C run downloaded a JSON file
This is expected: the button creates a request for an external personal verification kit. If the kit has not been prepared, follow the manual ZIP and Designer workflow above. The browser does not execute BSL.

1C asks for a .cf file
You selected Load configuration from file. Choose Load configuration from files instead, then select src.

I changed the code but see the old result
Download the ZIP after saving, load it again, update the database configuration and restart 1C. Check the name of the infobase you opened.

The editor will not let me change a file
XML is protected in the original copy. Create a new copy with metadata editing enabled when the exercise requires it. If another tab is editing this work, close that editor and select Enable editing.

I am using a phone or have no installed 1C
You can read lessons and work with text. Actual platform checks require a PC and the environment stated in the lab. The offline course package does not include a 1C installer.
