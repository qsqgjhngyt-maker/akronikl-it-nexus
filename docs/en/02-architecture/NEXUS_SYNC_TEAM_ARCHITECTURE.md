# Nexus Sync & Team Architecture

Foundation version: `v0.1.7-alpha.2.1`.

## Goal

One Project Studio project can safely exist on multiple devices and, after an explicit invitation, be shared with multiple team members. Personal projects remain private by default.

## Security boundary

The browser UI is not an authorization authority. The Worker makes the ALLOW/DENY decision after user identity has been established.

Authorization chain:

`subject -> workspace membership -> project membership -> role -> path scope -> action -> ALLOW/DENY`

Explicit DENY has priority over ALLOW.

## Roles and scopes

Base roles: owner, maintainer, developer, docs_editor, qa, viewer.

`docs_editor` has write scope on `docs/**`; `qa` has write scope on `tests/**`. Owners can add explicit allow/deny rules for a subject or role, for example deny `/releases/**` or allow only `/docs/api/**`.

## Local-first

The local project stays usable offline. Local revision, server revision and base server revision are tracked separately. Divergent server state must create a conflict instead of silently overwriting a newer revision.

## Cloudflare split

- Worker: API, authentication adapter, authorization and revision protocol.
- D1: workspace/project metadata, memberships, ACL, invites, revision index and audit.
- R2: immutable project snapshots.
- Durable Objects: future realtime coordination / presence / locking.
- Queues: future build, export and background jobs.

R2 keys are generated by the Worker from verified workspace/project/revision values and are never accepted directly from the browser.

## Audit

Server audit is append-only by system semantics. Sync updates record actor, before/after revision and changed project paths. Diff/review UI will be built on top of this model.
