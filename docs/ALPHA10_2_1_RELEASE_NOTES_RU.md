# Alpha10.2.1 — фотографии блога и обновление интерфейса

Версия: `0.1.7-alpha.2.4.6-ui1a.10.2.1`. Generation: `ui1a-alpha10-photo-20261022`.

Статус этого исходного changeset: локальный кандидат. Публикация и загрузка фото через действующий Yandex BFF с исправлением ещё не проверены. До подтверждения физических сценариев выпуск остаётся prerelease.

Фотографии получают постоянный статус рядом с кнопками выбора. При ошибке сохраняются текст статьи, прежняя обложка и оформление. Отмена выбора не отправляет запрос; подтверждение ключом восстанавливает управление и не повторяет загрузку автоматически. Сообщение о сохранении или публикации больше не заменяется фоновой подсказкой о доступности фото.

Для серверной загрузки фото применяется отдельный IPv4 dispatcher через обычный DNS с проверкой TLS. Он устраняет воспроизведённый на точном Linux runtime отказ выбора IPv4/IPv6. Общий 12-секундный deadline, HMAC, Origin, Cookie, Account, CSRF, fresh-passkey и строгая политика ответа сохраняются. Автоматических повторов POST нет. Остальные запросы Account/Cloud используют прежний транспорт.

Временная диагностика действующего BFF подтвердила `BLOG_MEDIA_UPSTREAM_NETWORK_FAILED`, HTTP 502, и сообщённые владельцем 12,98 с. Прежний image возвращён менее чем через 11 минут с сохранением настроек и secret bindings. Нижний сетевой exception в Yandex не наблюдался: IPv4/IPv6 как точная причина production-сбоя остаётся гипотезой до адресного LIVE-подтверждения.

Ручная кнопка «Проверить обновление» находится в левом меню. Плавающее уведомление появляется при подтверждённой новой версии. Проверки незавершённых изменений и сохранности данных продолжают защищать обновление; автоматической перезагрузки нет.

В установленной PWA кнопка повторной установки скрыта. Владелец подтвердил именно этот сценарий на iPhone; код установки не изменялся.

Собраны отдельные frontend/SW и BFF image, сохранены семь предыдущих публичных поколений. Подготовлен безопасный rollback к Alpha10.2 с сохранением нового поколения. Старый небезопасный SW не возвращается, проекты, CacheStorage и IndexedDB не очищаются.

Автоматические проверки выполняются на синтетических данных в локальном Chrome, workerd/D1 и Linux/TLS fixtures. Они не заменяют Windows Hello владельца, реальный upload через Yandex и физические iPhone/Android. Уже подтверждённые на Alpha10.2 сценарии входа и Cloud PUSH/PULL сохраняются как прежние OWNER LIVE evidence.
