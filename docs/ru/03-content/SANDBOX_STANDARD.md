# Стандарт Nexus Sandbox

## Принцип

Практические задания являются частью единой экосистемы Nexus. Учащийся не должен быть вынужден покидать платформу и устанавливать стороннюю IDE только для выполнения базовых заданий курса.

## Обязательный минимум

Каждый программный курс, где это технически возможно, должен предоставлять внутри платформы:

- редактор кода;
- стандартный ввод (`stdin`) и вывод (`stdout`);
- запуск и понятную диагностику;
- восстановление эталонного примера;
- сохранение пользовательского кода в прогрессе;
- самопроверку доступности runtime;
- адаптивный интерфейс для клавиатуры и сенсорного экрана;
- единый визуальный язык Nexus независимо от конкретного runtime/provider.

## Provider-independent архитектура

UI песочницы не должен зависеть от одного исполнителя. За единым интерфейсом в будущем могут использоваться:

1. browser runtime — быстрый локальный учебный режим;
2. WebAssembly/runtime — более полная локальная реализация;
3. защищённый compiler backend — для тем, требующих полноценного toolchain;
4. локальная среда пользователя — как дополнительный экспертный режим, но не как обязательный базовый путь.

## Мобильность

Ключевой сценарий обязан оставаться выполнимым без VS Code/Visual Studio. Для полей кода на мобильном устройстве необходимо исключать нежелательный autocorrect/autocapitalize и избегать размеров шрифта, вызывающих принудительный zoom на iOS.

## Надёжность

Перед релизом курса должны проверяться:

- self-test runtime;
- запуск эталонного примера;
- `stdin → program → stdout`;
- понятное сообщение при недоступности runtime;
- сохранение/восстановление кода;
- отсутствие зависания основного учебного интерфейса на типичном корректном примере;
- desktop и mobile smoke-test.

## Граница текущего alpha

Текущий C++ runtime является учебной браузерной реализацией и не объявляется полной заменой промышленного native toolchain. Для продвинутых тем провайдер выполнения может быть заменён без изменения интерфейса учащегося.

## Standard 1.2 — provider-based Sandbox
С v0.1.2-alpha.3 Sandbox рассматривается как единая инженерная среда, а не только учебный интерпретатор. UI не зависит от конкретного runner. Минимальный contract: `run`, `selfTest`, capabilities, diagnostics, stdin/stdout и provider metadata. Browser Runtime активен сейчас; WASM и Secure Build Runner — предусмотренные расширения.

Для упражнений интерфейс показывает отдельно: структурную проверку исходника, факт выполнения, diagnostics runtime и выполнение требований задания. Сырой технический вывод не скрывается, но показывается вторым уровнем после понятного объяснения.
