## Контракты проверки

Матрица содержит 21 программу и 42 сценария на одинаковых исходниках для g++ C++20/UBSan и действующего router/Worker/Clang-WASI. Проверяются границы, пустые и повторяющиеся значения, три сортировки, устойчивость, сравнение с oracle, STL, допустимое инвалидирование, binary search и отклонение неотсортированного ввода, ограниченная рекурсия, hash collisions, файлы/многофайловая сборка, два отрицательных compile/link контроля и regression M1/M2.

У `mt19937` проверяется стандартизованное 10000-е значение; у distribution — повтор внутри одной реализации, диапазон и размер. Точные distribution stdout между libstdc++ и libc++ не навязываются. `random_device`, криптография и системная энтропия не требуются. Clock probe проверяет доступность steady clock и неотрицательные samples, а не преимущество одного алгоритма. Формулы стоимости обосновываются подсчётами и моделью операций; время компиляции отделяется от запуска.

Синтетическая сохранность охватывает empty/partial/40/45, все 45 lesson records, quiz/code/stdin/VFS/unknown fields, повтор legacy import, будущие 50 ID без регистрации, project/checkpoint, Offline transfer и конфликт. Прежний curriculum по-прежнему рассчитывает 45/45; будущий показывает 45/50 и сохраняет legacy 40/40. UI не реализует отдельный архивный badge каждой промежуточной версии; такой badge нельзя считать доказанным этим аудитом.

Отдельный Chromium проверяет три прежних M4 ID online/cold Offline и настоящую многофайловую сборку через Code Studio. Только новый синтетический профиль: личный аккаунт, cookies, пользовательские работы и Cloud PUSH/PULL не используются.

## Источники и ограничения

[C++ draft: sorting](https://eel.is/c++draft/alg.sorting), [предопределённые engines](https://eel.is/c++draft/rand.predef), [distribution requirements](https://eel.is/c++draft/rand.req.dist) — primary reference для контрактов. Это изменяемый draft, а не доказательство поддержки runtime или эквивалентности курса университетской программе. Поддержка подтверждается реальным исполнением C++20; педагогическая эффективность требует отдельного пилота.

CI сохраняет FAIL и исходные артефакты. До фактического завершения не объявлять AUTOMATED PASS, LIVE или FULL LIVE PASS Module 4. Итоговый отчёт должен связать точный feature SHA, native/WASM parity, preservation, NEXUS-PERF-01 и границы допуска M4-1. Никаких новых Gold объектов, защищённого autograding или Mastery этот этап не создаёт.
