## Предлагаемое устройство

Один проект содержит переносимую модель на стандартном C++, тесты, интерфейс и описание сборки. Предлагаемые targets: тесты модели, консольный адаптер для headless проверок, настоящее GUI-приложение для Nexus и воспроизводимая внешняя сборка. Предметная логика не дублируется в JavaScript и не зависит от Nexus Account. Различающиеся платформенные адаптеры и зависимости входят в исходники/описание проекта, а не скрываются в приватном коде студии.

Первый кандидат для реального эксперимента — Qt for WebAssembly, собранный CMake и показанный в изолированном Preview Nexus. Это направление, а не принятый и работающий runtime. [Официальная документация Qt](https://doc.qt.io/qt-6/wasm.html) подтверждает браузерный запуск, но требует отдельного Qt/Emscripten toolchain; стандартные поставки Qt не доказывают нужную нам поддержку исключений. Совместимость C++20/EH/RAII, мобильные устройства, размер, доступность, условия распространения и воспроизводимость должны пройти проверку до окончательного выбора. Не переносить поддержку из нынешнего WASI по одному совпадению слова Wasm.

Пользователь остаётся в Nexus: редактирует файлы → нажимает «Собрать и запустить» → видит диагностику и живое приложение рядом с кодом/условием. Одна среда не требует, чтобы абсолютно вся компиляция шла на телефоне. Если выбран встроенный сервер сборки, Nexus обращается к нему сам; установка IDE и переход на сторонний сайт студенту не требуются. Место выполнения, офлайн-возможности, лимиты и стоимость пока не выбраны и не измерены. Сборка Qt непосредственно в браузере также не объявляется готовой.

Учебный GUI нельзя заменить готовой демонстрацией: изменение обработчика в C++ учащегося должно изменить поведение вновь собранного приложения. Отмена/перезапуск не теряют код; Preview старой ревизии не отображается как результат нового запуска. Ошибка сборки не переключает незаметно на интерпретатор, другую программу или предсобранный ответ.

## M6-R0 — следующий технический gate

В изолированной тестовой среде, без production deployment и работ владельца:

1. Закрыть M6-P1-01; не обещать OS threads до фактического target gate. Кооперативные события/отмена остаются самостоятельной темой.
2. Собрать минимальный настоящий C++ GUI-проект с моделью, полем ввода, кнопкой и изменением состояния. Изменить C++ обработчик, пересобрать и увидеть другое поведение. Проверить неверный ввод и события после повторного запуска.
3. Проверить настоящий C++ catch/RAII внутри приложения, правила event loop, Stop/Restart, лимиты памяти/времени/вывода и восстановление после ошибки. Кандидат не проходит при потере M5 EH ради GUI.
4. Запустить те же модель и тесты на native C++20 и browser target. Выгруженный проект собрать из чистого каталога без Nexus-сессии и сравнить результаты. Qt/browser/native адаптеры могут различаться; переносимость не означает идентичный бинарный файл для разных платформ.
5. Проверить изоляцию приложения от аккаунта и родительской страницы, отсутствие произвольного сетевого доступа, очистку только disposable runtime, сохранность проекта и стабильных IDs. Все данные — синтетические.
6. Измерить на desktop и мобильной ширине, затем на реальных устройствах: время сборки/запуска, размер загрузки, память, ввод/клавиатуру/доступность. Пороговые значения утвердить до объявления PASS. Новый runtime загружается по требованию и не увеличивает Home/static graph без отдельного решения NEXUS-PERF-01.

Готовность: реальные source edits → новая сборка → живое GUI внутри тестовой оболочки Nexus; одинаковая модель/тесты на двух targets; все значения и ограничения в evidence. Прототип не равен полноценной интеграции Project Studio, защищённой аттестации или production readiness. Если Qt-кандидат не проходит, выбирать другой переносимый GUI target по тем же критериям; обязательную работу студента во внешней IDE не использовать как обход.

Выбор пока открыт; UI остаётся в Nexus в обоих случаях.

Реальные попытки/оценки и Cloud-синхронизация — отдельный контракт03/02/01 с версионированием и безопасной миграцией; новых записей/схем этим документом не создано. Пользовательские проекты и прогресс сохраняются независимо от будущей системы аттестации.

## Архитектурные границы и evidence

Сборка недоверенных C++/CMake и запуск приложения должны быть изолированы от BFF Identity, секретов и других проектов. Предлагаемый preview — отдельный execution origin/контекст с минимальными правами, ограниченным и проверяемым каналом сообщений, без доступа к cookies/account storage родителя. Произвольные build scripts не запускаются в доверенном backend. Нужны quotas, отмена, изоляция файловой системы и pinning SDK. Эти механизмы ещё не реализованы; запись не разрешает новый deployment, платный тариф или публичную передачу личных работ.

Проверенные сейчас факты M6-0: native34/34, browser core31/31, три граничных случая и P1, cold Offline,56/56 и legacy40/40 preservation. GUI/сдача/portable ZIP остаются PLANNED. Для диплома фиксируются причина решения «всё в Nexus», альтернативы (внешняя IDE отклонена, готовая симуляция не подходит), архитектура до/после, измерения и ограничения каждого gate; образовательные результаты требуют отдельного пилота.
