# ADR 1C-0 — независимые пакеты и изолированный кандидат

Решение от 30.10.2026, статус IMPLEMENTED в feature, приёмка интеграции PARTIAL.

## До и после

До: `onec` уже существует в language registry со статусом planned, aliases `1c,bsl` и файлами `.bsl/.os`; прикладная карточка `1c-enterprise` существует в каталоге. Реализованного курса, BSL provider и shared-материалов 1С нет. Основное приложение имеет приватное хранилище и отдельную SEC-PWA-политику, которые нельзя расширять молча.

После в этой ветке: добавлены два course package в `courses/`, 20 модулей/80 тем, первые 8 уроков RU/EN, shared v1, нативный комплект и отдельный UI кандидата. Основной ESM-граф и existing contracts побайтно прежние. Активные Academy routes остаются будущей интеграцией; карточки сохраняют planned.

## Принятые решения

1. Course ID P = `onec`, A = `1c-enterprise`. Все Module/Topic/Activity ID имеют собственный префикс курса. Общий словарь не означает общего completion. Прогресс и попытки не мигрируют из C++.
2. CP-1.1 применяется без расширения общей схемы. Новые packages — pilot-contract; skill mappings pending-cp3. Skill Graph, Learning Events и Mastery остаются not-implemented. Prerequisite edges в curriculum описывают учебную последовательность, не реализацию общего графового движка.
3. Кандидат использует отдельный локальный store. Это позволяет доказать независимость и копирование до согласования account-private/Cloud Sync adapter. Нельзя объявить его production progress integration.
4. Разрешённый способ P1 execution — официальная локальная платформа. Browser UI не запускает процессы, не знает путь к лицензиям и не отправляет код на сервер. Запуск native gate — отдельное явное локальное действие.
5. Offline реализован переносимым пакетом, без нового service worker, CacheStorage authority или расширения SEC-PWA allowlist. Package содержит оригинальные материалы; обязательная загрузка основного Nexus не увеличивается.
6. Продолжение проекта создаёт новую работу и provenance. ID, содержимое и попытки источника сохраняются; completion не переносится. Настоящая ИБ восстанавливается в новый каталог, а не поверх оригинала.

## Рассмотренные альтернативы

| Альтернатива | Решение и причина |
|---|---|
| Объединить A/P в один курс | Отклонено: разные цели и аттестация, ложный перенос прогресса |
| Скопировать общий глоссарий в каждый урок | Отклонено: два источника истины и дрейф определений |
| Выдать JS-модель или подсветку за BSL execution | Отклонено: неверная семантика и недостоверное evidence |
| Сразу запустить удалённый runner | Отложено: лицензирование, недоверенный код, данные, квоты и security требуют отдельного решения |
| Сразу расширить active Academy/SEC-PWA/private storage | Отложено до 00/02/07/01: существующие contracts защищены поручением |
| Требовать EDT для P1 | Отклонено: проверенный путь через Конфигуратор доступнее и уменьшает prerequisite-нагрузку |

## Security и ограничения

В UI нет eval, установки пакетов или запуска BSL-процессов. Все учебные строки/заметки экранируются. Сохраняется только локальная учебная работа кандидата; аккаунтная авторизация, защищённая аттестация и облачный перенос здесь не обещаются. Отказ хранилища возвращает ошибку, повреждённое сохранение не очищается. Нативный gate создаёт только новый стенд, не читает список пользовательских баз и не собирает активационные сведения. Raw logs и .dt остаются локально, safe report переносится отдельно.

## Есть ли здесь материал для диплома?

Да. До/после образовательной архитектуры, раздельные траектории и общий словарь, критерии доказательств исполнения, negative-control дизайна тестов, восстановление, копирование без перезаписи и граница local/self-report versus защищённая оценка. Измеримые результаты: 80 уникальных Topic ID, 16 локализаций, нативные 3/105/2, отрицательный CheckConfig и браузерные проверки. Ограничения: нет измерения роста знаний, физического mobile LIVE, field p95, независимой педагогической экспертизы и production integration.

Дальнейшее развитие: согласованный adapter основного приложения, тест точной training-сборки, парные проверки OneScript при необходимости, A2/P2, затем отдельная оценка методического эффекта.
