# ADR — личное выполнение 1С и возврат протокола в Studio

Дата31.10.2026. Решение в единственном PR63 по поручению владельца «Продолжаем, доводим до релиза»,с сохранением запрета main/production/merge/официального Release. Архитектурный режим:Очень высокий. IMPLEMENTED;фактические статусы каждого прогона фиксируются отдельно в evidence,не выводятся из наличия кода.

## Контекст и выбранная граница

S5 доказал70+3 эталонные проверки настоящей учебной1С в Windows Sandbox,но допускал только один закреплённый reference. Для ученика нужен изменяемый снимок с происхождением,ограничение выполнения и возвращаемый результат. Браузеру не предоставляется process API,Docker socket,новый localhost HTTP execution listener или writable host mapping. Identity/IAM/OAuth/BFF/Worker/D1,public runtime router и общая схема проекта не меняются.

Studio формирует отдельный request v1:requestId/workId,курс/Topic ID,workspace revision/local revision,ordered file SHA и aggregate snapshot SHA. В нём только переносимые исходники,без owner/ACL/session/progress. Перед экспортом действуют прежние ACL/path checks. В отдельном журнале сохраняется привязка запроса,не дублируется текст исходников. Исходная работа не заменяется. Журнал находится в публично заданном account namespace,отдельно для каждой работы;проверяется тот же объект подтверждённого контекста аккаунта до/после async-операций. IAM allowlist не расширяется;существующая clearVerifiedAccountData удаляет данные по account prefix,включая новый журнал. Отдельный Web Lock координирует его записи. Corruption/quota/history limit приводят к отказу,а не очистке сохранений.

Операторский Node-комплект принимает новый каталог,доверенную собственную сборку и отдельно полученную владельцем официальную учебную поставку8.3.27.1508. Сборка/исходники/spec/media связаны SHA. Подготовка платформы читает только собственный закреплённый reference af19d9d…;код ученика на этом этапе не выполняется. Установщик и платформа не запускаются на host. Подписи/сертификаты MSI/VC/1cv8t и версия проверяются до использования. Право личного экземпляра не превращается в право общего сервера для класса.

Свежая VM имеет4GiB,один readonly input;сеть,vGPU,clipboard,audio/video/printer выключены. Ученик получает отдельный guest-каталог и новую базу;readonly исходник проверяется повторно. Native process создаётся suspended,назначается Win32 Job Object и только затем запускается. Лимиты:512MiB process/1GiB job,4 обычных процесса,CPU rate50%,35с user CPU per job;до45с на отдельный вызов и90с на весь learner workflow. Ошибка создания/назначения ограничителя не разрешает свободный fallback. Kill-on-close завершает обычных потомков. ERROR_NOT_ENOUGH_QUOTA1816/соответствующий NTSTATUS классифицируется RESOURCE_LIMIT,а не обычной ошибкой программы.

Job Object не охватывает все возможные брокерные процессы гостевого администратора. Поэтому внешний host controller имеет110с watchdog после подготовки платформы и всегда останавливает именно UUID,полученный собственным start,включая отказ/отмену. Не завершаются PID клиента/сервера,системные службы или чужие VM. При занятом Sandbox новый запуск отказывает. Неподтверждённая остановка — CLEANUP_FAILED;это не успешное исполнение. При аварийном завершении самого host controller автоматический finally не гарантирован:отдельный host-журнал стадии/UUID помогает восстановлению;полная независимая orphan/recovery изоляция общего сервера не заявлена. Этот runtime предназначен для одного личного учебного пользователя,не допускается как multi-tenant service или удалённая аттестация.

## Возврат результата

Выбран небольшой числовой канал официального CLI:статус native operation и упакованные file index/line/column/kind. Host строит bounded JSON из известного запроса и этих скаляров. Произвольные гостевые файлы,HTML,rawлоги,базы или новые исходники не возвращаются в host. Запись из guest в общую/quarantine папку отвергнута из-за расширения доверенной поверхности,рисков reparse/объёма и передачи недоверенных файлов. Гостевые базы/изменения исчезают при остановке;долговременный источник работы — Studio и сохранённый запрос.

Exit0 означает завершение процесса/проверки конфигурации,не правильность решения или авторство. Если собственный учебный harness сообщает NEXUS_CHECK_FAILED,возвращается LOCAL_TEST_REJECTED с явным обозначением локальной самопроверки. Код ученика может изменять собственные сообщения/тесты;поэтому любой импортированный протокол остаётся недоверенным. Поля outputTrusted/codeVerifiedServer/credentialEligible/automaticGrade/progressWritten строгоfalse. Импорт проверяет request/source/revision binding,mode,platform version,bounds и cleanup status;чужой запрос или повышение trust отвергаются. Дополнительные workspace/ACL/progress/HTML поля игнорируются. Повторный импорт не заменяет первую запись. Новая ревизия источника делает прежний результат историческим;прогресс обоих курсов и предыдущие attempts не переносятся и не очищаются.

## Windows CLI и обнаруженные отказы

wsb.exe находится в зарегистрированном MSIX MicrosoftWindows.WindowsSandbox. Его отдельная PE Authenticode отсутствует:проверка «Valid exe» была неправильной моделью для этой поставки. Используются Store/System registration,точный Microsoft publisher/publisherId,status,отсутствие development/partial staging и SHA каждого64KiB блока wsb.exe по установленному block map. Это цепочка доверия штатной подписанной Windows-поставки,а не разрешение запускать произвольный unsigned executable. Подмена publisher/status/block отрицательными тестами отвергается.

Прямой Node lifecycle первого fresh-прогона завис после создания VM;установочный/learner каталог ещё не появился. Этот прогон не принят. Остаточная VM подтверждена точным nonce её input и штатно остановлена;зависший собственный оператор завершён после проверки PID/родителя/пути запроса. Внутренний механизм packaged-console дескрипторов полностью не доказан. Исправление:вызов CLI через фиксированный штатный Windows PowerShell wrapper с отдельными base64 JSON-данными аргументов,без Invoke-Expression/ExecutionPolicy bypass;результат принимается по exit и полному JSON,без ожидания закрытия GUI-inherited pipes. Невалидный JSON/ненулевой exit/переполнение/отмена дают отказ. Реальный start/stop исправленного controller прошёл отдельно;полный fresh workflow имеет собственный evidence.

## Проверки и ограничения

На настоящей учебной платформе проверены изменяемая работа,compile-only,синтаксический отказ,семантическая самопроверка,попытка записи в readonly source,CPU quota и ожидающий дочерний процесс с wall timeout. Отдельный native QA проверяет memory refusal и уничтожение дерева процесса. Первоначальная неправильная классификация CPU-stop сохранена как failed experiment. Browser tests проверяют регистрацию/импорт/отказ подмены/историческую ревизию/reload/quota и прежний C++ writer;это синтетический аккаунт,не реальная server session. Fresh Studio→native→Studio acceptance и CI привязываются к точным source/build/head SHA отдельно.

WebKit обнаружил гонку теста при hash navigation:старый select заменялся новым lesson render. Исправлено ожидание точного нового course/locale/topic DOM без изменения ожидаемых итогов. Windows WebKit offline emulation блокирует даже пустой file:// HTML;контрольный опыт это отделил от курса. Для него применяется запрет всего HTTP/HTTPS с обязательным отрицательным контролем,с сохранением выключенного учебного сервера и требования0 HTTP запросов. Chromium использует обычный browser-offline. Это лабораторная эмуляция,не физическая приёмка iPhone/Android или fieldp95.

Не проверенные этим этапом forms/СКД/roles/RLS/server concurrency/scheduling/EDT не получают native PASS. Ограничения учебной версии и зависимости полного коммерческого стенда остаются в матрице. Естественный человеческий голос,реальные candidate Account writes,физические устройства и педагогическая эффективность требуют своих доказательств. Public catalog activation/main/production/merge/Release этим ADR не разрешаются.
