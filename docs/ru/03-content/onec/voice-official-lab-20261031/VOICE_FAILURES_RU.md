# Дополнительные отказы голосового цикла

Проверка перед закрытием milestone31.10.2026, тот же PR63.

1. Проблема: browser ASR по30-секундному таймауту выключал захват, но контроллер разговора оставался активным. Гипотеза: timeout отсутствовал в списке terminal capture states. Проверка состояния подтвердила отсутствие; timeout добавлен в существующую обработку отказов. Регрессия проверяет permission-denied,language-unavailable,error,limit,timeout: сеанс не активен и поздняя реплика не принимается. Повторный запуск явный. Лимит времени не увеличен.

2. Проблема: поздний onstart старого browser recognizer вызывал общий stop и мог остановить уже новый recognizer. Гипотеза: обработчик использовал глобальную текущую ссылку вместо собственного экземпляра. Новый сценарий в существующей группе воспроизвёл отказ:3/4 теста PASS, новый экземпляр получил aborted=true. Исправление отменяет только экземпляр r, которому принадлежит запоздавшее событие. После исправления старый onstart не отключает новый сеанс; новая реплика принимается, прежние cancel/logout/dispose проверки сохранены. Итоговый прогон зафиксирован в regression/ONEC_ASSISTANT_UNIT.txt и GitHub CI точного HEAD.

Дополнительный повтор браузерного QA в уже существующий offline output был отклонён OUTPUT_EXISTS. Предыдущий каталог не удалялся; повтор выполнен в новом s3-browser-timeout, все6 групп PASS. Это отказ защиты от перезаписи QA-артефакта, не потеря работы пользователя.

Эти проверки синтетические; они не объявляются приёмкой естественной речи человека или внешнего сервиса браузера.
