# ADR: аддитивный каталог и проверяемая граница выполнения

Решение01.11.2026, только PR63. Контент курсов доступен через динамический импорт, ShadowRoot изолирует его CSS. Существующий standalone/offline renderer используется с переданным root/storage/lifecycle; тяжёлый курс не включается в статический ESM-граф Главной. Существующие catalog fields/IDs сохраняются, кроме точной активации canonical routes. Проверяется ожидаемая трансформация каталога, а не широкое исключение из security gate.

Локальные попытки/финалы привязаны к уже проверенному аккаунту и его существующему namespace. Facade допускает только четыре ключа двух курсов; captured account и active view проверяются перед каждой операцией. Общая очистка/удаление/чужие ключи запрещены, ошибки quota не превращаются в сохранение. Старые автономные байты сохраняются отдельно; автоматическая миграция и облачная синхронизация не заявляются. Альтернативы — общий анонимный прогресс и изменение IAM allowlist — отвергнуты из-за смешения аккаунтов/границ поручения. Реальный Identity end-to-end требует законного review origin.

В расширенном native QA используется новая собственная конфигурация, исходный AF/12-файловый эталон не меняется. Настоящая роль читателя и RLS проверяются отрицательным запросом и записью; проверка администратора после читателя не вызывает seed и не маскирует изменение базы. Настоящая СКД и открытая форма проверяются отдельно от браузерной интерактивной модели. Один последовательный guest session соответствует ограничениям учебной версии. CLI получает только числовой итог; произвольные guest files/логи не переносятся в host. Новый runner не принимает пользовательский путь/код, host guard и Job Object сохранены. Native source/expected cases embedded в собственную сборку; результат не является подписью сервера или credential.

Docker daemon на этом ПК недоступен. Из закреплённого MIT whisper.cpp v1.9.5 собран статический Windows x64 CPU CLI; source/модель/VAD проверяются SHA. Это явная personal-operator альтернатива, не автоматический fallback. Внешние URL/команды не поступают от браузера, curl выключен, stdin/stdout ограничены, отмена завершает собственный дочерний процесс. Альтернатива с облачной передачей не выбрана: нет согласованного провайдера/бюджета. У Windows процесса нет Docker hard-memory/network isolation — это материал для отдельного review, не скрытое равенство механизмов.

Failed experiments: ошибочный корень прав `Configuration` не обеспечивал запуск; правильный root из собственного platform roundtrip — `Configuration.NexusTrainingServiceDeskFull`. Для обычного окна потребовалось право MainWindowModeNormal; административные права читателю не добавлены. Первоначальная проверка guest case IDs отказала на UTF-8 BOM ожидаемого ресурса при фактических76PASS; исправлено только декодирование BOM, все case IDs/числа сохранены. Windows Whisper при stdin выбирал output basename `-`, отключал callback stdout и возвращал пустую строку; fixed basename без output-флагов восстановил stdout без записи файла. Отказ и последующие реальные RU/EN результаты сохранены.

Измерения: native advanced guest 10470мс (уже установленная учебная платформа, не cold-install SLA); статический startup80модулей/635811байтов при неизменных caps80/640000. S6 cold-install E2E553237мс остаётся отдельным измерением. Естественная речь в двух15-секундных окнах не получена; отсутствие расшифровки не выдаётся за успешную приёмку. Fieldp95/педагогическая эффективность/авторство не доказаны.

Первичные источники: [ограничения учебной платформы](https://online.1c.ru/catalog/free/28765768/), [соглашение учебной версии](https://online.1c.ru/admin/documents/agreement.php?ID=16463663), [описание прав платформы](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_8.3.22_Developer_Guide/Appendix_5._Access_rights_description/), [официальный source Whisper v1.9.5](https://github.com/ggml-org/whisper.cpp/tree/v1.9.5). Публичный сервер/чужие конфигурации/реальный учёт не используются; vendor binaries и веса не входят в PR.

## CI follow-up: встроенный курс320px

Первый S7 HEADe548247: три historical content-review SUCCESS, два candidate FAIL после41regression/273unit и54browser PASS. Последний55-й сценарий обнаружил overflow общей оболочки на Linux320px. Внутренний root при интеграции не получал id=app, поэтому существующий адаптивный стиль standalone к нему не применялся. Восстановлен id в отдельном ShadowRoot, без коллизии с внешним app. Ожидаемая ширина не изменена; дополнительно проверяется computed overflow-wrap:anywhere и сохраняется диагностика. Chromium/WebKit по6новых сценариев после исправления PASS. Новый exact-head CI должен подтвердить итог; неуспешные runs/artifact digests сохранены в FAILED_CI_e548247.json. Это UI-дефект, не отказ P4-Q/security gate.
