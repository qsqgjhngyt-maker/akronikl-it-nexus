Точный действующий Cloud revision/image digest ещё требуется прочитать и закрепить: облачный CLI не подтвердил доступ (timeout/auth failure, raw вывод скрыт). Совпадение названия локального образа и live generation не заменяет такой pin. Конфигурация runtime, секретные ссылки, Gateway routes, Worker source/settings и схема должны быть сравнены до любой записи.

Действующие `publication-auth-deploy-guard`, `publication-primary-gate` и прочие security gates не изменялись. Нужны свежие настоящие login receipts по предусмотренному пути публикации; прежний одиночный QA-вход не заменяет проверку трёх способов входа и не превращается в готовый допуск. Публикация остаётся закрытой до выполнения применимых условий.

После подтверждения облачного входа: read-only pin и конкретный guarded rollout/rollback plan, публикация кандидата в существующую инфраструктуру без main/Release, затем настоящий Account/save/F5/reopen, голос и regression на ПК. Физические Android/iPhone владелец проверит после публикации. Только после успешной приёмки — main и официальный Release.

Унаследованные исторические PWA authority records не удаляются и не переносятся на новое поколение без существующего record.
