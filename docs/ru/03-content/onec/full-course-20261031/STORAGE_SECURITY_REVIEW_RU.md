# Сохранность и безопасность полного кандидата

Ранее выявленный S1-R06: общий ProjectStore допускал потерю изменения от другого snapshot; неучаствующий C++/Cloud writer не защищался отдельным lock1С. Исправление внесено в едином PR #63 после объявленного routing 03/05→02/01 в пределах полного поручения владельца.

Новый общий Web Lock привязан к verified account. S1 и C++ редакторы держат lease до закрытия; другая вкладка остаётся read-only. Create/import/controls/Cloud/graphics/offline-import и C++final используют тот же writer. Долгая Cloud операция дополнительно проверяет localRevision: pull не стирает изменения за время ожидания, push не очищает новую очередь. Отдельный encrypted-offline graphics port сохраняет собственную транзакцию и не требует чужой online account DB. Формат DB2, ключи хранения, Topic/Project IDs и ACL не мигрируют в новый namespace.

loadProjectDb стал чистым чтением: повреждённый JSON/корень/соседний объект блокирует запись вместо тихой нормализации с потерей. saveProjectDb проверяет исходный account snapshot и сырую строку до записи; put/patch дополнительно отвергают устаревшую revision редактора. CAS работает вместе с общим lock; сам по себе localStorage CAS не атомарен между несогласованными writers. Именно эту границу проверяет реальный shared localStorage двух вкладок в ephemeral browser context. Учебные account fixtures не являются серверным LIVE.

Финальные тесты имеют отдельные ключи каждого Course ID. Попытки, версии портфолио и версии черновика добавляются без очистки прежних. Перед ожиданием lock форма снимает значения. Даже при quota/повреждении истории можно выгрузить текущий несохранённый черновик; ошибка не считается успехом. Авторский текст экранируется в HTML. Эти данные локальные, не cloud backup, и удаление данных браузера остаётся риском: нужен экспорт.

Для PWA введён строго ограниченный публичный fragment только для manifest-pinned versioned courses/onec-education/index.html. Разрешены два Course ID, locale ru/en, собственный синтаксически ограниченный lesson либо assessment=final. Не разрешены новые ресурсы, приватные ответы, root shell, API, foreign origin, POST, произвольные query/параметры, duplicate keys или иной MIME. Integrity/MIME/private-header checks, worker source и исторический release admission не изменены. Новый SW собран и установлен только в отдельной неопубликованной loopback preview. Корневой production SW не перезаписывался.

Ограничения: старые уже открытые версии не соблюдают новый lock; требуется контролируемый reload после backup. Клиентская ACL/блокировка не защищает от владельца браузера или исполняемого им JS. Физические устройства, real-account LIVE и холодный private Studio/PWA не проверены. Серверные security contracts не менялись. Scope допускает только 31 точно хешированных файлов; иные protected изменения по-прежнему попадают в historical-release review. Release security gates не ослаблялись.
