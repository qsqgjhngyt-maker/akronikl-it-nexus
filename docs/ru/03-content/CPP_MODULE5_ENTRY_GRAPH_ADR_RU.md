# ADR: независимая проверка public SW и версии компилятора

27.10.2026. Принято и реализовано в feature1dd56ca; Account bundles установлены на BFF. Строгий compiler guard сохранён.

Проблема: BFF и frontend публикуются независимо. Равенство RUNTIME_GRAPH_ID делало доступ к Account зависимым от SDK C++. Смена compiler graph при прежнем BFF закрывала повторный вход после logout.

Решение: Account проверяет подтверждённый public protocol, формат graph и окончательную publicReady. Compiler runtime отдельно требует точное равенство digest. Account никогда не выводится из SW status: его доказывает только сервер. Предполагается установленный на каноническом origin собственный проверенный SW. Это не защита от полного компромета этого origin.

Альтернативы: синхронно обновлять frontend/BFF при каждой смене SDK — лишняя связь и повторяемый риск; удалить SW gate — потеря fail-closed проверки публичной политики; разрешить любой graph для compiler — нарушение целостности; требовать от пользователя Shift+F5/очистку — временный обход с риском данных. Они отклонены. Изменение backend sessions/cookies/D1 не требовалось.

Доказательство: точный прежний bundle воспроизводит зависание390/1366; два исправленных варианта SDK проходят эти размеры. Wrong compiler graph всё ещё блокируется. Legacy/malformed/incomplete/protocol controls отвергаются. CI12jobs PASS, live9checks и подтверждение владельца на телефоне/ПК. Изолированная автоматизация использует login stub; реальная церемония подтверждена только ручным сценарием владельца. Скорость сети и эффективность обучения не измерены.

Измерения шапки:54 layouts, локальный390 RU unlocked0.375→138.75px; LinuxCI−6.75→128.78125px. Геометрия шрифта зависит от ОС, поэтому сравнивается допустимый интервал, а не равенство чисел разных систем.

Есть ли здесь материал для диплома? Да: эволюция контракта двух независимо публикуемых компонентов, альтернативы, security assumptions, причинное воспроизведение и ограничения. Материал передать04 с ledger; не заявлять измеренный учебный эффект.

Дальнейшее развитие: добавить этот cross-generation сценарий в общую матрицу01/05 при каждом изменении public SW/SDK; следующая BFF сборка обязана включать исправленный client. Нужна отдельная согласованная frontend generation для шапки; текущую immutable generation не перезаписывать.
