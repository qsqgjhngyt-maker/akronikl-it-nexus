## Версии программы и сохранение завершения

Раньше три точки входа считали все completed записи и делили на 40. Теперь общий cppProgramProgress в уже загружаемом storage.js считает только уникальные ID активного curriculum. У расширенного curriculum обязателен отдельный programVersion. Незарегистрированные ID остаются в state, но не увеличивают завершение активной программы.

Исторический набор cpp-v7 из 40 ID зафиксирован отдельно и используется прежним legacy importer. Его функция переноса сохранена без изменения тела. Состав ID, порядок, legacyIndex и старый quiz не меняются. getCppProgress без аргумента сохраняет прежний формат done/total/pct и считает историческую программу. Общий расчёт для новой версии возвращает также исторический прогресс. Online и Offline используют одну функцию; в представлении новой программы завершённые прежние 40/40 показаны отдельно.

Выбран вычисляемый вид над существующими флагами completed: он не мигрирует и не переписывает пользовательские данные. Завершение старой программы остаётся 40/40 при добавлении новых тем; явное снятие пользователем старой отметки по-прежнему меняет её прогресс. Здесь не создаётся неизменяемый дипломный credential или новая система Mastery.

Замена 40 на 45/60 отвергнута: она переопределила бы старую завершённость и продолжала бы учитывать посторонние записи. Косметическое ограничение процентов до 100 также не исправляет состав программы. Новые учебные ID ещё не назначены; расширенная версия проверяется на синтетическом curriculum.

## Файловый контракт runtime

До исправления request.files участвовал в компиляции, а программа запускалась в пустой файловой системе. Теперь каждый запуск получает отдельную копию файлов своего request в виртуальном WASI. Результат возвращает только созданные или изменённые файлы через outputFiles; состояние следующего запуска определяется новым request. Скрытого глобального файлового хранилища между программами нет.

Используется закреплённый Runno WASI 0.10.0 и его fs/result.fs API, проверенный по сохранённым SHA256 bytes. Формат файлов и custom instantiation описаны в [документации Runno](https://github.com/taybenlor/runno/tree/main/packages/wasi). Это API сверено с фактически закреплённым кодом; переход на текущую версию библиотеки не выполняется. Компиляция остаётся Clang C++20 с прежними flags и диагностикой; исходник и stdout не переписываются.

Пути относительные, до 256 знаков, без traversal, абсолютных путей, Windows drive, управляющих символов и служебных компонентов. Система допускает до 128 файлов, до 512 KiB на файл, до 2 MiB суммарно и до 2 MiB записанных байтов за запуск. Создание каталогов учитывает внутренние markers в квоте; markers не выгружаются как пользовательские файлы. Изменяющие размер WASI вызовы проверяются перед выделением памяти в runner. Выход за квоту получает WASM_FILE_QUOTA и отмечается ограничением среды; следующий корректный запуск должен работать.

UI показывает имена и размеры результатов и позволяет скачать каждый файл. Текстовые UTF-8 результаты сохраняются в рабочую область только явной кнопкой, в Code Studio и Project Studio online/Offline. Весь batch проходит проверку до изменения VFS: код, entry, readOnly, binary и конфликтующие правки не затираются. Сравнение с файлами исходного request обнаруживает правки после запуска. Обновление VFS испускает одно событие, сохраняя active file, исходники и метаданные. Binary можно скачать без перекодирования; в текстовый VFS он автоматически не записывается.

Удаление, перемещение и ссылки не применяются к проекту из результатов исполнения. Runtime не получает пользовательские cookies, Account, Cloud credentials, host filesystem или сетевые adapters. Временная виртуальная запись не означает сохранение в проекте; следующий запуск читает результат только после явного принятия файлов вызывающей стороной или сохранения через UI.
