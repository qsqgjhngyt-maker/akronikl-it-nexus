# Nexus Lesson Standard 1.0

**Статус:** candidate-final после трёх benchmark-уроков C++; становится нормативным после live-smoke и принятия Benchmark 03 в GitHub Pages.

## Цель

Урок Nexus должен не просто передать текст, а провести учащегося по циклу **понять → смоделировать → попробовать → диагностировать → применить → доказать понимание**. Стандарт рассчитан и на пользователя без предварительной подготовки.

## Обязательная структура

1. Практический смысл темы и ожидаемые результаты.
2. Prerequisites с объяснением, что действительно нужно знать до начала.
3. Ключевая модель до деталей.
4. Фундаментальная теория с расшифровкой терминов и сокращений.
5. Интерактивная модель там, где предмет этого требует.
6. Модель выполнения/внутреннего устройства с оговоркой границы между семантикой языка и конкретной реализацией.
7. Построчный или поконструкционный разбор кода.
8. Управляемые эксперименты «изменить → предсказать → проверить → объяснить».
9. Диагностика ошибок: симптом → причина → исправление.
10. Практические задания нескольких уровней.
11. Лабораторная работа с критерием доказательства понимания.
12. Контроль понимания, проверяющий перенос знания, а не только запоминание.
13. Skill Graph: что укреплено и что открывается дальше.
14. Справочник терминов как независимый drawer, не разрывающий поток чтения.
15. Nexus Sandbox для программирования без обязательной внешней IDE.
16. Полноценные RU/EN тела benchmark-уроков; новые языки подключаются через локали без изменения core.

## Три эталона

- `cpp.first-cpp-program` — теория, терминология, toolchain и Sandbox.
- `cpp.pointers-references-addresses` — интерактивная адресная модель и lifetime.
- `cpp.oop-principles` — интерактивная модель class/object/invariant/inheritance/virtual dispatch.

## Правила качества

- Не предполагать знание сокращений: IDE, ABI, OOP, RAII и подобные термины раскрываются при первом существенном использовании.
- Не превращать все темы в одинаковый шаблон: интерактив и примеры должны соответствовать предмету урока.
- Не выдавать распространённую реализацию за требование стандарта языка: например vtable — типичный ABI-механизм, но не обязательная сущность стандарта C++.
- Песочница обязана давать понятный статус, человеческую диагностику и доступ к техническому выводу.
- Внешняя IDE может быть дополнительным инструментом, но не обязательным условием базового прохождения курса.
- Пользовательские уроки не должны ссылаться на старые PDF/legacy-страницы; provenance хранится во внутреннем редакционном слое.

## Freeze rule

После успешного live-smoke Benchmark 03 этот документ получает статус **Normative / Production 1.0**. Дальнейшие изменения структуры урока оформляются как 1.1+ и проходят регрессию на всех трёх эталонах.
