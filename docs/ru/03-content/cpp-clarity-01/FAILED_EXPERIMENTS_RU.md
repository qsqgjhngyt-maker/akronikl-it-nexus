# CPP-CLARITY-01 — отрицательные результаты и решения

1. **Историческая упаковка.** Run `41694195172` отказал с `Source text snapshot exceeds the explicit 100 MiB cap`. Гипотеза: в текущий контентный снимок попали исторические поколения. Подготовительный `77fce50` сузил состав; run `41694561850` был подготовительным успехом. Это не приёмка содержания. В кандидате cap не повышался; текущий текстовый source отделён от старых поколений, бинарных SDK и release receipts.

2. **Локальная браузерная политика.** Вариант стенда с canonical hostname и перенаправлением на loopback получил `ERR_NETWORK_ACCESS_DENIED`. Автоматическая проверка отклонила повтор: наличие production-домена в журнале не позволило считать локальность доказанной; указана опасность чтения/изменения production. Этот вариант не повторялся. Новый стенд использует явный `http://127.0.0.1`, отдельный пустой профиль и созданную тестом зашифрованную копию. Повторный явный loopback-тест разрешён и выполнен. Ни реальный аккаунт, ни профиль владельца не использовались.

3. **Регрессия мобильной ширины.** После открытия исходников Qt-страница при ширине390 дала scrollWidth981. Гипотеза: длинный inline code и старое правило flex для непосредственных div примера. Исправлены сетка примера, перенос inline code и summary; pre сохраняет внутреннюю горизонтальную прокрутку. Повторные реальные Chrome viewport1366/390/320 прошли без расширения страницы. Скриншоты сохранены. Это не физические Android/iPhone.

4. **Каталог лабораторных и budget.** Первый повтор генератора продублировал M6 в основном каталоге:67 вместо55 записей, статический cap46000 был превышен. 5. **Холодное открытие тестовой формы.** В полном локальном прогоне и CI source`e9ca4f6` прошли все155 WASI-наблюдений, затем ожидание `#psNewProject` после перезапуска завершилось таймаутом. В локальном диагностическом профиле `fill` и посимвольный ввод не удержали значение поля; окончательная причина этого поведения не установлена. Задание известной синтетической фразы через DOM и штатный submit позволило открыть ту же зашифрованную копию. Принято: отдельно проверять cold storage/runtime с явной DOM-подготовкой фикстуры; не объявлять это ручной приёмкой ввода фразы. Полный повтор, независимый cold-тест и реальное исполнение сохранённого кода без сети прошли. Продуктовый vault и криптография не менялись.

Старое поведение отдельно не объявляется воспроизведённым LIVE-дефектом. Выбрана короткая атомарная операция: во время сохранения кнопки отключены и cancel предотвращается; до начала операции обычная отмена доступна. Диалог получил доступное имя. Тест задержанной записи наблюдает предотвращение cancel, правильный backup, дальнейшую замену, quota и lock. Дополнительного writer нет.
