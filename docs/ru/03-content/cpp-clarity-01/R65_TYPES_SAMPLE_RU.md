# R65 — первый авторский образец «Типы данных»

Дата: 06.11.2026. Область предъявления — только `cpp.data-types`, RU и EN. Это калибровка перед остальными темами первого блока, не выпуск всех курсов.

## Исходная точка и решение MASTER

Проверены локальная ветка, origin, main и открытый Draft PR #65: HEAD `8b386e1f90bbe6bac5bf00677b223b36eb8e5fed`, base `ee2787c0cd92da2ad1d5e79df5e2bfadab2c3dd6`. Новых исправлений относительно рассмотренного MASTER кандидата не было. Решение CHANGES REQUESTED / production BLOCKED остаётся в силе. Прежний отчёт о 151 теме описывал интеграцию экрана, но не доказывал достаточное учебное покрытие. Это ограничение подтверждено и исправляется по темам.

Воспроизведён R65-09: `tools/build-cpp-clarity-courses.mjs` при наличии `g.clarity` заменял `g.sections` коротким `clarity.model`. В конечном `cpp.data-types` не было полноценного обязательного объяснения инициализации, auto, размеров и свойств numeric_limits.

## Авторский источник и границы изменения

Обе редакции находятся в `courses/cpp/gold/basics/data-types.{ru,en}.json`, поле `teachingEdition`. Прежние цели, теория, лабораторные и практикум сохранены для сопоставления. Генератор явно допускает эту редакцию только для `cpp.data-types`; конечные записи — `courses/clarity/lessons/cpp.data-types.{ru,en}.json`. Новая редакция `types-author-v1` не считает прежние проверенные ответы ответами на новое условие. Прежние значения, проекты и история не удаляются.

Содержательные файлы остальных 300 редакций и три принятых образца проверяются побайтно относительно `8b386e1`. Общий renderer получил условное подключение авторской подачи, диалог возврата к правилу и исправление склейки feedback. Исправление feedback касается выбора пояснения и в прежних темах; поэтому необходима регрессия всего общего экрана. Генератор, renderer и индекс помощника не объявляются изолированным production-релизом одной темы.

## Дизайн и обратная связь

Предсказание предшествует открытию таблицы. Шаг деления выделен подписью типа и фоном, поэтому смысл не зависит только от цвета. Результат хранения 15.0 отделён от форматирования stdout: программа явно печатает одну цифру после точки. Пример и его stdout находятся рядом. В самостоятельной работе другие исходные числа и отдельный буфер.

«Вспомнить теорию» открывает правило и учительский пример, не решение мастерской. Закрытие возвращает фокус, выделение и прокрутку к ответу/редактору. Для длинного урока есть оглавление смысловых шагов. Необязательное чтение доступно внутри темы и из её навигации.

Выявлена дополнительная ошибка renderer: массив индивидуальных пояснений добавлялся целиком после выбранного пояснения. Исправлено разделение массива и общего текста; проверяется неверный ответ, конкретная причина и повторная правильная попытка.

## Первый блок и весь объём

Каталог: 67 C++ + 52 программирование 1С + 32 прикладная 1С = 151 каноническая тема / 302 редакции. Машиночитаемый реестр — `R65_TOPIC_REGISTER.json`. В этой итерации редактируется только cpp.data-types.

Первый блок из 10 тем, в порядке учебного прохождения: cpp.first-cpp-program, cpp.comments-constants-literals, cpp.data-types, cpp.variables-scope, cpp.expressions-operators-blocks, cpp.arithmetic-assignment, cpp.type-conversions, cpp.relations-logic, cpp.pointers-references-addresses, cpp.standard-io. Редакторская калибровка начинается с «Типов данных», как поручено владельцем; прежний порядок курса и ссылки не переставляются. В этот блок входят четыре обязательных образца повторной приёмки. Сложная тема onec.p7.topic-2 отмечена для отдельного блока запросов 1С; её принятый текст нельзя менять без отдельной ревизии.

## Доказательства и границы

`cpp-clarity-types-content.test.mjs` проверяет полный перенос авторского источника, наличие обязательных разделов, одинаковый смысл ключей RU/EN, сохранность прежнего ответа и повторную сборку всех 302 ресурсов с побайтным сравнением 300 соседних редакций.

`cpp-clarity-types-browser.mjs` проходит обычный offline-маршрут Академии в отдельной синтетической зашифрованной копии, обе локали, desktop и мобильные размеры, прогноз, неправильный/правильный ответы, возврат из диалога, курсор, соседнюю тему, настоящий runner и холодный offline. Снимки до/после должны сравниваться на одной ширине и в одной оболочке. Текущий локальный просмотр содержит только искусственную учебную копию; серверный Account и личные данные владельца не подключаются.

Состояния испытаний сохраняются в evidence и привязываются к точному SHA после фиксации. Эмуляция не является физическим Android/iPhone. Реальный Account/login, Qt и учебная 1С для этого образца NOT RUN. Реальный ответ учащегося и наблюдение за пониманием NOT RUN — их нельзя заменить тестами или авторской вычиткой.

До первого выпуска остаются согласование последовательных релизов одной Work-сессии, проверка версии вне блока после обновления установленной PWA и цикл обновление → работа → rollback → чтение → повторное обновление на фактически развёрнутой базе. PR #65 можно слить только один раз. Предлагаемый порядок: нынешний PR остаётся preview до решения MASTER; для первого выпуска потребуется доказанный ограниченный состав, последующие изменения — последовательными PR той же Work-сессии после проверки опубликованного блока. Новые ветки сейчас не создаются. Это предложение, не разрешение выпуска.
