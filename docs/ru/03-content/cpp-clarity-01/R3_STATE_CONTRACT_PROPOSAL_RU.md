# R3 — предложение сохранения для согласования 01/02

STATUS: PROPOSED, NOT IMPLEMENTED. Изолированный экран использует только Map в памяти. Его переходы проверены; F5/закрытие не сохраняют черновик. В приложение не добавлены новый ключ localStorage/IndexedDB, событие обучения, endpoint, обход Account или новый механизм шифрования.

Текущее основание: `core/view-resume.js` уже хранит маршрут и позицию в accountSessionStorage; `core/learning-views.js` ведёт code/stdin/workspace/activeFile/quiz через существующий storage adapter; final-assessment имеет собственный специализированный draft, который нельзя молча использовать для обычного урока. Публичный пример — контент, собственный код и ответы — приватное состояние.

Предлагаемое поведение пилота:

- Одна текущая работа привязана к прежнему canonical topic ID и существующему workspace/project. Переключение языка и этапа не создаёт нового проекта и не заменяет editor buffer. Полная копия примера открывается отдельно; явная замена использует прежний защитный механизм копии/backup и подтверждённый save, включая unsaved buffer и stdin.
- Позиции: route + stage + anchor/scroll, через прежний view-resume adapter. Не общий ключ браузера на всех пользователей.
- Черновик ответа: question ID + content revision + value + статус draft/checked. Checked означает только локальную самопроверку по конкретной редакции, не mastery/attempt/completion. Новый текст вопроса не должен наследовать старую положительную проверку.
- Результат: существующие project/file/entryFile/stdin и идентификатор версии/хеш source+input. После правки результат помечается устаревшим. Не менять смысл прежних attempts, не переносить старый PASS на новую версию. Ручное наблюдение BSL помечается self-report и не становится серверной верификацией.
- Собственный код и ответы сохраняются только через действующий приватный adapter и действующую границу local encrypted copy/Account. Блокировка аккаунта/копии блокирует доступ к черновику; смена пользователя не смешивает работы. Без нового server sync endpoint и без вывода кода в telemetry/evidence.

Решения для 01/02 перед внедрением: допустимое место draft fields в существующем versioned state, лимиты и политика сохранения; revision invalidation; правила quota/lock/failed save; snapshot результата против размера; момент flush перед сменой route; как показывать неподтверждённый save. Не предлагать потерю буфера как допустимый успех. Документ не даёт оснований объявить контракт согласованным.

Обязательные будущие gates: раздел/язык/сосед/возврат, активный файл/cursor/stdin/result version, refresh, закрытие/reopen, cold offline, quota/lock, два пользователя, старая attempt/progress без изменений. До них STATE PRESERVATION всего пилота — PARTIAL. Содержательное review 03/07 можно провести на демонстрационном режиме без записи приватных данных.
