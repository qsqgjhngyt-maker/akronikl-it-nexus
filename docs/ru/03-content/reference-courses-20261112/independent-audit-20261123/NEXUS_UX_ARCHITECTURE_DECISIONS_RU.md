# Архитектурные решения по UX и обучению

## Принятые решения P0

| Решение | Вариант, который проверили | Почему выбран текущий вариант |
|---|---|---|
| Общее представление C++ | Загрузить полный курс на Главной или прописать число 67 | Главная уже загружает лёгкий outline текущего curriculum. Тот же счётчик принимает полный curriculum и лёгкий outline. Не добавляется запрос тел уроков, legacy-путь и сохранённые данные остаются доступными |
| Эталон в самопроверке | Изменить JSON утверждённых эталонов или убрать вариант с последующим сдвигом индексов | Уточнение текста неверного утверждения в рендерере сохраняет ключи, индексы, правильный вариант и байты эталонов. Отдельная кнопка открывает существующее решение в диалоге на текущем этапе |
| Каталог | Отображать номера видимых карточек с перенумерацией при каждом фильтре | Позиция технической записи нужна каталогизации. Снятие декоративного индекса сохраняет фильтры и маршрут без меняющихся номеров |
| Отзывы | Убрать одиночную запись на сервере или классифицировать смысл автоматически по длине | В автоматической витрине требуется минимум три доступных опубликованных отзыва. Главная использует существующую ручную подборку. Отдельная страница отзывов, модерация и расчёт агрегатов остаются доступными. Проверка содержательности выполняется модератором |
| Сохранение | Подменить модель статусов или переиспользовать одно сообщение для всех случаев | Происхождение восстановления и частичной записи подписано в том же renderer. Ожидание, ошибки, конфликт, повтор и выгрузка сохраняют реальные признаки записи. Облачные подтверждения относятся к существующему отдельному контуру |

Совместимость опирается на существующие module boundaries. Code Studio, попытки, проектный writer, Identity, Cloud Sync, Worker, D1, PWA-обработчик и статические опубликованные поколения сохраняют свои версии. P0 меняет локальный кандидат. Для возврата к предыдущему варианту достаточно выбрать существующий релиз C11 для сравнения. Если позднее будет одобрено переключение, рабочий образ C11 и исторический C10 закреплены отдельно. Детальная операция восстановления потребует отдельного разрешения.

## Предлагаемый контракт Карты навыков

Статус **PLANNED**. Основание — [черновик контракта графа](../../../03-data/SKILL_GRAPH_DATA_CONTRACT_DRAFT.md) и [стандарт оценки](../../ASSESSMENT_STANDARD.md).

- **Skill** — стабильный `id`, предмет `domain`, названия RU/EN и версия описания. Пример предлагаемого ID `skill-cpp-algorithm-contract` требует проверки на коллизию с реестром. Перевод названия не меняет ID.
- **Prerequisite** — пара `fromSkillId` → `toSkillId` с версией графа. Для обязательных требований требуется ацикличность. Уровень доступа к уроку сохраняет прежнюю модель, ребро даёт учебную рекомендацию.
- **UnitSkill** — `skillId`, текущие `courseId/topicId`, `contentRevision`, роль связи `introduces/practises/assesses`. Для «Алгоритмизации» связать договор входа и выхода с `cpp.algorithm-definition-properties`, трассировку с `cpp.pseudocode-euclidean-algorithm`, граничные случаи с `cpp.flowcharts`, декомпозицию с `cpp.top-down-design`. Договор входа и выхода предшествует трассировке, трассировка помогает проверять границу.
- **Evidence** — локальная ссылка на принятую попытку или проверенный запуск с типом, ревизией и результатом. Завершение темы позволяет показать факт прохождения. Для подтверждённого владения согласовать отдельную рубрику и набор доказательств, например корректный прогноз плюс перенос на новом входе. Доступ к сохранённому коду для работы карты не требуется.
- **Projection** — у навыка отдельные признаки доступности и состояния обучения. Пустые данные подписываются явно, устаревший revision отображается как более раннее доказательство. Перевод, открытие эталона, повторение и время сами по себе не изменяют подтверждение.

Предпочтительный MVP — статический проверяемый каталог и локальная read-only проекция. Альтернативы с новой базой и централизованной оценкой откладываются до появления измеримой необходимости и отдельного решения Identity. Для 1С использовать самостоятельные domain и ID, связав общие понятия отношением `related`. Подтверждение в другом языке остаётся самостоятельным. В 1С native-наблюдение или самоотчёт хранят собственный тип evidence.

**LIVE-приёмка пилота** требует ручного прохождения реальными тестировщиками в чистой и частично пройденной учебных копиях, в RU/EN и на физических мобильных устройствах. Участник показывает prerequisite, находит урок, объясняет два разных состояния и возвращается к прежней работе. Отдельно проверить, что открытие эталона, перенос данных и отсутствие подтверждённого результата сохраняют корректный статус.

## Предлагаемый контракт Learning Analytics

Статус **PLANNED**, нужен отдельный review 00, Content и Identity. Образовательное действие приложения и добровольная исследовательская телеметрия остаются отдельными контурами. Перед экспериментом участник выбирает явное согласие, видит цели, виды событий, срок, условия удаления и может отказаться с сохранением доступности обучения.

Проект минимальной записи включает версию схемы, тип события, courseId/topicId/stepId, вариант сценария, грубый интервал длительности, результат выбранной проверки и случайный ID исследования. События рассматриваются для начала и завершения этапа, числа попыток, подсказки, открытия эталона, подтверждённой ошибки и добровольного feedback. Публичные отзывы, произвольный текст, исходники и содержимое проектов исключаются. Для добровольного текстового сообщения нужен отдельный предпросмотр и решение об отправке. IP, email, токены, browser fingerprint и технические ID аккаунта в payload не нужны.

Проект срока — до 30 дней для сырых событий пилота. После этого удалять записи либо хранить утверждённые агрегаты с отдельным сроком и порогом малых групп. Видимость ограничивается ролью исследования и аудитом доступа. Отзыв согласия прекращает сбор и запускает удаление подлежащих удалению записей по идентификатору участника. Вывоз данных, соединение с другими таблицами, точные сроки и условия исследования требуют назначения ответственного и утверждения владельца. Вывод об эффективности возможен после независимого сценария с отсроченным заданием, а число переходов служит только сигналом для изучения.
