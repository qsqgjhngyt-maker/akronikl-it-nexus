# Эталонные маршруты: совместимость и границы

Дата: 12.11.2026. Статус: принято для непубликованного кандидата по единому поручению владельца.

## Исходная точка

PR #65 открыт, Draft, не merged. Локальная и удалённая ветка `feature/cpp-clarity-01-m1-m2-20261104` указывают на `9a01de88dac94729b0bb232fb18bd6de49e7507d`. Main: `ee2787c0cd92da2ad1d5e79df5e2bfadab2c3dd6`. Рабочее дерево перед началом чистое. Исторический опубликованный composite и его rollback сохраняются; этот кандидат не предназначен для слепой замены production.

## Решение

1. Сохранить существующий R3 renderer и три этапа. Заменить содержание ровно десяти существующих ID. «Старт с нуля» — дополнительный порядок переходов, без перенумерации каталога.
2. Объединить подключение контекстной справки в renderer. Адаптер различает объекты терминов C++ и строковые ID 1С. Использовать существующие словари; базовый справочник синтаксиса дополнить отдельными карточками с источниками. Полные карточки загружать по запросу. Аннотация только текстовых узлов учебного материала, вне редактора, интерактивных элементов и копируемого кода.
3. Исправить область действия стилей статических `pre`, исключив слои редактора. Одинаковые метрики ввода и подсветки задаёт редактор; искусственных поправок координат курсора нет.
4. Результат проверки C++ — отдельное наблюдение текущего снимка, без новой модели Mastery и без выдачи зачёта за stdout. Проверять исполняемый код штатным runtime. Изменение кода/ввода делает результат устаревшим. Сохранение, запуск, проверка и освоение различаются.
5. Содержание остаётся рядом с материалом при достаточной ширине; на узком экране используется раскрываемая панель. Заметные переходы между подтемами, этапами и уроками имеют разные подписи.
6. Повторяемый пропускаемый тур хранит только своё состояние через действующий механизм preferences. Он не меняет учебный прогресс или код.

## Альтернативы

Полная замена редактора отвергнута: причина дефекта локализуется в CSS, замена расширила бы runtime/сохранение контракт. Отдельные демонстрационные HTML-уроки отвергнуты: review должен проверять тот же renderer. Массовая перепись 151 темы отвергнута: сначала педагогическая проверка десяти эталонов. Автоматический BSL runtime в браузере не создаётся.

## Карта изменений и регрессия

- `courses/clarity/lessons/` и `courses/cpp-clarity-r3/lessons/`: 20 редакций десяти ID; версии содержания и реестр вопросов согласуются.
- `core/cpp-clarity-r3-renderer.mjs`, новые модули справки/маршрутов/feedback и `core/cpp-clarity-authored.mjs`: общие функции всех 151 тем.
- `courses/onec-education/candidate.mjs`: исключение повторного старого glossary только на R3, прежний renderer сохраняется.
- `courses/reference/`: локальные RU/EN карточки и индексы. Никаких сторонних изображений или сетевой зависимости урока.
- Проверки: 20 редакций, неэталонные темы трёх курсов, положительные/отрицательные решения, редактор до/после, ширины/масштаб, фокус, сохранность, offline/private-deny, реальный ESM boot, действующий classifier и FULL. Старые pins изменять только с точной причиной и отрицательным контролем.

## Security, сохранность и откат

Identity/IAM, backend, рабочие базы, Cloud Sync, runtime API, лимиты PWA не меняются. Учебная 1С использует отдельные синтетические базы. Старые попытки, проекты, код и прогресс сохраняются; новая редакция не получает старую оценку автоматически. Статус reviewer не пишется в прогресс. Откат кандидата — отдельный обратный коммит разрешённых файлов; production не переключается.

## Доказательства и диплом

Технические проверки не доказывают обучение новичков. Внутреннее прохождение фиксируется как редакторский review; реальные участники и физические телефоны отдельно. Материал для диплома: регрессия CSS, адаптация справочных форматов, совместимость версий содержания, наблюдаемый результат вместо ложного зачёта. Независимый эксперимент ещё не проведён.
