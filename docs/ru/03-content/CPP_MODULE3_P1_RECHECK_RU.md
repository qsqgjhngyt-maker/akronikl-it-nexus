## Исправленный прогресс

Для расширенного curriculum обязателен отдельный programVersion; исторические 40 ID cpp-v7 зафиксированы отдельно. Online и Offline используют одинаковый расчёт, представление выводит текущий total вместо литерала 40.

В синтетической новой программе проверены 40/45 и 89% при сохранённых исторических 40/40 и 100%; после выполнения пяти новых тем — 45/45 и 100%. Прежнее завершение показано отдельной строкой RU/EN. Добавление неизвестных ID к старой программе оставляет 40/40; сами записи не удаляются. Пустой/частичный профиль, импорт всех legacy индексов, личные code/stdin/quiz/VFS, неизвестные поля и Offline-конфликты прошли девять групп API-проверок.

Расчёт читает существующие данные без миграции и перезаписи. Завершение старого состава программы сохраняется при расширении; явное снятие старой отметки пользователем по-прежнему меняет его прогресс. Новые учебные ID в реальном curriculum ещё не назначены.

## Исправленный файловый обмен

Каждый C++ запуск получает отдельную виртуальную копию файлов request. Созданные или изменённые файлы возвращаются через outputFiles; следующий запуск получает их только через новый request. Запись программы сама не перезаписывает проект. UI показывает результат, скачивает отдельные файлы и сохраняет текстовые файлы явной кнопкой.

Реально проверены входной data/records.txt, запись/чтение внутри запуска, возврат report.txt и повторное чтение после сохранения. Code Studio урока и Project Studio прошли эти действия online и в холодном Offline, включая полное закрытие браузера. Код, quiz, отметка завершения, заметка, личный header и checkpoint сохранились. Правка файла, который должен принять результат, после запуска блокирует весь batch. Исходники, readOnly и binary не записываются через текстовое применение результата.

Без явной передачи предыдущий результат следующему запуску недоступен. Настоящие WASI проверки подтвердили изоляцию, traversal denial, создание каталога без выгрузки внутренних markers, binary bytes `[0,255,1]`, лимиты числа/размера файлов и корректный запуск после quota error. Дополнительно локально выполнено настоящее скачивание текстового и binary файла через UI; бинарные байты сохранились, binary не попал в текстовый VFS.

Контракт ограничен относительными путями до 256 знаков, 128 файлами, 512 KiB на файл, 2 MiB суммарно и 2 MiB записанных байтов за запуск. Проверки потенциальных allocations выполняются перед вызовом runner. Переименование, ссылки и удаление файлов проекта из результатов не применяются. [Решение и альтернативы](CPP_MODULE3_P1_DESIGN_RU.md) описывают границы контрактов; compiler/runtime версии и flags сохранены.
