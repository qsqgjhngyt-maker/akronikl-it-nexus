# Материал для ВКР по CP-NEXT-01

## Организация разработки

Исходная точка — подтверждённый после C12 Git HEAD `a944f7221f76622a1d6bb41f5159e0f1cfa3a614`. Для разработки курсов уже существовали восемь областей ответственности, отражённых в документах и пользовательских чатах. Историю приходилось собирать вручную. Изменение урока могло одновременно затронуть переключение этапов, проверку программы и сохранение. Для такого изменения важны общий SHA, явные границы записи и проверка другим исполнителем.

Теперь описания специалистов хранятся в восьми TOML-профилях Codex. Общие инструкции и индекс источников версионируются в том же репозитории. Главный Codex определяет объём, сверяет спорные выводы и интегрирует файлы. Локальные проекты, ответы учащихся и учётные данные исключены из инструкций и рабочего журнала.

| Решение | Рассмотренный вариант | Основание |
|---|---|---|
| Профили рядом с кодом | Отдельный внешний оркестратор | Штатные механизмы запуска и обозримый объём конфигурации |
| Главный интегратор, раздельные пути записи, QA чтением | Параллельное редактирование общей оболочки и учебных данных | Воспроизводимость диффа, отсутствие конфликтующих решений о совместимости |
| Индекс SHA и документов | Пересылка полной истории чатов каждому специалисту | Достаточный контекст и меньший риск лишнего раскрытия данных |

В Work-сессии роль передавалась при штатном запуске подзадачи. Проверка формата профиля и запуск подагента с заданной ролью фиксируются как два разных результата. Сравнительного опыта с одинаковым заданием одному и нескольким исполнителям не было. Ускорение либо рост качества по этому этапу количественно не установлены.

## Расширение Академии на C17

В C12 в браузерном компиляторе уже была ветка C с `clang -std=c17`. Code Studio и Runtime Router умели передать `languageId: 'c'`. Учебное представление прежних курсов совмещало C++ и внешний сценарий 1С. Карточки доступного курса C ещё не было.

В кандидате `courses/catalog.json` открывает `#course=c`. Отдельный просмотр читает manifest, доступные ID и программу из `courses/c/`. JSON конкретного урока загружается по ID и локали. Схема урока ведёт от объяснения и прогноза через обоснование ответа к новому заданию. Рядом с примером показаны его вход и выход, после задания — критерии и раскрываемый эталон. Эталон отображается как текст. Его открытие оставляет рабочую копию в редакторе.

Практика использует Code Studio, `main.c`, Runtime Router, существующий провайдер `wasm-cpp` и цепочку Clang → WASI → stdout/stderr/код завершения. Наблюдаемый вывод пригоден для проверки конкретного случая. Отметка изучения — отдельное явное действие учащегося. Для подтверждения навыка нужны объяснение результата и перенос на новую задачу.

Для черновиков C в браузере используется новое пространство ключей проверенного аккаунта. Переход после ошибки записи останавливается. Старые ключи, ID, форматы и сервисные маршруты сохранены. При холодном автономном открытии действует существующий проверяемый публичный кэш. Частная автономная копия C и её синхронизация остаются отдельной предметной задачей.

Рассмотрено расширение интерфейса прежних тем условными ветками C. Выбран отдельный ленивый маршрут C с переиспользованием оболочки, редактора и среды выполнения. Ядро остаётся общим, а редактура 151 темы и критический граф загрузки Главной независимы от нового материала. Добавление следующего языка потребует собственных учебных контрактов, среды, примеров и критериев.

Для экспериментальной части нужны воспроизводимые разборы положительных, граничных и отрицательных случаев, сценарий восстановления черновика и проверка интерфейса на малой ширине. Внешнюю методическую оценку следует получить от начинающих и профильного специалиста. Техническое поведение проверяют запуски и скриншоты. Учебный эффект требует отдельного наблюдения.
