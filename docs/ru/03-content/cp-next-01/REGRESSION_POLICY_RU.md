## Проверка текущего кандидата

Новый сценарий «Академия — регрессия расширения» имеет собственный результат. Исторические результаты GitHub остаются видны. Их правила, закреплённые хэши, исходные проверки и публикационные решения сохраняются байт-в-байт от C12. Сценарий R1 использует только чтение GitHub и не хранит секреты выпуска.

1. Сверяет физически проверяемое дерево с точным SHA PR. Проверяет происхождение от C12 и принятого C17. Отсекает неподтверждённую смену базы, новые неизвестные пути, удаление, переименование, ссылки и смену режима файла. Список допустимых путей точен для R1.
2. Проверяет байты материалов трёх курсов, данные и контракты аккаунтов, согласованные части runtime, Code Studio, PWA и документы выпуска. Для текущего SHA разрешены CI, адресные тесты и этот документ. Продуктовые байты совпадают с принятым кандидатом C17. Согласованные изменения первого этапа в редакторе C и восстановлении работы wasm-провайдера входят в этот принятый снимок.
3. Повторяет прежние Preservation и семь отрицательных контролей 1С на отдельном точном checkout C12. На кандидате дополнительно проверяет, что старая ветка допуска отклонена и что текущий gate отвергает запрещённый CSS, приватное хранилище, runtime, уроки и неизвестный workflow.
4. Выполняет обычные учебные и защитные проверки на точном SHA кандидата. Использует исходные контракты 151 темы и 302 редакций, лимиты запуска, синтетические аккаунты, восстановление редактора и offline, native C++20, браузерные проверки прежних уроков RU/EN и десяти эталонов. Прикладные и технические данные проходят по действующим маршрутам тестовой сборки.

При добавлении следующего крупного учебного этапа его утверждённая база, допустимые файлы, новый runtime и проверки описываются явно. Новые права для неизвестных файлов не возникают автоматически. Успешный тест регрессии сам по себе не предоставляет допуска к merge, Deployment или Release.

## Границы доказательств

Используются браузерная эмуляция, локальные компиляторы и синтетические аккаунты. Физическая мобильная приёмка, запуск фактического клиента 1С в браузерных сценариях и понимание материала учениками фиксируются отдельно. При сбое сборки, сети или исполнения сценарий завершается ошибкой. Логи, точные SHA и снимки прикладываются к результату CI.
