# ADR-0023 — полный Gold Module 2 поверх стабильных учебных объектов

Дата: 24.10.2026. Решение реализовано только в feature. Предыдущий runtime baseline — 1be795e; опубликованный main — d9249b2. Публикация и релиз не входят в решение.

Проблема: 12 существующих тем второго модуля нуждаются в полной RU/EN переработке. Изменять старые IDs, порядки quiz, сохранённые файлы или базовые данные ради нового материала нельзя. Каталог M1 и moduleId-проверка прежде допускали только алгоритмы.

Решение: 24 новых фиксированных JSON в basics, прежний M1-export и его 16 объектов сохранены. Catalog возвращает ожидаемый moduleId из точного набора; registry сравнивает его с ответом. Offline-public reader расширен на точные 40 путей двух модулей; произвольный Gold URL, query/hash и чужой origin запрещены. Данные и presentation по-прежнему lazy; app/offline-entry, Identity, Cloud, storage, compiler и Worker не меняются.

В academy-gold-1.1 добавлены необязательные, не сохраняемые в learner state поля: readinessCheck, blockPracticum, visualization.title/description, diagnosticExamples, outputNote/verification и проверочные варианты исходника. Старые объекты их не требуют. Вопросы readiness и assessment имеют раздельные DOM-группы. Практикум C и итоговый проект могут показываться одновременно. Все строки и код экранируются; sourceRefs отображаются только через заранее заданный список первичных ссылок.

Альтернативы: переписать legacy data — отклонено из-за связи с прогрессом; новые учебные IDs — отклонено из-за дублирования обучения; универсальный произвольный JSON-loader — отклонён из-за расширения public authority; динамический «интерпретатор типов C++» — отложен, потому фиксированные текстовые трассы и настоящий компилятор объясняют текущие задачи без ложной модели исполнения.

Проверка размеров типа использует свойства и отношения. Точный stdout образца Clang/WASM помечен как target-specific; host long/pointer могут отличаться. Отрицательные программы должны реально завершаться compile-диагностикой. Зарезервированные имена без обязательной диагностики не используются как compile-error ожидания. Опасные UB-конструкции не выполняются.

Security implications: новых credential/session/config данных нет, private cache authority не расширена, API mutations не добавлены. QA использует отдельные синтетические профили и шифрованный тестовый vault. Изменений production/main нет. Возможный откат feature — возврат только перечисленных контентных и четырёх интеграционных файлов к 1be795e; прежнее исправление выбора runtime сохраняется. Миграции пользовательских данных для такого отката не нужны. Если публикация будет отдельно разрешена, новый сборочный rollback и production gate потребуются заново.

Доказательства: отдельный M2 Content Gate, real g++/UBSan и real Clang/WASM, холодный Offline, 24 RU/EN проекции, состояние двенадцати уроков и синтетический проект, M1/runtime regression. Статусы берутся из фактических артефактов. ADR не является доказательством успешного прогона или эффективности обучения.
