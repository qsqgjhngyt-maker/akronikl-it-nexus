# Requirements Baseline — v0.1.7-alpha.2.3

**Нормативный язык:** русский.  
**Runtime baseline:** `v0.1.7-alpha.2.2.1`.  
**Статус:** WORK02 COMPLETE.  
**Дата:** 2026-09-25.

## Назначение

Этот baseline переводит требования Nexus из раннего Foundation-списка в управляемый каталог полного жизненного цикла. Требования основаны на фактическом состоянии `v0.1.7-alpha.2.2.1`, подтверждённых LIVE-тестах Cloud Sync и согласованном целевом направлении: Identity, Cloud Profile, Skill Graph, Control Center/CMS, Support и исследовательская AI-подсистема.

## Классы идентификаторов

- `FR-*` — функциональные требования продукта.
- `NFR-*` — нефункциональные требования.
- `SEC-*` — требования безопасности/приватности.
- `AIR-*` — исследовательские требования AI/диплома.
- `UC-*` — use cases.
- `US-*` — user stories.
- `AC-*` — acceptance criteria.

## Статусы

- `IMPLEMENTED` — подтверждено текущим кодом/тестом/LIVE evidence.
- `FOUNDATION` — архитектурная/кодовая основа присутствует, пользовательский сценарий неполон.
- `PLANNED` — согласовано как целевая функция, реализация ещё не начата.
- `RESEARCH` — требуется исследование/эксперимент до окончательного design decision.
- `DEPRECATED` — больше не является целевым состоянием.

## Приоритет

- `P0` — архитектурно/эксплуатационно критично.
- `P1` — значимо для основной продуктовой траектории.
- `P2` — расширение после основных контуров.

## Правило baseline

Новые крупные функции не принимаются в разработку без requirement ID, acceptance criteria и планируемого способа verification. Архитектурно значимые требования должны иметь связь с ADR/diagram/API/data model. AI-функции дополнительно требуют research question, baseline и evaluation plan.
