# ADR-AK0-004 — раздельная приёмка Account и приватной локальной копии

Дата: 26.10.2026. Статус: принято для тестового кандидата ветки 08; production не опубликован.

## Контекст

Холодный публичный офлайн Gate B1 не доказывает сохранность приватных проектов. Локальная фраза не является серверной сессией. Подмена этих двух видов доступа дала бы ложное доказательство авторизации. Кроме того, сохранение view-state редактора может происходить одновременно с чтением контекста помощником.

## Решение

Разделить доказательства на три независимых контура: реальные модули Account/bootstrap/assistant с синтетическими зависимостями; настоящий собранный offline UI с encrypted vault и синтетическими копиями; обновление/откат настоящих SW с byte-exact историческим пакетом. В отчёте не объединять эти проверки в утверждение full authenticated E2E.

Для read-only проверки сначала дождаться реального сохранения выделения редактором, затем снять ciphertext/revision baseline и выполнить контекст/поиск. Для проверки гонки сохранения временно задержать native encrypt в одноразовом профиле, не отключая шифрование и не меняя runtime. Закрытие копии должно очистить панель до завершения записи, а последующий cold restart — восстановить последний источник.

Старое поколение брать snapshot-ом закреплённых опубликованных исходных байтов без пересборки. Кандидат с retained generations собирать во временной source-копии. Trackable release metadata не изменять; такой пакет не считать разрешённым к deploy.

## Альтернативы

Только MemoryStorage unit-тесты отвергнуты как недостаточные для AES/IndexedDB/SW. Только browser component не доказывает реальную offline-shell/autosave интеграцию. Считать локальное unlock подтверждением Account запрещено контрактами. Пересборка старой версии вместо snapshot не проверяет точные rollback bytes. Отключение autosave ради стабильности теста скрывало бы гонку и не используется.

## Результат и ограничения

121 Core/UI тест, в том числе 8 новых границ Account; 14 private offline, 13 public offline и 5 upgrade/rollback групп прошли в CI 40326168219 на source 4d7cc36e2a861dbf752cc4b5a153cc9241fa6844. Первая неверная гипотеза о read-only selection сохранена как failed experiment.

Это синтетические данные и автоматический Linux/Chrome, не физический телефон, живой backend или педагогическое исследование. Проверка plaintext-маркеров не является полным криптоаудитом; state между всеми возможными старыми окнами не покрыт. Полный authenticated browser E2E и release decisions остаются отдельными gates.

## Security и rollout

Ни один существующий runtime-файл этим ADR не меняется. Реальные secrets не требуются. Нет cloud/backend/IAM/D1 mutations. Rollback эксперимент ограничен тестовым loopback-профилем и не переключает production.
