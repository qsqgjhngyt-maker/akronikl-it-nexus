AK-P1: навигация/справка; AK-P2: экспериментальный tutor; AK-P3: управление одним локальным runtime; AK-P4: чистый UX. Основа — PR #43, runtime `fe1564ba7192495370385002a81d0db98f67254f`, HEAD `1d42b6fde9f52cea2231451f6d808cbf7fd0fc7f`.

Нынешняя Qwen3-0.6B Q8_0/Wllama 3.8.1 имеет техническое доказательство генерации из прежних этапов, но качество и скорость не приняты. Установка с сохранением между запусками, несколько весов, реальный аппаратный WebGPU и внешний AI не готовы. Архитектурный пакет не закрывает предыдущие quality/device gates.

Контекстный перенос между моделями включается только после отдельной privacy-проверки, даже если обе модели локальны.

## Обязательные отрицательные проверки будущей установки

1. Неверный hash/размер/формат, другой runtime/modelId, отсутствующая редакция лицензии → нет installed/activate.
2. Отмена и закрытие посередине файла; crash после записи и до commit метаданных; stale metadata → корректный staging/missing, без ложного «готово».
3. Нет свободной квоты, отказ persist(), browser eviction → понятный отказ; не очищать проекты, progress и офлайн-копии.
4. Неверный Range, ответ 200 вместо 206, изменённый ETag/revision, неожиданный redirect → не склеивать разные версии.
5. Смена аккаунта и локальная блокировка при установке/генерации → отзыв; поздний progress/result игнорируется.
6. Переключение CPU/GPU/модели во время нагрузки; cleanup failure; две вкладки → нет второго неконтролируемого runtime.
7. Удаление одной установки → не удаляет личные данные, другую модель, прошлое release-generation или общий файл без учёта ссылок.
8. Холодный офлайн после подготовки → чтение сохранённых весов; отсутствие запроса в сеть; отсутствие весов не запускает download.
9. Изменение personality/model → не меняет ACL, facts, source IDs, exam rubric и права tools.
10. BYOK: запрещённые URL/redirect/private-network, чужая secret reference, повтор запроса после timeout, несанкционированный context → отказ до передачи.

## Измерения и приёмка качества

Сохранять environment, exact source, model/runtime revisions, hash весов, параметры и режим. Первый видимый фрагмент отдельно от raw JSON chunk и runtime TTFT. Считать token rate по реальному счётчику; отсутствии значения — null. Page heap не выдавать за всю память WASM/Worker или VRAM. Измерить холодную установку, повторную загрузку с диска, активацию RAM, первый запрос, продолжение, cancel, влияние на открытие урока/редактора.

Сравнивать одинаковые входные данные/источники в одной среде, отдельно повторения и разброс. Устройство без GPU не доказывает аппаратный offload. 32-case результат и понятность личности нельзя заменить фактом JSON-ответа. Критическую ошибку RAII сохранять как регрессию. Удаление условия ради зелёного PASS запрещено.

Профили ПК/iPhone16ProMax/SamsungA06 заполняются фактическими данными; эмуляция viewport не считается устройством. Точный HTTPS-кандидат и независимый test backend не разворачиваются без разрешения. Экранные дикторы и клавиатура — отдельная приёмка. Независимый review остаётся NOT RUN, пока его действительно не провели.

## Сохранность, выпуск и rollback

H0 не меняет runtime, поэтому рабочему сайту откат не нужен: main и production остаются прежними. Feature-документы можно не сливать либо отменить точным revert их коммита; старые PR не переписывать.

Будущие runtime-milestones требуют exact source/build/model/runtime/storage-schema ledger, сохранённой прежней сборки и проверки возврата. Update каталога не должен автоматически удалять прежние веса. Старый frontend при неизвестной новой схеме должен отказать безопасно/предложить Core, а не очистить хранилище. Миграции безобратного формата требуют отдельного согласования. Ни один старый B1/B2 rollback не объявляется новым PASS будущего Hub.
