# ADR-AK0-003 — отдельная приёмка собранного публичного офлайн-контура

Дата: 26.10.2026. Статус: принято для кандидата ветки 08, не production release.

## Контекст

PR #32 и #33 содержали дополняющие защиты UI. Компонентный PASS не доказывал загрузку модулей из immutable-путей, работу опубликованного формата SW и сохранение ресурсов между браузерными процессами. При этом использование настоящего production Account не требуется для проверки публичного индекса.

## Решение

Создать один кандидат поверх PR #33 с readReady из PR #32. Сохранить прежние ветки без force-push и merge. Собрать отдельное staging-поколение штатным build tool, проверять его bytes/manifest и затем запускать настоящую public offline-оболочку на loopback. Подготовка — при доступном сервере; холодный запуск — после закрытия процесса, в прежнем persistent-профиле, с offline network и недоступным сервером. SW не отключается, код модулей не переписывается.

Проверять повреждённый и отсутствующий публичный индекс, отказ неподготовленного профиля и контролируемое восстановление через обычный verified fetch. Не подменять server Account proof и не обращаться к production.

## Альтернативы

Только unit/component-тесты отклонены как недостаточные для cold-start. Простая перезагрузка страницы недостаточна для доказательства сохранности между процессами. Тест на действующем production не выбран из-за ненужной зависимости от реальных credentials и риска для пользователей. Объявление общего LIVE PASS по публичному тесту отклонено как превышение области доказательства.

## Последствия

Gate B1 закрывает built public offline path, но не Account/Cloud/private vault, update/rollback поколений и физические устройства. Эти области выделены в Gate B2. Исторические retained generations исключены только из staging-сборки B1; это не изменение release-контракта.

Повреждается один публичный ресурс в синтетическом профиле, не хранилище пользователя. Recovery вызывается контролируемым fetch и не доказывает автоматический recovery-UX. Длительности Playwright не используются как продуктовые latency p50/p95.

## Доказательства и воспроизводимость

Код `8f96e7dfc9712273ee48be94987d743ebc7fb899`; CI `40321085801`; 270 записей build manifest, 4 статические группы, 13 браузерных групп public offline и 13 component — PASS. Подробности, SHA256, неудачные эксперименты и границы — в MILESTONE_AKRONIKL_0_2_GATE_B1_2026-10-26.md.

Техническая основа методики: официальные Playwright BrowserType.launchPersistentContext и BrowserContext.setOffline. Используется отдельный тестовый профиль, не профиль владельца. Архитектура runtime/SW не менялась; production rollback остаётся прежним.
