## WHAT WAS PROVED

### Контракты аккаунта — настоящие модули, синтетические зависимости

Подтверждение аккаунта предшествует импорту приложения. Смена hash очищает помощник до завершения recheck и не разрешает открытие на старом DOM. Account A → B закрывает старые host/Core/facade; новый controller B не читает прогресс A. Logout во время запроса, 401/403, pagehide и поздние ответы не возрождают прежний контекст. Временный 503 не стирает прогресс и требует нового документа после восстановления.

Это **контрактная интеграция**, а не браузерное доказательство серверной сессии или полного UI приложения.

### Приватная локальная копия — настоящий браузерный контур

На loopback подготовлены ресурсы и две синтетические зашифрованные копии с одинаковым projectId, но разными владельцами и исходниками. После закрытия процесса браузера профиль запущен без сети; сервер перестал отдавать ответы. Частный редактор не открыт до ввода локальной фразы; неверная фраза отклоняется. UI явно сообщает, что облачный вход не подтверждён.

По умолчанию код в помощник не включается. После выбора наружу выходит только выделенный диапазон. Снятие выбора, смена файла и изменение workspace очищают старый результат. Контекст и поиск после завершения штатного editor-save не меняют ciphertext, ревизию и учебный прогресс.

При контролируемой задержке шифрования закрытие копии синхронно скрывает панель и запрещает повторное открытие до завершения записи. Затем последний исходник действительно сохранён и после второго перезапуска восстанавливается вместе с прогрессом. Копия B не наследует код A при том же projectId; копия A остаётся сохранной.

Задержка — временная тестовая обёртка native encrypt только в одноразовом профиле; после освобождения вызывается оригинальное шифрование. Нажатие обработчика закрытия при открытом modal вызвано программно: это fault-injection сценарий жизненного цикла, а не имитация доступного пользователю клика сквозь modal.

Проверено отсутствие заданных plaintext-маркеров кода, имени и синтетической фразы в durable vault. Это ограниченная отрицательная проверка, не полный криптографический аудит. Сеть после повторного включения не вызывает автоматический Cloud/Account обмен в данном сценарии. Приватный стенд: 0 запросов записи, 0 Account/API запросов, 0 ответов loopback во время cold-private, ошибок страницы нет. Скриншоты 390/1366 px просмотрены.

### Обновление и точный откат service worker

Штатный `snapshot-published-build.mjs` извлёк **2976 файлов** из закреплённого опубликованного source `065606a788198045cadf250fea663246ddbb2d56`. Старые байты не пересобирались. Проверка актуальной раздачи production этим снимком не выполнялась.

Новая тестовая сборка содержит **3237 файлов и 19 прежних поколений**. Все записи проверены по размерам/SHA256; у **2967 исторических immutable-файлов** hash и размер совпали с исходным snapshot. Изменена только временная копия build-конфигурации, не tracked metadata.

Настоящий браузерный тест прошёл последовательность: старая версия → кандидат → точная старая версия → кандидат. Два уже открытых тестовых документа сохранились. Синтетические localStorage, cache и encrypted IndexedDB bytes остались неизменны; после каждого перехода настоящая офлайн-оболочка разблокировала тот же проект, и расшифрованный payload полностью совпал с исходным. Worker errors: 0; внешних запросов: 0; 8 ожидаемых ошибок fetch при отключённой сети отдельно учтены. Пользовательские stores/cache не удалялись.

Это не доказательство сохранения открытой панели старой версии при всех lazy-import переходах и не проверка физически установленной PWA.
