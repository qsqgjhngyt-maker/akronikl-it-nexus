# ADR-AK0-002 — привязка UI-контекста к экземпляру редактора

Дата: 26.10.2026. Статус: принято в implementation candidate ветки 08; production не опубликован.

## Контекст

Offline-First Core уже умеет отклонять устаревшие запросы. При подключении панели к Nexus одного ID проекта и ревизии недостаточно: новый Code Studio может использовать тот же textarea, активный файл и номер ревизии. Устаревший UI не должен сохранять право читать код прежнего workspace или показывать его после закрытия редактора.

## Решение

Снимок host связывается с identity-объектом приложения, маршрутом, языками, DOM-редактором, конкретными объектами Studio/workspace, ревизией и активным файлом. Любое расхождение делает host недействительным. Прямое хранение credentials и чтение аккаунтных данных из localStorage не вводятся.

Открытая панель подписана на изменение workspace и на `childList` всей вложенной области root. Наблюдатель не подключён при закрытой панели. Уведомление `nexus:context-invalidated` является только командой очистки UI; оно не служит подтверждением сессии. Старые запросы отменяются, поздний результат не выводится.

## Альтернативы

**Только accountId/projectId/revision.** Отклонено: значения могут совпасть между разными экземплярами редактора.

**Только проверка textarea.** Отклонено по воспроизведённому дефекту: DOM-узел может быть переиспользован.

**Периодический polling всего приложения.** Не выбран: лишняя постоянная работа и интервал до очистки. Вместо него используются события, подписка workspace и наблюдатель открытой панели.

**Передача всей workspace в панель заранее.** Отклонено: расширяет область чтения кода и время жизни лишних данных. Читается один файл только при явном include selection; наружу выходит выбранный диапазон.

## Последствия и ограничения

Панель намеренно закрывается при смене контекста, а не пытается переносить выбранный код в другой проект. Пользователь открывает её заново. Это безопаснее, но UX повторного открытия нужно проверить на реальных сценариях.

Наблюдатель subtree видит DOM-мутации; произвольное присваивание JS-свойства само по себе не генерирует такое событие. Даже в этом случае host-проверка уже закрывает чтение. Полная интеграция обязана уведомлять о своих переходах; этот ADR не вводит универсальную защиту от любого доверенного кода приложения.

Глобальная частота DOM-мутаций, перерисовки и latency всей страницы ещё не измерены. Компонентный Chrome и narrow viewport не заменяют физические мобильные устройства и cold PWA.

## Проверка

Первоначально три теста повторной привязки дали FAIL. После фикса проходят четыре lifecycle-теста и полный набор из 97 Core/UI тестов. В CI отдельно прошли 13 браузерных групп с реальными UI/Core/knowledge/CodeWorkspace; две из них проверяют вложенное удаление и повторный bind.

Источник доказательств: commit `89755d5e1ff1ee38a4816ef1622ad154d58a53c4`, workflow run `40317282075`; подробности в MILESTONE_AKRONIKL_0_2_2026-10-26.md.

## Rollback и выпуск

Изменения остаются в feature-ветке. Нет изменения production backend, IAM, OAuth, D1 или разрешения merge. Для неподключённого кандидата rollback — оставить текущие main/release-артефакты неизменными. При последующей публикации нужен отдельный gate и план возврата версии.

## ВКР

Материал относится к архитектуре контекста, минимизации данных и regression testing. Это инженерный результат, не доказательство педагогической эффективности или научной новизны.
