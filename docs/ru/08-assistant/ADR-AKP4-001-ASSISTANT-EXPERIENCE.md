# ADR-AKP4-001 — разговор отдельно от настроек и доказательств

Дата: 27.10.2026. Ответственная ветка: 08. Статус: IMPLEMENTED в feature-кандидате; публикации нет.
Проверенный source: `fe1564ba7192495370385002a81d0db98f67254f`.

## Проблема и исходная архитектура

AK-P1–P3 предоставляли отдельные панели навигации, поиска, контекста, учебного диалога и управления моделью. Их механизмы уже проверены, но пользователь должен был выбирать технический инструмент до постановки вопроса. Модель медленная; наличие источника и успешная генерация не означают правильное объяснение.

## Решение

`openAssistantPanel` остаётся прежней ленивой точкой входа, но делегирует представление `experience/chat.js`. Принятые host, Core, PlatformGuide, TutorSession и ModelConnections сохраняются. Интерфейс не получает новых прав.

Один ввод маршрутизирует ограниченные известные формулировки к уже существующим действиям. Навигация использует каталог, предложение и повторную проверку при подтверждении. Вопросы наставнику проходят TutorSession; неизвестные ответы не заменяются придуманными действиями. Сообщения о неизвестной истории прогресса и не подключённой диагностике явно сообщают ограничение.

Основной экран содержит заголовок, статус, историю, поле сообщения, отправку/остановку и необязательные предложения. Пять разделов настроек скрыты до явного открытия. На Desktop это боковая область в том же модальном окне, на узком экране — отдельное представление. Пока настройки открыты, область разговора inert; Escape сначала возвращает разговор, затем закрывает окно. Это одна модальная область, не вложенные диалоги.

Источник курса, справка платформы, выбранный код и сгенерированное объяснение визуально различаются. Происхождение свёрнуто в отдельный блок. Текст модели не интерпретируется как HTML, инструменты или активная разметка. Модельный текст появляется после существующей проверки полного ответа; статус подготовки остаётся понятным.

## Минимизация контекста

Согласие на выбранный код выключено по умолчанию. Согласие на контекст текущего урока можно отозвать отдельно. При отзыве меняется граница контекста, отменяется запрос, очищается история и создаётся новая сессия. Смена аккаунта, блокировка копии, закрытие окна, изменение workspace и событий контекста сохраняют прежнюю очистку.

Динамические сообщения не добавляются в список элементов для перевода интерфейса: такой список мог бы удерживать удалённые DOM-узлы и выбранный код. Исправление выполнено по code review; отдельный heap-snapshot до/после не получен и не заявляется.

Настройки и разговор в этой версии живут только в окне. Это намеренный предел, не долговременная персонализация. Закрытие не восстанавливает модель/историю автоматически. Внешний провайдер остаётся отключён; системные разрешения и backend не меняются.

## Рассмотренные альтернативы

1. Только новый CSS поверх пяти прежних блоков — отклонено: сохраняет необходимость понимать устройство помощника.
2. Отдельная универсальная модель, напрямую управляющая DOM — отклонено: не обеспечивает проверяемые разрешённые переходы и отмену.
3. Полностью новый controller — отклонено: теряет уже принятые границы загрузки, lease, Account и очистки.
4. Потоковый вывод непроверенного JSON/текста — не выбран: текущий контракт подтверждает законченный ответ и разрешённые цитаты. Первый числовой chunk не выдаётся за первое показанное пользователю объяснение.

## Измерения и качество

Добавлен числовой meter: время первого content-chunk, total, runtime prompt/decode timings, количество токенов только из runtime, опциональный JS heap страницы. `firstOutputChunkMs` не переименовывается в точный TTFT: chunk может содержать JSON-служебные символы. Отсутствующая метрика — null, не ноль. JS heap не равен памяти Worker, WASM или процесса.

Новый корпус32 содержит ссылки на24 исходных материала RU/EN,4 граничных вопроса и4 диагностики настоящего g++ на синтетическом коде. Подготовка/валидация корпуса не равна пройденной оценке модели. Качество на всём корпусе NOT RUN; исторический дефект RAII сохранён и обнаруживается отрицательной проверкой. Исторические ответы читаются реализующим ассистентом, не независимым экспертом.

## Проверки и ограничения

Source:309 Core/UI,17 startup,25 bootstrap,21 isolation,4 build,22 UI-browser,11 authorized E2E,14 public offline — PASS. UI использует синтетический provider, авторизованный тест — виртуальный CTAP2/SQLite/gateway envelope. На настоящих телефонах, экранных дикторах и аппаратном GPU проверки не выполнены.

Без merge/deployment. Текущий rollback — сохранение прежней main/production; перед будущей публикацией нужен собственный точный пакет и release gate. Старые rollback-сценарии не считаются повторно пройденными этой сборкой.

## Материал для ВКР

Разделение presentation и capability/security; ограничение срока жизни контекста; различение факта источника и генерации; тестовый дефект выбора старого сообщения; разделение автоматического PASS, удобства и качества. Педагогическая эффективность и новизна не заявляются.
