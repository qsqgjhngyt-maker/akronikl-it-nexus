# ADR-AKP4-002 — Model Hub: один Akronikl, сменные модели

Дата: 27.10.2026. Ветка ответственности: **08 · AKRONIKL / INTELLIGENT ASSISTANT**.
Стратегическое решение: поручение владельца / MASTER 00 «MODEL HUB & PLUGGABLE INTELLIGENCE».
**Статус:** архитектурное решение зафиксировано; новые возможности Hub — **PLANNED**.
Эта поставка содержит документацию и доказательство совместимости, а не реализацию установщика, нескольких моделей или BYOK. Общий AK-P4 — **PARTIAL**.

## 2. Решение и шесть слоёв

**Один Akronikl → единый интерфейс, знания, характер и инструменты → сменный движок генерации.** Модель не становится владельцем личности, данных, разрешений или действий Nexus. Одинаковая политика не гарантирует одинакового качества речи разных моделей: каждое сочетание модели, runtime, языка и профиля проходит собственную приёмку.

| Слой | Владеет | Не получает |
|---|---|---|
| Akronikl Core | проверенный контекст, знания, навигация, реестр безопасных действий | новые права из текста модели |
| Personality Layer | версия характера, язык, стиль и режим серьёзности | право менять факты, ACL, диагностику или оценку |
| Model Hub | каталог, установки, совместимость, согласия, активное подключение | чтение всех проектов ради выбора модели |
| Model Adapter | формат запроса/ответа, генерация, отмена, измерения | произвольные файловые/административные инструменты |
| Tutor Layer | педагогический сценарий, источники, проверка ответа и ссылок | возможность выдавать неподтверждённую компиляцию за факт |
| Security/Privacy Layer | изоляция аккаунта/копии, разрешённые поля, отзыв, внешняя передача | регулирование безопасности ползунком юмора |

Путь запроса: разрешённый снимок Core → правила Tutor/Companion и личности → отзываемое подключение Hub → адаптер → структурная проверка ответа → отображение с происхождением. Результат генерации не исполняется. Справка и навигация Core обходятся без модели. При отказе модели пользователь получает ясное сообщение и доступ к Core; автоматической отправки в облако нет.

## 3. Совместимость с AK-P3/P4: что уже есть и чего нет

| Реальный узел | Состояние сейчас | Переход без скрытой смены контракта |
|---|---|---|
| `connections/profiles.js` | sources, CPU/WebGPU одной Qwen3; external отключён | сохранить IDs как legacy aliases; модель и профиль выполнения разделить |
| `connections/controller.js` | один владелец runtime; отзыв lease, cancel, cleanup, revision | оставить владельцем активного runtime; добавить отдельный каталог и менеджер установок |
| `connections/probe.js` | ограниченный same-origin manifest, проверка среды/GPU | не приравнивать наличие manifest к целостности runtime, свободной RAM или скорости |
| `tutor/local-model.js` | один фиксированный hash GGUF; Wllama 3.8.1; выбор Blob; без каталога на диске | сначала реализовать проверенный локальный storage adapter; не принимать любой GGUF только по расширению |
| `tutor/session.js` | только local/in-process; `{messages, allowedCitations, signal, onProgress}` → `{answer,citations}` | сохранить v1, вводить версионированный adapter bridge с отдельными тестами |
| `core/model-api.js` | иной контракт: `{prompt,context}` → `{text}`; external запрещён | не считать тождественным tutor API; не снимать запрет global-флагом |
| `experience/chat.js` | чистый разговор, настройки отдельно, история и предпочтения в окне | добавить Hub и личность только в настройки; не пересоздавать Академию/редактор |
| `context.js` | динамический импорт UI по открытию | не переносить Hub, хэширование весов и runtime в стартовый граф |

**Вывод:** архитектура совместима с существующей моделью владения и отзыва доступа, но расширяемый каталог, установка, постоянное хранение, свободный разговор и перенос истории ещё не реализованы. Нынешний контроллер намеренно отвергает другой modelId и внешний транспорт. Это защитная граница, не готовая поддержка любых моделей.

## 4. Предлагаемые контракты

### ModelDescriptorV1 — доверенные метаданные

Разделить `modelId`, revision/quantization и `executionProfileId`. Одна установка Qwen может использовать CPU или проверенный GPU-профиль; второй профиль не означает второй файл весов.

Минимальные поля: schemaVersion, modelId/revision, kind (local/external), adapterId/version, runtimeId/version, формат, квантование, язык/проверенные задачи; список артефактов с **точным** числом байтов и SHA256; закреплённый источник; licenseId, licenseURL, проверенная редакция и условия использования; оценка RAM/VRAM/места с признаком «оценка», диапазон контекста; статус проверок и ссылка на evidence.

Для текущего Qwen установлен верхний размер, но это не exact-size manifest будущего установщика. Неизвестные exact bytes, лицензия или runtime-совместимость блокируют автоматическую установку. SHA256 подтверждает совпадение с доверенным описанием, а не безопасность неизвестного кода, происхождение сам по себе или право распространения. Каталог не содержит API-ключи, имена личных проектов и пользовательские сообщения.

### ModelHubV1 — разделить операции

`listCatalog`, `listInstallations`, `inspectCompatibility`, `install`, `pause`, `resume`, `cancelInstall`, `activate`, `deactivate`, `remove`, `snapshot`, `lease` — **проектируемая поверхность**, не работающие вызовы нынешнего Hub.

Установка получает trusted catalog ID или явно выбранный файл и отдельное согласие; не произвольный исполняемый URL. Подключение принимает только подтверждённую установку. Удаление адресуется конкретному artifact ID, никогда всей IndexedDB/CacheStorage/OPFS. Прекращение генерации, выгрузка из RAM и удаление весов с диска — три разных действия.

### Adapter bridge — постепенная миграция

Сначала wrapper над действующим tutor-v1 без изменения формата. Следующим отдельным milestone вводится версия с `requestId`, `purpose` (tutoring/companion), контекстной ревизией, ограниченным входом, cancel и типизированным результатом. Legacy Core API не ломается: отдельный bridge и контрактные тесты, без двух несогласованных prompt-builders.

Ответ содержит текст, известные метки источников, статус завершения, факт генерации, model/adapter revision и полученные числовые метрики. Неизвестный источник, `tool_calls`, действия, незавершённый JSON и просроченный контекст не считаются готовым ответом. Отсутствующая метрика — null. Первый фрагмент JSON не называется первым отображённым словом или точным TTFT.

Политики Core/Privacy/Tutor неизменяемы для адаптера. Личность — валидированные параметры стиля из host, не инструкция, прочитанная из курса/модели. Нельзя просто подставить внешний provider в нынешний local-only lease: требуется отдельный серверный путь с собственной приёмкой.

## 5. Установка, дисковое хранение и RAM — три разных состояния

Состояния артефакта (PLANNED): absent → awaiting-consent → downloading/importing ↔ paused → verifying → installed; отдельно cancelled, failed, missing/evicted, corrupted, removing. Только verified/installed допускает активацию. Подтверждённая запись метаданных публикуется после полной проверки всех байтов; частичный файл остаётся staging и никогда не активируется.

Состояния подключения сохраняют смысл P3: sources / disconnected / checking / checked / loading / connected / unavailable / error / closed. `checked` ≠ `installed` ≠ `connected` ≠ «качество принято».

Начальный storage-кандидат: **OPFS для больших публичных весов, отдельная IndexedDB для каталога**. Это проектный выбор, требующий проверки браузеров, а не новый внедрённый backend. При отсутствии нужных API — явный импорт по сеансу, а не молчаливое обещание постоянной установки.

Публичные проверенные веса могут быть общими для одного browser profile/origin, но согласие на загрузку, выбор активной модели и предпочтения привязаны к владельцу допустимого контекста. На общем устройстве это должно быть показано; по умолчанию аккаунт B не наследует модель, стиль, разрешения и переписку A. Неутверждённые частные модели/LoRA и файлы с личными данными в общий store не допускаются.

**Отдельное имя базы не создаёт независимую квоту или криптографическую изоляцию.** Origin-хранилища управляются браузером, оценка квоты приблизительна, возможна очистка. Установка большой модели конкурирует за место с офлайн-данными Nexus. Перед записью нужен резерв для проектов, проверка estimate(), обработка QuotaExceededError и отказ вместо удаления учебных данных. persist() — отдельная возможность браузера, не гарантия вечного хранения. OPFS не является шифрованием личной переписки. Основание: [S1–S2].

При повторном открытии читать только небольшой каталог после открытия помощника/настроек. Проверить наличие и согласованность файла; перед активацией выполнить проверку целостности принятой версии. Пропажа весов → статус «Файл модели отсутствует» с предложением повторной подготовки, но **без автоматического скачивания**. Сохранённые веса не означают загруженную модель: RAM выделяется отдельно по активации. Время, transient RAM и влияние повторного хэширования измерять; нынешний arrayBuffer целого GGUF не считается готовым малопамятным установщиком.

## 6. Согласие и тихая подготовка

Первое согласие привязать к модели/revision/hash, размеру, лицензии, источнику, локальному месту и расходу сети. Новая версия, другой источник/размер или другая модель требуют нового подтверждения. Согласие загрузить публичные веса не разрешает отправлять контекст внешнему AI.

Подготовка — только при открытом Nexus, после согласия, с возможностью остановки и ограничением CPU/памяти/сети. На слабом устройстве по умолчанию ручной запуск. Проверка доступных ресурсов не должна собирать hardware fingerprint; нехватку GPU/RAM нельзя надёжно исключить одним размером файла или requestAdapter.

Большие I/O и хэширование — в Worker с пределами и отзывом задачи. Не обещать универсальный браузерный streaming SHA256: конкретная реализация и зависимость должны пройти проверку. Не загружать модель в RAM во время старта Академии. После полного закрытия браузера/PWA подготовка не обещается. При смене аккаунта pending-job приостанавливается/отзывается; продолжение только в разрешённом контексте.

Пауза/возобновление сети разрешаются лишь для проверенного источника. Для Range проверить 206, Content-Range, исходный validator/revision, итоговый размер и SHA256. Ответ 200 на resume нельзя дописывать к старому файлу; изменение validator требует безопасного перезапуска с уведомлением. Нет поддержки корректного resume → честно «загрузить заново», а не фиктивная пауза. HTTP-основание: [S3].

Staging и завершённая установка разделены, публикация метаданных транзакционная; после аварии незавершённая запись не считается установленной. При удалении активной модели сначала отзыв lease/отмена/cleanup, затем удаление только её артефактов. Общий файл CPU/GPU удаляется с учётом ссылок и явного предупреждения. Миграция store и rollback не должны требовать очистки личных проектов.

## 7. Переключение модели и перенос контекста

В текущем коде переключение очищает разговор; этот default сохраняется. Сначала отзыв старого lease/epoch и очистка видимого приватного контекста, затем ожидание cleanup, проверка новой модели и отдельная активация. При ошибке cleanup новая модель не запускается; Core остаётся доступным. Одновременно активен один runtime на контекст, а в первой версии требуется также межвкладочная координация тяжёлой активации; выбранный механизм блокировки проходит отдельную проверку.

Личность хранится независимо от экземпляра модели, поэтому её конфигурация может сохраниться внутри того же разрешённого окна. Это не перенос старого model KV-cache. Перенос истории **выключен по умолчанию** и вводится отдельным gate: выбор пользователем конкретных данных, новая проверка ACL и актуальности, показ получателя и разрешение. При переходе local → external необходимо отдельное внешнее согласие. После logout, блокировки или смены аккаунта переноса нет даже при старом согласии.

Артефакт лицензированной публичной модели может оставаться на диске после logout, но личный контекст, KV-cache, callbacks, выбранный аккаунтом режим и runtime освобождаются. Логи не содержат код, сообщения, credentials или raw error bodies. Сводные показатели не отправляются наружу без отдельного разрешения.

## 8. External AI / BYOK — будущий отдельный milestone

Планируемый путь: UI → защищённый серверный адаптер Nexus → конкретный allowlisted provider. Сервер заново проверяет Account/ACL, разрешённый состав передачи, лимит токенов/размера, частоту, бюджет и cancellation. Секрет изолирован по аккаунту, не возвращается в публичный JavaScript, localStorage, GitHub или evidence. Форма «введите любой URL» и открытый proxy запрещены; запрет redirect/SSRF проверяется отдельно.

Показывать активного получателя и возможность отключить его, не загромождая чат длинными настройками. Язык/характер не раскрывают дополнительные данные. Повторная попытка после timeout не должна незаметно повторять платный запрос. Отмена на клиенте не гарантирует отмену начислений провайдера — нужна реальная проверка конкретного API.

OpenAI, Gemini, Anthropic, DeepSeek, OpenRouter и OpenAI-compatible — только планируемые семейства. Для каждого отдельно фиксируются версия API, схема, ошибки, формат citations/stream, цены и ограничения. OpenAI-compatible не означает одинаковые возможности всех сервисов. В этом ADR ни один внешний адаптер не реализуется, секреты не запрашиваются, платные запросы не выполняются.

## 9. Альтернативы и последствия

Не выбрано: заменить Akronikl брендом модели; отдать модели прямое управление файлами; принимать произвольные исполняемые runtime из каталога; хранить веса и переписку в общем публичном SW-кеше; загружать модель при старте; молча переключаться в облако; считать зелёный unit-тест доказательством качественного преподавателя.

Принято: расширить существующий controller, а не переписать Account/Академию. Отдельные artifact/runtime states и явная миграция двух API добавляют работу, но делают проверяемыми разрешения, расход памяти, отключение и rollback. Автоматическое сохранение всей истории между аккаунтами не требуется для постоянного характера.

## 10. Gate, ограничения и дальнейшие действия

Прямо сейчас меняются только docs/evidence. Адресная проверка существующей основы: 97/97 PASS (47 connections/probe + 33 experience + 17 startup); модель, браузерный E2E и все 32 качества заново не выполнялись. Новых весов, хранилищ, серверов и runtime нет. Это проверка пригодности исходных границ для проектирования, не AUTOMATED PASS будущей установки.

Для перехода к реализации см. [контракт UX/личности](CONTRACT_AKP4_PERSONALITY_HUB_RU.md) и [roadmap/gates](ROADMAP_AKP4_MODEL_HUB_RU.md). Сначала сохраняем чистый UX и закрываем реальные качество/скорость; установщик, multi-model и BYOK требуют отдельных milestones и допуска владельца. Физическая приёмка, независимый review и полноценный release/rollback остаются открытыми.

Материал для ВКР: отделение личности от движка, две реальные версии API, жизненный цикл установки/активации, shared-origin threat model и отказ от ложных гарантий офлайн. Педагогическая эффективность и полный продуктовый PASS здесь не доказаны.

## Первичные технические источники

Технические основания проверены 27.10.2026; они не заменяют испытания Nexus. Описанные способы использования — проектные решения.

- **S1:** WHATWG Storage Standard, storage buckets, quota, management, persistence: https://storage.spec.whatwg.org/ . Оценка квоты не равна свободной RAM; удаления browser-managed данных не исключены логическим namespace.
- **S2:** MDN, Origin private file system: https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system . OPFS относится к origin, подчиняется квоте; очистка данных сайта удаляет его; синхронные операции выполняются в Worker.
- **S3:** MDN, HTTP range requests: https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Range_requests . Различать 200/206/416, Range и If-Range при продолжении загрузки.
