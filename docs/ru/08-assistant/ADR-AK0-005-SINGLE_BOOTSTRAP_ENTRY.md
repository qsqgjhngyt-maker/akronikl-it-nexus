# ADR-AK0-005 — одна точка автоматического запуска bootstrap

Дата: 26.10.2026. Ветка 08, завершение AKRONIKL-0.2 Gate B2.
Статус: исправление в изолированном кандидате; не разрешение на merge/release. Независимый security review не выполнен.

## Проблема и наблюдение

В сквозном прогоне 40334309212 успешно выполнены вход виртуальным WebAuthn, контекст/поиск/урок, создание личной копии, сохранение, холодный запуск и обратный импорт. После импорта переход к редактору многократно заменял DOM: 32 повторные попытки нажатия за 20 секунд, повторные Account-запросы и затем 429 control/capabilities. Протокол сохранён как FAIL.

HTML запускает `core/bootstrap.js?v=<version>`. `offline-center.prove()` импортирует `../core/bootstrap.js` для `readVerifiedSession`. Это разные URL модуля. Прежний безусловный auto-start создавал два bootstrap с разными WeakSet выпущенных hashchange. Каждый экземпляр принимал событие другого за новый переход и вновь проверял сессию. Это дефект жизненного цикла приложения, не ошибка ответа модели.

## Решение

Автоматически запускать bootstrap только когда его точный module URL соответствует `script[type="module"][src]` текущего документа. Импорт reader без query больше не создаёт второй управляющий экземпляр. Явные `startNexus`, `createNexusBootstrap` и `readVerifiedSession` сохраняют API; проверка server proof, Account DTO, HttpOnly transport, suspend/logout и ACL не меняются.

Сравнение URL разрешает автоматический запуск, но НЕ разрешает доступ к данным: startNexus всё так же проверяет настоящий серверный ответ до storage/app. Отсутствующий или повреждённый document не открывает автоматический путь. Прямой module script без query также поддержан.

## Альтернативы

Глобальный флаг «уже запущено» не выбран: скрывает владельца жизненного цикла между поколениями и затрудняет очистку. Удаление version-query из существующего HTML не выбрано: затрагивает закреплённый build/release contract. Выделение чистого session-reader в отдельный модуль возможно позже, но потребовало бы более широкого перемещения проверенного кода сессии.

## Проверки и пределы

Добавлены пять регрессий соответствия входного module URL. Повторяются адресные UI/Account/bootstrap/startup/ESM проверки, сквозной browser E2E, сравнение скорости и точный rollback после изменения входного модуля. Фактические результаты должны браться из CI конкретного итогового SHA, а не из наличия этого ADR.

ADR-AK0-004 и его отрицательный эксперимент select/autosave сохранены. Физические устройства и реальный ключ владельца этим исправлением не проверены. Backend, IAM, OAuth, D1, main и production не меняются. Перед публикацией нужен review frontend bootstrap в составе единого кандидата; решение принадлежит MASTER/владельцу.
