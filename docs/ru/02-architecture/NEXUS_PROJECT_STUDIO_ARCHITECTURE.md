# Nexus Project Studio — архитектура итоговых инженерных проектов

## Назначение
Nexus Project Studio — будущий модуль AKRONIKL IT NEXUS, в котором учащийся после освоения курса создаёт собственный работающий продукт внутри той же экосистемы. Это не отдельный внешний IDE-сценарий, а продолжение учебного пути: **изучить → понять → попробовать → проверить → создать → выпустить**.

## Основные сценарии
- выбрать предложенный итоговый проект или сформулировать собственную идею;
- оформить техническое задание и минимальную рабочую версию;
- вести дерево файлов проекта;
- запускать, тестировать и собирать проект через Nexus Sandbox;
- получать контекстную помощь Akronikl без автоматического «написания проекта вместо ученика»;
- сохранять именованные версии/snapshots и сравнивать изменения;
- откатываться к предыдущей рабочей версии;
- получать build artifacts там, где это допускает runtime/build provider;
- выпускать итоговую Portfolio Card с описанием, навыками, тестами, историей версий и артефактами.

## Контекст Akronikl Project Mentor
Akronikl получает только разрешённый контекст проекта: спецификацию, дерево файлов, активный файл, diagnostics/build output, тесты, историю попыток и освоенные навыки. Наставник должен объяснять причины, предлагать план исправления, делать review и помогать декомпозировать задачу, но не подменять самостоятельную работу учащегося.

## Версионирование
Начальный интерфейс не требует знания Git. Пользователь видит понятные snapshots: `0.1 — первый прототип`, `0.2 — инвентарь`, `1.0 — стабильный выпуск`. Позже курс Git связывает эту модель с commit/branch/diff и профессиональными системами контроля версий.

## Sandbox / Build
Project Studio использует единый Nexus Sandbox API. Простые задачи выполняются Browser Runtime, более сложные — WASM provider, а многфайловые/native build-сценарии — изолированный Secure Build Runner. Выбор provider не должен менять основной интерфейс ученика.

## Безопасность
Cloud/build provider обязан быть изолирован: ограничения CPU/RAM/времени, запрет произвольного доступа к инфраструктуре, контролируемая файловая система, аудит зависимостей и отсутствие секретов в клиентском коде.

## Статус
Архитектура зафиксирована в v0.1.2-alpha.3. Полноценная реализация Project Studio — отдельный будущий этап после стабилизации Nexus Sandbox и benchmark-уроков.
