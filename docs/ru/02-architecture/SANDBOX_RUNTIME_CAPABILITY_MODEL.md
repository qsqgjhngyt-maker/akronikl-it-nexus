# Модель возможностей Nexus Sandbox Runtime

**Статус:** архитектурный стандарт, v0.1.5-alpha.1  
**Язык-норматив:** RU

## Цель

Nexus Sandbox с `v0.1.5-alpha.1` использует **language-neutral Runtime Router**. C++ остаётся первым эталонным языком, но provider contract принимает явный `languageId` и предназначен для всех языковых треков блока «Программирование».

Nexus Sandbox должен оставаться единой средой обучения и разработки даже тогда, когда разные темы требуют разных execution engines. Пользователь не должен разбираться, какой именно runtime обслуживает упражнение; это задача платформы.

## Три независимых результата

Sandbox обязан различать:

1. **Статический анализ Nexus** — базовая структурная проверка исходника.
2. **Проверку задания** — соответствие явным требованиям упражнения.
3. **Runtime/Build** — фактическое выполнение программы выбранным provider.

Успех первых двух пунктов не означает, что исходник прошёл полноценный C++ compiler. И наоборот, отказ лёгкого Browser Runtime не должен автоматически считаться ошибкой ученика.

## Уровни provider

### Browser Runtime

Назначение: быстрые учебные упражнения, console I/O и мгновенная обратная связь.

Гарантируемая зона: базовые выражения, ветвления, циклы, функции и простые консольные программы в поддерживаемом подмножестве.

`class`, constructors, inheritance, `virtual`, `override`, templates, exceptions и другие современные конструкции считаются **best-effort**, пока capability probe не подтвердил их для конкретного runtime.

### WASM Runtime

Расширенный локальный tier. В `v0.1.5-alpha.1` реализованы provider contract, lifecycle и изолированный Web Worker foundation; сам Modern C++ compiler подключается в следующем этапе. Цель — полный современный C++/STL без изменения UX Sandbox, а затем подключение других WASM-capable toolchains.

### Secure Build Runner

Планируемый изолированный server-side provider для multi-file projects, полного toolchain, тестов и build artifacts Project Studio.

## Capability routing

Перед выполнением Nexus анализирует требуемые возможности исходника. Router выбирает наиболее подходящий доступный provider. Пока расширенные providers не подключены, Browser Runtime используется как fallback с явной маркировкой `best-effort`.

## Диагностика ограничений среды

Если:

- базовый статический анализ не находит структурной ошибки;
- runtime parser падает на конструкции вне гарантированного набора текущего provider;

Nexus показывает состояние **«Ограничение среды»**, а не объявляет исходник неверным C++.

Это не утверждение, что программа заведомо корректна: статический анализ Nexus не заменяет стандартный compiler. Сообщение означает только, что текущий лёгкий provider не может быть надёжным арбитром для данной конструкции.

## Compatibility adapters

Допустимы только преобразования временной runtime-копии, которые не меняют учебный исходник и не должны менять intended semantics корректной программы.

В v0.1.4-alpha.2 разрешён retry без `override`: `override` является compile-time annotation проверки переопределения. Пользовательский source остаётся неизменным.

Запрещено автоматически удалять `virtual`, менять иерархию, типы, ownership или логику программы только ради того, чтобы старый parser её принял.

## Self-test

«Проверить среду» выполняет как минимум:

- базовый console/stdout probe;
- отдельный OOP capability probe.

Провал OOP probe не означает поломку базового runtime. UI должен показать, что console layer готов, а расширенное ООП — best-effort.

## Связь с Project Studio

Project Studio использует тот же Nexus Sandbox router. По мере роста проекта интерфейс сохраняется, а execution provider может переключаться с Browser Runtime на WASM или Secure Build Runner без переноса ученика во внешнюю IDE.
