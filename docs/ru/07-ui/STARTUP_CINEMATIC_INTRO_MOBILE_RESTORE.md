# Мобильная регрессия заставки: восстановление прежнего плеера

STATUS: IMPLEMENTED; проверки продолжаются. Публикации нет.

База: ad3cfeaeef4710a126a336499c85420264591384 (PR51).

Подтверждение пользователя: на физическом телефоне по-прежнему чёрное ожидание, на ПК всё нормально. Прежние Chrome-проверки PR51 доказали постер и тёплое воспроизведение, но не исправление полного холодного запуска на телефоне. Этот отзыв отменяет прежнее заключение о закрытии мобильного дефекта.

Причина, воспроизведённая на холодном транспорте: цельный cinematic-v4 и общий предварительный буфер задерживают запуск до мобильного дедлайна. Восстановлены мобильный IntroSequence принятого PR49 и его неизменные same-origin Full HD части cinematic-v3: четыре части по 2 секунды, всего 8 секунд. Предварительный буфер v4 остаётся только Desktop. Старое качество не перекодируется. Логотип появляется по общей временной шкале с шестой секунды; финал удерживается 500мс, гаснет 900мс, затем интерфейс раскрывается 500мс. Первое проявление 1200мс. Пропуск доступен сразу.

ПК сохраняет цельный cinematic-v4, прежние буфер, настройки, источник и тайминги. Account/Cloud/Code Studio/Content, сервер, entry.html/entry.js, OAuth, параметры исполнения и данные не меняются. Ранний мобильный фон и постер сохранены. Отключение, reduced motion, offline и подавление повтора после выхода сохраняются. Поворот экрана пересоздаёт соответствующий плеер.

Проверка должна доказать движущиеся кадры из всех четырёх частей в новом профиле без прогрева HTTP cache. Постер и тёплый кэш не принимаются за исправление. Chrome mobile viewport не равен физическому iPhone/Android; физическая проверка остаётся отдельным этапом.

Откат: tools/prepare-startup-mobile-restore.mjs --rollback восстанавливает семь корневых файлов точными bytes базы, сохраняет immutable поколения и пользовательские данные. Новый runtime BFF не требуется.
