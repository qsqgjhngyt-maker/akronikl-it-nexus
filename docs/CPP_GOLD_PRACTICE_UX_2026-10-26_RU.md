# Gold-практикумы — контрольные случаи и рабочая среда

26.10.2026. Область 03/07; 02 — информационно. Продолжение тестовой публикации Module 4. Официальный Release/тег не создавать.

STATUS: IMPLEMENTED / PARTIAL. Исправление подготовлено в feature; новая публикация и её LIVE здесь не заявляются.

Владелец подтвердил работу Module 4 test.1 на ПК и телефоне, но сообщил о слишком широкой/высокой таблице и отсутствии понятного перехода из задания к Studio. Видео подтверждает: длинный stdin задаёт ширину столбца, скрытые stdout/файлы задают высоту строки, единственный горизонтальный scrollbar оказывается внизу всех случаев. Функциональный LIVE не закрывает это замечание 07.

Общий renderer M1–4 заменяет таблицы раскрывающимися случаями. Первый открыт, остальные видны как подписанные строки; stdin/stdout располагаются рядом на широком экране и друг под другом на телефоне. Файлы и свойства раскрываются внутри соответствующего случая. Перенос длинных строк устраняет горизонтальный scroll; отдельный очень длинный текст имеет ограниченную высоту. Копирование stdin, stdout и каждого файла сохраняет исходный текст, включая пустой ввод.

Лабораторные и оба вида практикумов получают блок «Где выполнять работу»: переход к редактору того же урока и ссылка в Code Studio для отдельного проекта. Практикум рекомендует отдельный C++ проект и поясняет перенос заготовки/файлов. Навигация не вставляет код и не создаёт проект автоматически. Фокус переходит в существующий редактор; мгновенная прокрутка сохраняет его заголовок под фиксированной панелью.

Проверено локально в отдельном Chrome с синтетическим аккаунтом: 92 RU/EN объекта, точное содержимое всех случаев, файлы/свойства, шесть ширин 320/360/390/768/1366/1440 — без горизонтального overflow. Клавиатурные Enter/Space, фактический clipboard, пустой и длинный ввод, переходы из четырёх модулей RU/EN и возвращение из Studio прошли. Вызов clipboard получает исходные LF; Windows при чтении системного clipboard преобразует их в CRLF, это учтено отдельно. Содержимое кода, stdin, прогресс и весь синтетический ProjectStore сохранены. Из сравнения служебного state исключены updatedAt и workspace.revision: существующий bind редактора обновляет их при возврате. Это не сравнение личных данных владельца и не физический LIVE.

История проверок сохранена: первый запуск заблокирован сетевой песочницей; затем уточнены ожидания теста для Windows CRLF, выходного файла вместо отсутствующего c.files и служебного revision. Найденный при проверке медленный переход из-за CSS smooth исправлен на instant. Старый точный publication gate закономерно отклоняет изменённый renderer, пока новый пакет не получит отдельный pinned scope; это не разрешение ослабить gate.

Не изменяются учебные JSON, C++ исходники/контракты, stable IDs, storage/migrations, Identity/Cloud, ProjectStore, runtime или backend. NEXUS-PERF-01 и холодный Offline требуют повторного подтверждения на окончательной сборке. Существующее опубликованное поколение test.1 не редактируется.
