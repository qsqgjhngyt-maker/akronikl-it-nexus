# Gold-практикумы — контрольные случаи и рабочая среда

26.10.2026. Область 03/07; 02 — информационно. Продолжение тестовой публикации Module 4. Официальный Release/тег не создавать.

STATUS: IMPLEMENTED / PARTIAL. Исправление подготовлено в feature; новая публикация и её LIVE здесь не заявляются.

Владелец подтвердил работу Module 4 test.1 на ПК и телефоне, но сообщил о слишком широкой/высокой таблице и отсутствии понятного перехода из задания к Studio. Видео подтверждает: длинный stdin задаёт ширину столбца, скрытые stdout/файлы задают высоту строки, единственный горизонтальный scrollbar оказывается внизу всех случаев. Функциональный LIVE не закрывает это замечание 07.

Общий renderer M1–4 заменяет таблицы раскрывающимися случаями. Первый открыт, остальные видны как подписанные строки; stdin/stdout располагаются рядом на широком экране и друг под другом на телефоне. Файлы и свойства раскрываются внутри соответствующего случая. Перенос длинных строк устраняет горизонтальный scroll; отдельный очень длинный текст имеет ограниченную высоту. Копирование stdin, stdout и каждого файла сохраняет исходный текст, включая пустой ввод.

После второго замечания владельца переход вниз отменён до публикации. Кнопка «Задание и Code Studio» открывает native modal поверх урока: на ПК условие/контрольные случаи рядом с редактором, на телефоне вкладки «Задание» / «Code Studio». Кнопка «Вернуться к заданию» и Escape возвращают фокус и точную позицию страницы. Прокрутка задания сохраняется при переключении мобильных вкладок.

В окно переносится тот же DOM-редактор с прежними обработчиками и workspace; второй редактор и второй state не создаются. В условие копируется только представление задания. Код не вставляется автоматически. Для итогового проекта остаётся отдельная ссылка в Code Studio с объяснением сохранения самостоятельного проекта. Native dialog делает фон inert; при закрытии, смене маршрута или удалении урока освобождаются media listener и observer. Окно не меняет Identity/Cloud/ProjectStore/runtime contracts.

Проверено локально в отдельном Chrome с синтетическим аккаунтом: 92 RU/EN объекта, точное содержимое всех случаев, файлы/свойства, шесть ширин 320/360/390/768/1366/1440 — без горизонтального overflow. Клавиатурные Enter/Space, фактический clipboard, пустой и длинный ввод, переходы из четырёх модулей RU/EN и возвращение из Studio прошли. Вызов clipboard получает исходные LF; Windows при чтении системного clipboard преобразует их в CRLF, это учтено отдельно. Содержимое кода, stdin, прогресс и весь синтетический ProjectStore сохранены. Из сравнения служебного state исключены updatedAt и workspace.revision: существующий bind редактора обновляет их при возврате. Это не сравнение личных данных владельца и не физический LIVE.

Дополнительно локально PASS: 32 открытия/закрытия рабочего окна в четырёх модулях RU/EN на 1366/390 px, точный возврат focus/scroll, сохранение того же editor node, исходников, stdin и синтетического проекта; настоящий Clang/WASI запуск внутри окна дал stdout `modal` и exit 0. Это QA с локально проверенными runtime bytes, не CDN LIVE и не физические устройства. Окончательный вариант с очисткой при смене маршрута и полной responsive матрицей проходит повторную приёмку отдельно.

История проверок сохранена: первый запуск заблокирован сетевой песочницей; затем уточнены ожидания теста для Windows CRLF, выходного файла вместо отсутствующего c.files и служебного revision. Первоначальный переход вниз прошёл проверки, но отозван по UX-замечанию владельца до deployment; PR30/58db507 не является принятым окончательным UI. Старый точный publication gate закономерно отклоняет изменённый renderer, пока новый пакет не получит отдельный pinned scope; это не разрешение ослабить gate.

Не изменяются учебные JSON, C++ исходники/контракты, stable IDs, storage/migrations, Identity/Cloud, ProjectStore, runtime или backend. NEXUS-PERF-01 и холодный Offline требуют повторного подтверждения на окончательной сборке. Существующее опубликованное поколение test.1 не редактируется.

ROUTING CHECK: 07 — общая приёмка контрольных случаев и переходов; 05 — точные source/build/rollback/CI и границы LIVE; 00 — Module 4 остаётся PARTIAL по UX до повторной проверки владельцем. 02 — ссылки используют существующий редактор и Code Studio, контракт хранения не меняется. 01 — изменений auth/Cloud нет. 04 — материал: progressive disclosure, сохранность точных учебных входов, визуальная регрессия и разделение автоматической/личной приёмки. 06 — отдельное исследование сейчас не требуется.

Есть ли здесь материал для диплома? Да: альтернативы — дублирование scrollbars, переход к нижнему редактору с возвратом, отдельные редакторы под заданиями. Выбраны раскрывающиеся случаи и контекстное рабочее окно с единственным редактором: сохраняются рабочий код и позиция, не появляется конфликт нескольких копий state. Измеримы отсутствие overflow, сохранность данных, возврат focus/scroll и работа C++; улучшение эффективности обучения экспериментально не измерялось.
