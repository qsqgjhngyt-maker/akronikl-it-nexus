# Сборка C++ приложений и проверка работ в Nexus

Экспериментальный сервис для feature Module 6. Студент создаёт переносимый TaskFlow, редактирует C++, собирает настоящее Qt приложение, сохраняет данные, запускает тесты и сдаёт точную версию внутри Nexus. Преподаватель получает исходники этой версии и выставляет оценку по рубрике. Автотесты проверяют модель проекта; сами по себе они не подтверждают освоение курса.

## Сборка и исполнение

Обычные уроки продолжают использовать прежний Clang/WASI. Qt target собирается из присланного исходного C++ внутри ограниченного контейнера: без сети, root privileges, capabilities и Docker socket; readonly SDK/input, отдельные tmpfs/output, 2 CPU, 2 GiB, 128 процессов, 180 секунд, ограниченные logs/artifacts. При отмене уничтожается сам контейнер. Преподавательские контрольные тесты берутся из серверной версии и компилируются независимо от редактируемого CMake и тестов студента.

Кандидат SDK: Qt6.8.3 singlethread и Emscripten3.1.56. Base image закреплён digest в Dockerfile; фактический image ID сохраняется в результате. Qt использует совместимый Emscripten exception ABI с `-fexceptions`, а прежний WASI сохраняет native Wasm EH. Это разные targets. Поддержка OS threads не заявляется. Development Qt сборка использует O0 ради короткой обратной связи; размер Wasm больше, чем при O3.

Приложение исполняется на отдельном HTTPS site в opaque sandbox iframe. CSP запрещает внешнюю сеть, формы, плагины и доступ к аккаунту. Выдаются только известные артефакты по короткоживущему readonly capability; исходники, snapshots и оценки через него недоступны. Остановка, закрытие проекта и выход отзывают доступ. Сообщения проверяются по окну, opaque origin, nonce и hash версии. Вывод и частота сообщений ограничены. Данные приложения могут попасть только в разрешённые текстовые файлы; проверка конкурентных изменений Code Studio сохраняется.

Стандартный механизм доступности Qt активируется внутри его shadow DOM; input получает имя из Qt accessibility metadata. Проверены реальные C++ callbacks через эти элементы. Это не заменяет проверку VoiceOver/TalkBack и физических устройств. Desktop Chromium подтвердил отзывчивость родительского Nexus и остановку настоящего бесконечного C++ callback. Перенос этого результата на другие браузеры требует отдельной приёмки.

## Доступ и хранение

Сервис использует существующий account-read proof BFF. Клиент не передаёт session secret, owner, SDK image, команды или оценку. Expected account ID привязывает операции к текущему аккаунту; проверка origin и авторизация выполняются на каждом API запросе. Проверять работы могут только явно назначенные сервером преподаватели; self-grading запрещён.

Сдача фиксирует snapshot/hash, hashes файлов, assignment/test version и toolchain image ID. Изменения рабочего проекта не меняют сдачу. Источник проверяется по hash перед выдачей и оцениванием. Оценка фиксируется один раз, включает шесть критериев, обратную связь и подтверждение защиты. Положительная оценка требует серверных тестов и защиты. Шаблон TaskFlow и публичные модельные тесты являются пилотом механизма; банк итогового экзамена, полная рубрика содержания и сертификаты курса ещё не подготовлены.

Private store сохраняет snapshots, результаты и оценки на диске с закрытыми правами и атомарной записью metadata. Повторный запуск помечает прерванные jobs. Одна сборка на аккаунт, две глобально, 60 jobs/час на аккаунт, 200 сохранённых jobs на инстанс. При заполнении сервис останавливает новые jobs; автоматического удаления работ нет. Для production нужны постоянное хранилище, резервирование, стратегия ёмкости/retention и распределённое исполнение. Ephemeral filesystem Serverless для этого не подходит.

## Подключение в отдельном окружении

По умолчанию `NEXUS_STUDIO_BUILD_ENABLED` выключен: нет нового listener, Docker, storage или дополнительного account lookup. Studio API отвечает `STUDIO_NOT_CONFIGURED`, обычный logout проходит прежним путём.

При включении обязательны `NEXUS_STUDIO_DATA_DIR`, `NEXUS_STUDIO_SDK_IMAGE`, `NEXUS_STUDIO_PREVIEW_ORIGIN` и `NEXUS_STUDIO_PREVIEW_PORT`. Preview origin должен быть HTTPS на отдельном site; приватный loopback listener требует отдельного TLS ingress с исходным Host. `NEXUS_STUDIO_REVIEWERS_JSON` задаёт назначения преподавателей; default — никто. Сами значения account IDs и любые credentials в репозиторий не добавляются.

Текущий production bundle `server-access/image` намеренно сохранён. Этот source integration не является готовым deployment package. Подключение production ingress, runner, хранилища и сборка нового BFF требуют отдельного этапа. Также до распространения Qt SDK/binaries нужен подтверждённый лицензионный маршрут. Платёж или лицензия этим изменением не приобретаются; лицензия студенческих работ не меняется. CI публикует только безопасные результаты и синтетические screenshots, без SDK, compiled Qt binaries, private jobs или browser profiles.

## Переносимость и локальная копия

ZIP содержит обычные исходники, headers, тесты, CMake, README и разрешённые данные. Owner/ACL/Cloud/session metadata не включаются. Модель, CLI и тесты собираются обычным C++20 компилятором без Qt и Nexus. Desktop GUI дополнительно требует Qt. Исходники сохраняются в штатном VFS и `.nexus.json` transfer; повторный импорт должен создавать отдельную рабочую копию.

Qt сборка, сдача и преподавательская проверка требуют подключения. В локальной копии доступны сохранённые исходники и объявленный console target прежнего WASI. GUI offline admission не выдан. Прежние M1–5 и encrypted Offline contract не меняются.
