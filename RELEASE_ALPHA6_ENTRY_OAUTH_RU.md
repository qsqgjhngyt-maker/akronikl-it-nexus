# Nexus Alpha6 — исправление входа

После успешного Passkey-входа титульная страница теперь открывает новый серверный документ. Ранее переход с `/` на `/#view=home` менял только hash, и пользователь оставался на титульной странице несмотря на действующую сессию. «Продолжить в Nexus», возврат к разделам и переходы в новой вкладке сохраняют выбранный маршрут.

Callback Яндекс ID допускает один служебный параметр `cid` ограниченного формата. Ранее корректный ответ `code + state + cid` отклонялся с `INVALID_INPUT`. Этот параметр не определяет аккаунт; проверки state, flow-cookie, PKCE, подписи приватного сервиса и `client_id` профиля сохранены. Дубликаты и посторонние параметры по-прежнему отклоняются.

Обновление меняет контейнер BFF и публикуемое поколение интерфейса. Worker, D1, Gateway, Passkey, права модератора и секреты не меняются. Первую привязку Яндекс к существующему Akronikl пользователь выполняет явно из свежей Passkey-сессии в разделе безопасности. Google/VK ожидают настройки приложений. Полный PWA gate и реальные проверки провайдера не объявляются пройденными локальными тестами.

Адресные проверки покрывают фактические обработчики обеих кнопок, полный переход документа, сохранение маршрута, допустимый `cid`, неизменность проверки state и отказ при дубликатах/посторонних параметрах. Предыдущая Alpha5 и исходные SHA256 сохранены. Откат контейнера возможен к `bbafp68l4ul4t3uqa34i` без удаления данных и добавочных OAuth-таблиц.
